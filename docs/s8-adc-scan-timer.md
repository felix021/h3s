2026-11-16。基线 main `bf99758`。纯静态只读路：零 tools/ 改动，产出=本文（形态结论 +
对 H2 per_source 契约的补充影响 + D1S9 遗留 2 消账）+ HANDOFF 条目。

对象：D1S9（`025e2fc`，[s9-keyscan-timer.md](s9-keyscan-timer.md)）遗留的兄弟源——S8
walker 注册的 **adc_scan 5-tick sys_timer**。D1S9 已钉死键扫（S9）形态，本路照同构打法
钉死 adc_scan（S8），回答「与键扫同一快轮链表还是不同链表」与「D1 窗口内是否可能周期
触发」。

方法与证据强度：反汇编用 official app.bin（sha256 `18f3d573…`，load base 0x06000100）
的线性反汇编（`disassemble_app.py` 同款），call 目标按 end-relative 程序化解析（AGENTS
不变量 5，脚本 `~/tmp/s8scan/verify_final.py` 复算，禁手算）。**[静态]** = 本路指令锚定
复算；**[文档]** = 已合并 docs/HANDOFF 条目。全部结论 derived-not-measured。

## 0. 一句话结论

adc_scan（S8 walker）与键扫（S9）**同构**：同为挂在 **Timer0 tick 回调里的软件定时器
（sys_timer）**，注册走**同一个 thunk 0x6066c26 → sys_timer_add 0x6066a7e**，且**同入
快轮链表（头 0x126DF0）**——它是与键扫**同一快轮链表的两个条目**，不是不同链表。两者
区别只在注册形态：adc_scan 的**周期=5 tick 是立即数硬编码**（非 ctx 初值）、**参数=0**
（空指针）、**注册无条件**；键扫的周期=10 tick 来自 ctx[+16]、参数=注册表项指针、注册
**条件性**（cfg523 解析成功才注册）。H2 per_source 里 adc_scan 与键扫同属 **timer0 衍生
帧（derived-from-timer0 的 sys_timer 条目）**，周期 = 5 × P_timer0 = **200,000 模型步**
（标称，运行实读为准）。

## 1. 静态链：从 S8 注册段到 adc_scan 回调

### 1.1 S8 注册段（adc_scan sys_timer 的产生）[静态+文档]

app_core init walker 段 S8（`0x60121a2..0x60121ae`，appcore-tail-map 表；AY 已修正 S8
标签为「sys_timer_add 非 task_create」）**无条件执行**——前接 S7 向量安装、后接 S10 指针
表 walker，中间直线无分支。本路字节级复算四条寄存器装载 + 一条 call：

1. `r1 = 0x60349d2`（回调，adc_scan 本体）。
2. `r0 = 0`（参数=空指针；与键扫 r0=注册表项指针 0x60C0E20 不同）。
3. `r2 = 5`（**周期=5 tick，立即数硬编码**；与键扫 r2=[ctx+16]=10 从 ctx 读不同）。
4. `r3 = 0`（flags/快慢轮选择=快轮）。
5. `0x60121ae → 0x6066c26`（sys_timer_add 的 4 字节 thunk，与键扫 0x6012202 同一 thunk）。
6. thunk `0x6066c34 → 0x6066a7e`（真正的 sys_timer_add）。

即：**adc_scan 注册形态 = sys_timer_add(回调=0x60349d2, 参数=0, 周期=5 tick)**，与键扫
sys_timer_add(0x6001944, 0x60C0E20, 10) 同构 [文档：D1S9 §1.1]。

注：任务书 D1S9 遗留 2 括号里问「5？来自 ctx 初值」——答案是**周期确为 5，但来自立即数
`r2 = 5`（0x60121aa），不是 ctx 初值**。adc_scan 没有 ctx 描述符（参数就是 0），这是它与
键扫在注册形态上的第一个区别。

### 1.2 sys_timer 的时基与到期链（与键扫完全同一条链）[静态+文档]

adc_scan 与键扫共用同一套 sys_timer 轮询机制，到期链逐段相同：

1. Timer0（IRQ4，时钟源 5=STD12M，PRD+1=120000 tick=10ms [文档：AH/probe_irq_entry]）
   到期 → Timer0 handler 0x12ece8 → tick 回调 0x603622c。
2. tick 回调 0x603622c 每 Timer0 周期执行：tick 计数 [0x1268CC]+1（`0x6036234`）、累计
   ms [0x1268D0]+=[0x1268C4]（`0x603623a`），然后 `0x603623e → 0x6066de0`（sys_timer
   轮询，本路复算确认）。
3. sys_timer 轮询 0x6066de0 遍历快轮（头 0x126DF0）/慢轮（头 0x126DF8），到期判定
   `[+20] ≤ 当前 tick 计数` → 周期重挂（`[+20] = tick + period`）→ `call [+8](参数=[+12])`。
   本路复算确认火回调点：`0x6066e32 r10=[r5+12]`（参数）、`0x6066e36 r6=[r5+8]`（回调）、
   `0x6066e7a r0=r10`、`0x6066e7c call r6`。

结论：**adc_scan 回调的每一次触发与键扫一样，都在 Timer0 IRQ4 交付帧内同步发生**——没有
第二个定时器、没有新的中断号/向量槽/交付请求。快慢轮由注册时的 r3（经 thunk 转成
sys_timer_add 的第 5 个参数）选择，与周期数值无关。

### 1.3 快慢轮的选择：两者同入快轮 [静态]

sys_timer_add 0x6066a7e 把节点挂进哪个轮，取决于第 5 参（`r9 = [sp+32]`，即 thunk 里
保存的原始 r3）：轮头 = QCY 基址 0x1265c0 + 2096 + r9×8。r9=0 → **0x126DF0（快轮）**，
r9=1 → 0x126DF8（慢轮）。本路枚举 thunk 0x6066c26 的全部 19 个调用点，r3 只取 0/1 两值
（快/慢），证实 r3 就是快慢轮选择器：

- **adc_scan（S8）r3=0 → 快轮 0x126DF0**；键扫（S9）r3=0 → 快轮 0x126DF0。
- 慢轮 0x126DF8 由 r3=1 的调用点使用（如若干 2/20/100-tick 定时器），adc_scan 与键扫都不在。

所以「同一快轮链表的两个条目」成立：两者都是挂在 0x126DF0 上的 sys_timer 节点，节点布局
`{next@0, prev@4, 回调@8, 参数@12, 到期时刻@20, 标志(周期|bit25)@24, 节点 id@28}`（从
15×36B 槽表 @0x1261E4 分配），轮询时按到期顺序逐个 fire。

## 2. adc_scan 回调本体（0x60349d2）[文档：BH §1.4-3，本路复算入口]

回调是「ADC 队列采样循环自我维持」的启动器 [文档：Q §2.2]。本路复算钉死两条入口门和一条
调用链，行为语义沿用 BH §1.4-3：

1. 门 1：`0x60349de` 读 `[QCY+0x5fb×4] = [0x127dac]`，若 ≠ −1（该槽占用）整轮返回。
2. 门 2：`0x60349ec` 读 CON 寄存器 0xfd3100，bit4（EN）置位则返回。
3. 找到期项 `0x60349f2 → 0x60348a2`（游标从 b[0x124c85] 轮转续扫；period==0 的占用项
   立即返回其 index），随后 `0x6034a12 → 0x6011666` 调 setter(key,1) **启动一次转换**。

D1 窗口内（无按键）它是 Timer0 tick 链内每 5 tick 一次的良性背景回调：双门决定它这轮是否
真推进采样，但**定时器层面它每 5 tick 必被轮询、必进回调**（详见 §4）。

## 3. 两个核心问题的静态答案

### ① 与键扫同一快轮链表还是不同链表？——同一快轮链表的两个条目

| 判据 | adc_scan（S8） | 键扫（S9） | 判定 |
|---|---|---|---|
| 注册 thunk | 0x60121ae → 0x6066c26 | 0x6012202 → 0x6066c26 | 同一 thunk |
| add 体 | 0x6066c34 → 0x6066a7e | 同 | 同一 sys_timer_add |
| 快慢轮选择 r3 | 0 | 0 | **同入快轮** |
| 轮头 | 0x126DF0 | 0x126DF0 | **同一链表** |
| 周期 | 5（立即数） | 10（ctx[+16]） | 同链表内两个不同周期的节点 |
| 参数 | 0 | 0x60C0E20（项指针） | 回调入参不同 |

结论：**同一快轮链表的两个节点**，只是周期与回调入参不同。轮询 0x6066de0 每 Timer0 tick
把快轮整个扫一遍，adc_scan（周期 5）到期比键扫（周期 10）更频繁。

### ② 每周期步数 P 的静态依据

- Timer0 周期 = 10ms = **40,000 模型步**（常量链：STD12M 每模型步 3 计数，PRD+1=120000
  tick / 3 = 40000；同 D1S9 §2②）。
- adc_scan 周期 = **5 tick**（立即数，§1.1 字节级复算）。
- 故 **P_adc_scan = 5 × 40,000 = 200,000 模型步 = 2×10⁵**。

红线同 P_park：**运行实读为准，不预锁**。tick 数 5 是静态的（且是立即数，不随 ctx 变），
但 Timer0 周期可被 os_time_dly 按场景重编（BY 实测 PRD 三态），所以 P_adc_scan =
5 × period_closed_form(timer0) 随 P_timer0 缩放；2×10⁵ 只是 Timer0=40,000 形状值下的标称。

## 4. D1 窗口内是否可能周期触发：静态判据与运行实读判据分开写

### 静态判据（本文可钉的部分）——**成立，节点必在、必周期重挂**

1. **注册无条件**：S8 段是 init walker 里的直线段，前接 S7、后接 S10，无任何条件分支。
   app_core init walker 在 boot 期一次性走完（远早于 D1 窗口/park），所以 **adc_scan 节点
   必然已挂在快轮**——不像键扫要等 cfg523 解析成功（条件注册）。
2. **周期重挂**：注册时 r3=0 → 节点标志 bit25=0，轮询到期走「重写 [＋20] = tick + period」
   分支（D1S9 称之为「周期标志重挂」），节点**留在链表里每 5 tick 重触发**。
3. 故静态上，**D1 窗口内 adc_scan 每 5 tick（约 200,000 模型步标称）必被轮询、必进回调
   0x60349d2**；是否真「启动一次转换」由回调双门（§2）按队列/硬件状态决定，那是回调行为
   不是定时器形态。

### 运行实读判据（归 PR-BI，本文不预写）——在 park 态实读快轮链表

1. 在 park 态快照里实读**快轮链表（头 0x126DF0）**，确认 adc_scan 节点在链上：回调字段
   =0x60349d2、标志字段周期=5、参数=0。
2. 观测 D1 窗口内回调 0x60349d2 的**到期/调用/返回计数**（观察锚=sys_timer 轮询
   0x6066de0 的火回调点 0x6066e32/0x6066e7c + 回调入口/返回，同 D1S9 §3 观察件纪律），
   判断是否真的周期触发、每周期步数与 `5 × period_closed_form(timer0)` 是否一致。
3. 与键扫不同：**adc_scan 是必然存在的源**（无条件注册），per_source 生产不应把它挂在
   cfg523 条件栈下；键扫才需要按 cfg523 实取自适应。

一句话：**静态形态已钉死（节点必在、必周期重挂、周期=5 tick 立即数），是否窗口内真周期
触发/每周期步数按 park 态快轮链表实读定——这正是 D1S9 遗留 2 的消账边界**。

## 5. 对 H2 per_source 契约的补充影响（在 D1S9 §3 基础上追加）

D1S9 已给键扫定了「timer0 衍生帧、非独立 IRQ 键」的条目形态（source='keyscan'、kind=
'sys_timer'、period=10×P_timer0、三分计数坍缩）。adc_scan 是**第二个同类源**，补充：

1. **per_source 再加一条 `'adc_scan'`**：kind='sys_timer'、derived_from='timer0'、
   period=5×P_timer0（标称 200,000 步）、三分计数坍缩（deliveries=expirations=
   completions=回调 0x60349d2 同步调用次数，无 IRQ 交付）。
2. **条件性区别（重要）**：adc_scan **无条件必在**，键扫**条件性**（cfg523 才注册）。
   生产者按条件栈实取时，`'adc_scan'` 只要 init walker 走完就应 emit；只有 `'keyscan'`
   挂在 cfg523 开关下。D1S9 §3.3（键扫条件 emit）本身是对的，但它 §4.2 把两者并成
   「不预写『必有 adc_scan/键扫』」——**这对键扫成立，对 adc_scan 不成立**：adc_scan
   是直线段无条件注册，静态必在，可以（也应）预写。
3. **checker 侧**（PR-2 生产者落地时，非本路）：`PERIODIC_SOURCES` 需同时加 `'keyscan'`
   与 `'adc_scan'`，并按 `kind=='sys_timer'` 识别衍生源套 `⌈N/P⌉+1` 上界（P 分别 =
   10×P_timer0、5×P_timer0）；H1/H4/H7 的 wake_reasons 枚举要能容纳这两类 sys_timer
   衍生源。
4. **窗口覆盖**：默认 N=max(S_tick+160k, 200k) 对键扫 P=4×10⁵ 覆盖 <1 个完整周期；对
   adc_scan P=2×10⁵ 覆盖 ≈1 个周期（更易观测）。H8 仍只折算 Timer0 的 P_park，两者都不
   影响 H8；是否拉长窗口观测这两源归 PR-BI 观察轮数据定，不预设。

**需要新键：需要**，且是两条（adc_scan + keyscan），判别字段 kind 共用。均属「先改
d1-health-checks.md 契约再改代码」范畴，本路只读不落地。

## 6. 遗留与相关

1. **D1S9 遗留 2 消账**：adc_scan 的 sys_timer 注册链静态钉死——回调 PC=0x60349d2、
   周期=5 tick（立即数非 ctx）、参数=0、thunk 0x6066c26→0x6066a7e、快轮 0x126DF0、
   与键扫同一链表。「是否窗口内周期触发」的**静态判据已钉（成立）**，**运行实读判据仍归
   PR-BI**（park 态快轮链表实读 + 回调计数观测）。
2. **S9 文档两处小勘误**（本路复算发现，不改变 D1S9 结论，供后续 reader 参考）：
   - D1S9 §1.2「call [＋8](arg=[＋24]&0xFFFFFF)」的参数标签不准——火回调点实际传参是
     `[＋12]`（`0x6066e32 r10=[r5+12]`）；`[＋24]&0xFFFFFF` 是周期值，用于重写到期时刻
     `[＋20]`，不是回调参数。回调参数对键扫是项指针 0x60C0E20、对 adc_scan 是 0。
   - appcore-tail-map S8 行「→ 0x606689a」标签不准——S8 链实际是 thunk 0x6066c26 →
     0x6066a7e（挂轮 helper 0x60667b6/0x6066a5c），0x606689a 是 sys_timeout 族（0x6066a0a
     调用）的另一 add 体，不在 S8/S9 路径上。
3. **BH §1.4-3 地址勘误**：入口门 1 的地址 BH 写 `[QCY+6124]=[0x127d44]`，本路复算
   QCY+0x5fb×4（6124）= **0x127dac**（=ADC 队列第 11 项 item10 的 key 字段），不是
   0x127d44（那是 item3+12 的 mode|period 字，BH 自己也列为「[疑] 0x127D44 身份」的
   另一处）。门语义（≠−1 → 整轮跳过）不受影响。
4. **衍生源的计数采集点**：adc_scan 的「到期/调用/返回」观测锚与键扫完全相同（轮询
   0x6066de0 火回调点 0x6066e32/0x6066e7c + 回调 0x60349d2 入口/返回），PR-2 生产者复用
   D1S9 §1.2 观察件纪律即可。
