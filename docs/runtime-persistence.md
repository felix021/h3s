# 运行时持久化存储调研（R4，只读预研）

目标：搞清耳机固件里「运行时修改、重启后还能读」的配置存储机制，为「自己的 App 通过 BLE 写配置 + 自定义固件读配置」铺路。

结论一句话：**QCY H3S 用一套「键值配置存储」（syscfg 风格）做运行时持久化，普通用户配置（降噪模式、EQ、音频模式等）走 VM 区（Flash 0x1da000 起），key 是 u16 编号；App 通过 BLE 自定义命令触发 setter，setter 调同一个写函数把 key+数据写进 VM。** 要接自己的配置，最小改动是复用这套 keyed store 的既有写函数，而不是新开 Flash 区。

> 本文所有反汇编地址都以官方原 app.bin（SHA256 `18f3d573…`，运行基址 0x06000100）为准。函数角色是「按行为命名」，不是恢复了厂商符号。证据等级在每节末尾标注。

---

## 1. 持久化机制全景

### 1.1 架构：键值配置存储 + 多后端

固件有一个统一的配置读写入口，按 key 分派到不同存储后端：

| 组件 | 地址 | 角色 | 证据 |
| --- | --- | --- | --- |
| get_config 分派器 | `0x06000f88` | `get_config(key, buf, len)`，按 key 区间选后端 | 反汇编（下同） |
| set_config 分派器 | `0x06001f12` | `set_config(key, buf, len)` | 反汇编 |
| 条目 get/set 助手 | `0x06000f5e` | 调后端 record 的 match/get/set 函数指针 | 反汇编 |
| 后端注册表 | `0x060c32c8..0x060c3338` | 4 条 28 字节 record，每条 `[+0]init [+4]match [+8]get [+12]set` | app.bin 数据 + HANDOFF.md:395 |

key 区间与后端对应（两个分派器一致）：

| key 区间 | 后端 | 可写 | 存储介质 |
| --- | --- | --- | --- |
| 1..99 | VM 区（record `0x60c3300`） | 是 | **Flash VM 区 0x1da000** |
| 100..511、701+ | ops 表后三后端（btif 窗口 / cfg_tool 记录区） | 是 | cfg_tool.bin + btif 窗口 0x1e0000 |
| 512..700 | record `0x60c331c`（记录区） | 否（set 指针为 0） | 系统值（只读） |
| 102 特殊 | get_config 直接读 boot_info+32 的 6 字节 | — | 身份类（MAC 等） |

record `0x60c3300`（VM 后端）的三个函数指针：

| 角色 | 地址 | 行为 |
| --- | --- | --- |
| match | `0x06061304` | `key-1 < 256` 即命中（key 1..256） |
| get | `0x06060ea0` | 查 RAM VM 位图，key 在位则返回 key，否则返回 0/-256 |
| set | `0x06060efe` | 调 VM 写核心 + 更新位图 + 提交 VM 头 |

### 1.2 已确认的配置项（key → 语义）

| key | 语义 | 长度 | RAM 镜像 | 证据 |
| --- | --- | --- | ---: | --- |
| 16 | 降噪模式（QCY mode/scene/strength） | 3 字节 | `0x12666b`（QCY 全局结构 `0x1265c0`+171） | docs/app-analysis.md:76 + 反汇编 `0x0600dddc`/`0x06012be2` |
| 42 | EQ 参数（3 字节头 + 每段 7 字节） | `3 + 段数*7`（默认 20 段 = 143） | EQ 节点参数区 | docs/eq-toggle.md:46 + 反汇编 `0x060257c2`（`r2 = r0+3`，r0=段数*7） |
| 22 | 当前音频模式（音乐/游戏/电影） | 1 字节 | — | 反汇编 `0x060252ba`（`r0=22;r2=1`，按键动作 7 模式切换路径） |
| 101 | 设备名模板 | 32 字节 | — | 反汇编（key 0x65） |

其余 key（3,4,6,7,8,12,13,14,15,17,20,25,26,37,38,43..48,58,59,61,84,86,88..97,99,100,110,115,117 等）在启动期被 `get_config` 成批读入 QCY 全局结构（`0x1265c0` 域 + `0x1249bc` 音频框架域），但逐个语义**待命名**（见 §6 决策点）。已知 key 6 = 12 字节（3×float32，默认全 1.0f）落在 `0x1265c0+4488`，是音频增益/声道类配置的候选，但未钉死是「声道平衡」。

### 1.3 机制小结

- **运行时修改 → 持久化**：App 下发 BLE 自定义命令 → 固件命令 setter（如 ANC 的 `0x06025ca4`、EQ 的 `0x0602583c`）→ setter 把值写进 RAM 全局结构 → 调 `set_config(key, buf, len)` → VM 写核心落 Flash。
- **重启 → 加载**：开机 syscfg init（`0x0601194e` 一带）成批 `get_config` 读回 RAM 全局结构；个别项（ANC）有独立 init（`0x0600dddc`）。
- 这不是 EEPROM 模拟，是 **Flash 上的键值区（VM）+ 一个 RAM 位图缓存**，走 JL SDK 的 vm/syscfg 同类设计（参考 SDK 只是命名参考，不是 QCY 源码）。

**证据等级**：架构（分派器/后端/key 区间）＝反汇编钉死；key 16/42/22 语义＝文档+反汇编交叉钉死；其余 key 语义＝观察存在、待命名。

## 2. Flash 配置区定位

### 2.1 VM 区（主配置区，key 1..99）

- **Flash 物理区间**：`0x1da000` 起，固件 `boot_info.vm_size=0x4000`（16KB 保留）。实测 USB 恢复时配置变化发生在 `0x1db000`（第二半）。见 docs/usb-recovery.md:92「VM `1da000..1ddfff`… 本次变化发生于 `1db000`」。
- **运行时组织**：VM init 把 `vm_saddr=0x1da000` 写进结构，按 `span=0x2000`（8KB）两半各 `0x1000`（4KB）组织（HANDOFF.md:396）。即「双半区轮换」的磨损均衡。
- **格式**：VM 头 magic `0xFF5A5A5A`（HANDOFF.md:396 的 magic 判定分支）；记录按 key 组织。VM 区空白/格式化判定在 `0x0600a7b6`（空白扫描）与 `0x06060f9a`（VM 窗口 init）。
- **RAM 缓存**：VM 有效标志 `b[0x1272dc]`；VM 位图（哪些 key 已写）`0x1272ac` 起 4094×u16，每 bit 一个 key（HANDOFF.md:396「重建 VM 位图」+ get 函数 `0x06060ea0` 的位测试 `r4&(1<<(key&0x1F))`）。

### 2.2 其它配置后端

| 后端 | Flash 位置 | 内容 | 证据 |
| --- | --- | --- | --- |
| cfg_tool 记录区 | cfg_tool.bin（flash 0xDF454 资源块） | 工具/调音参数（key 100+ 一部分） | firmware-layout.md:53 |
| btif 窗口 | flash 0x1e0000..0x1e1000（bank B，公开 UFW 无此字节） | 蓝牙信息类记录 | HANDOFF.md:395 |
| 记录区（只读 key 512..700） | VM 之外的记录区 | 系统值（chip/MAC 类） | 分派器 `[0x60c331c+12]=0` |

### 2.3 写配置的 API（固件侧）

- **高层**：`set_config(key, buf, len)`（`0x06001f12`）→ 分派到 VM set `0x06060efe`。
- **VM 写核心**：`0x06010534`（`vm_write` 角色）——内部拿 OS 互斥锁（`0x12b55c`/`0x12b5b0`，HANDOFF.md:394 的 pend/post 对），分配缓冲（`0x12e160`）、拷贝（ROM `0x1fd7c`）、算 CRC（`0x6000f0c`），空间不足时调 `0x600a70a` 同步到 Flash。
- **VM 同步到 Flash**：`0x0600a70a` 是 2 指令 wrapper，`call 0x12cc40`（RAM 驻留函数，实际 SFC 擦/写 VM 区）。真正的 Flash 擦写指令在 RAM 0x12cc40 内，本调研未逐条追入（见 §6）。
- **VM 头提交**：set 完成后递归 `set_config(255, buf, 40)`（`0x06060f94`），key 255 = VM 头（40 字节）。

### 2.4 写入时机

从 `0x06060efe`（VM set）的流程看：**写入先落 RAM 缓冲 + 更新位图 + 置脏，VM 头（key 255）最后提交**；`0x600a70a`（同步到 Flash）在「缓冲空间不足」分支被调（`0x06010534` 里 `if (r0>r3)` / `if (r3<r2)` 之后）。也就是说：**每次 set_config 都会走完「写缓冲→提交 VM 头」的同步链路，落 Flash 是同步的，不是纯掉电前才写**；但「每次 set 是否都整区擦写」取决于 VM 缓冲是否已满，这个精确边界本调研只追到 `0x600a70a→0x12cc40`，未追进 RAM 0x12cc40 内部（待补）。

**证据等级**：VM 区地址/双半区/magic/位图＝钉死；「写缓冲→提交」链路＝反汇编钉死；「每次是否整区擦写」＝部分追踪、待确认。

## 3. 重启加载路径

### 3.1 开机总流程

1. **平台 init** 尾（`0x0601206c` 遍历后端表 `0x60c32c8..0x60c3338`）依次调 4 个后端 init（HANDOFF.md:395）：
   - btif 表 walker init `0x06060a4a`
   - index<768 校验 `0x06060c3c`
   - **VM 窗口 init `0x06060f9a`**（判定 VM magic、空白扫描、重建 VM 位图）
   - 记录区 init `0x06060d7c`
2. **syscfg 成批读**（`0x0601194e` 一带）：对 key 3/4/6/7/8/13/14/17/20/25/26/89/91/100/101/102/601/602/529… 逐项 `get_config` 读回 QCY 全局结构 `0x1265c0` 域与音频框架 `0x1249bc` 域，每项都有默认值回退（读回长度不符就写默认）。
3. **VM 位图是门**：get_config 的 VM get `0x06060ea0` 先查 `b[0x1272dc]`（VM 有效）再查位图 `[0x1272ac+(key>>3)] & (1<<(key&0x1F))`，key 不在位图则返回 0（调用方走默认值）。

### 3.2 ANC 模式（key 16）——重点

- **开机读**：`0x0600dddc`：`r5=0x1265c0; r1=r5+171(0x12666b); r0=16; r2=3; call get_config`。返回 `r0==3`（读满 3 字节）才用保存值；否则写默认（mode/scene/strength 按 QCY 内部分派，见 docs/app-analysis.md:77-79 与 evidence/anc-cycle/0600dcee-0600de80.asm）。
- **运行期改**：按键循环（ANC 键）只改 RAM 状态走「下一档」逻辑，**不写 Flash**（anc-cycle.md 的核心结论）；**App 直接设置**才持久化：命令 0x17 setter `0x06025ca4` → 回调 `0x06025d6a` → `0x06012be2`（ANC 写 wrapper）→ `set_config(16, 0x12666b, 3)`。
- **保持机制**：3 字节 QCY mode/scene/strength 存 key 16，重启后由 `0x0600dddc` 读回，再经 `0x0600dcee` 映射成内部 ANC ON2/OFF1/TRANS3 应用。

### 3.3 EQ 模式（key 42）——重点

- **App 改 EQ**：命令 0x22 setter `0x0602583c` → 应用参数例程 `0x06025118` → 保存 key 42（docs/eq-toggle.md:44-46）。
- **重启加载**：`0x06024fe6("MusicEqBt", index)` 读 key 42 并加载配置项（eq-toggle.md:46）；读回长度 = `段数*7 + 3`（`0x060257c2`）。
- **注意**：EQ 曲线参数持久化，但「EQ 开关」（r2 实验的 bit7 双击开关）**只在 RAM、开机默认启用**（eq-toggle.md:69），不是持久化项。

### 3.4 默认值回退

所有读路径都是「读回长度 != 期望长度 → 用内置默认值」。证据：ANC `0x0600dddc` 的 `if (r0 != 3)` 分支；EQ/其它 key 的 `ifs (r0 < 0)` 分支写默认（`0x06011af6` 写 1.0f 等）。

**证据等级**：流程＝文档+反汇编交叉钉死；VM 位图门控＝反汇编钉死。

## 4. 对接面：自己的 App 写 + 自定义固件读

### 4.1 结论（最小改动建议）

**复用固件既有 keyed store，不新开 Flash 区。** 具体两选一：

- **方案 A（推荐，改动最小）**：自定义固件里直接调 `set_config` / `get_config`（`0x06001f12` / `0x06000f88`），用一个**未被占用的 key**（key 1..99 里挑一个固件没用的）存自己的配置。App 侧用既有的 BLE 自定义命令框架（0x22 EQ / 0x17 ANC 同款，新注册一个命令号）下发，setter 里 `set_config(my_key, buf, len)`。持久化、重启加载、默认回退、磨损均衡全部白嫖，零新 Flash 管理代码。
- **方案 B（不推荐，除非 key 空间用完）**：新开 Flash 区 + 自写擦/写/读/CRC/磨损均衡。要自己处理 SFC 擦写（4KB 扇区）、VM 头、boot 期读取顺序、双 bank。工作量大且容易踩 boot-info CRC / 双备份的坑（firmware-layout.md:87-105 的教训）。

### 4.2 方案 A 需要落地的点（供后续「自己改的版本」）

1. **选 key**：从 §1.2 的已观察 key 集合里避开已用 key；key 16（ANC）/42（EQ）/22（音频模式）等已占用。建议先完整枚举 key 1..99 的占用（§6 决策点），选一个空位（如 30 附近）。key 必须 ≤ 256（VM 后端 match 上限）。
2. **注册 BLE 命令**：仿命令 0x17/0x22 的注册记录（`app.bin+0xa9ae8` 是 0x17 记录，eq-toggle.md:44 是 0x22 的 `app.bin+0xa9a78`），新增一条自定义命令 + getter/setter/callback。
3. **读写封装**：setter 里 `set_config(key, buf, len)`；开机 init 里 `get_config(key, buf, len)` + 长度校验 + 默认值回退（照抄 `0x0600dddc` 的模式）。
4. **长度上限**：VM set 校验 `len ≤ 4095`（`0x06060f0e` `if (r4 > 4095)`），单条配置别超这个数。

### 4.3 不能直接复用的部分

- 「按键功能」这类需要改按键分发表（`0x060252c6` 的 tbb）的配置，持久化只是存值，真正生效还要改按键处理逻辑（eq-toggle.md:40 的教训：分发表里没有隐藏 EQ 开关编号）。
- App 侧不能只发孤立命令：QCY 走 CustomCmd → CustomParam → SDK 分片（app-analysis.md:48-55），自己 App 要按相同封装发。

**证据等级**：复用点＝反汇编钉死；「选哪个 key 空位」＝待枚举（§6）。

## 5. 决策点（需要进一步确认的事）

1. **key 语义全枚举**：key 1..99 的完整「key→长度→语义→RAM 镜像」映射本调研只钉死了 16/42/22 等少数几个。要在方案 A 里安全选空 key，需要把启动期 `0x0601194e` 一带的成批 `get_config` 逐个 key 追一遍（读出 key + 期望长度 + 目标 RAM 地址）。
2. **VM 写核心的 Flash 擦写细节**：`0x600a70a → RAM 0x12cc40` 内部的 SFC 擦/写序列、双半区切换、每次 set 是否整区擦写，本调研只追到 wrapper。若要评估「高频写配置的 Flash 寿命」，需追进 0x12cc40。
3. **声道平衡是否存在**：key 6（12 字节 3×float32）是候选，但 H3S 是否真的暴露「左右声道平衡」这个 App 功能未确认；若 App 没有这个 UI，可能只是内部增益结构。需要看 App 控制面板 data/controlpanel_qcyh3s_16764.json 有无对应项。
4. **掉电写入窗口**：VM 头提交是同步的，但「掉电瞬间正在擦写 VM 区」会不会丢数据，固件有没有掉电保护，未追。

## 6. 证据等级速查

| 结论 | 等级 |
| --- | --- |
| 键值配置存储架构（get/set 分派器 + 4 后端 + key 区间） | 反汇编钉死 |
| key 16=ANC(3B)、key 42=EQ(3+段数*7B)、key 22=音频模式(1B) | 文档+反汇编交叉钉死 |
| VM 区 flash 0x1da000、双半区 0x1000、magic 0xFF5A5A5A、RAM 位图 0x1272ac | 文档（usb-recovery/firmware-layout/HANDOFF）+ 反汇编交叉钉死 |
| 写入=缓冲+VM头提交、同步到 Flash | 反汇编钉死 |
| 「每次 set 是否整区擦写」 | 部分追踪（未进 RAM 0x12cc40） |
| 其余 key（3..117 等）语义 | 观察存在、待命名 |
| 函数角色（get_config/vm_write 等命名） | 行为命名，非恢复符号 |
