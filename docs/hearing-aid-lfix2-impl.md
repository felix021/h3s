## 4. 补丁表

### C1 两态表（1 字节 + CRC 链，builder --anc-cycle-two-state）

app.bin+0x9e410（运行时 0x0609e510）表字节 `01`→`02`：flash 坐标 0x2120+
0x9e410，uFW 文件坐标 0xa0b30。与 b79 时代完全同款（anc-cycle.md「uFW变化
20 字节」先例；F2 vs F1a 全文件 diff 恰 1 表字节+20 CRC 元数据字节——预检

### C2 close 恢复补刀（+66B，载荷源 mic_effect_close_lfix2.S）

F1a close 98B 的前 28 条指令形状原样（stock close+A3c 门控释放；两条 goto
偏移随段变长拉伸、F1a 的收尾 r0=0/pop 对被 C2 接管），其后追加：

```
c2_settle:
  r0 = 20; r6 = 0x06064efc; call r6      ; C2a os_time_dly(20 tick=200ms) 稳定缓冲
  r0 = 2; r1 = 1; r6 = 0x0600db3c; call r6 ; C2b db3c(2,1) 请求 ANC ON（官方键路径同参）
  r6 = 0x1265C0; r4 = [r6+500]            ; C2c ANC ctx
  if (r4 == 0) goto close_done_ok         ; 子系统未建：无可等
  r5 = 60; r6 = 0x06064efc
c2_wait:
  r0 = b[r4+29] (u); if (r0 != 0) goto c2_poll   ; 过渡未清 → 扣计数
  r0 = b[r4+33] (u); if (r0 == 2) goto close_done_ok ; 目标 ON 且稳定：完成
c2_poll:
  r5 += -1; if (r5 == 0) goto close_done_ok      ; 超时放弃（不回滚）
  r0 = 1; call r6; goto c2_wait                  ; 1 tick=10ms 重试
close_done_ok: r0 = 0; {pc, r6-r4} = [sp++]
```

寄存器纪律与 A1 同款（r4/r5/r6 跨 os_time_dly 存活，callee-saved 已核，
lfix-impl §2）；幂等（槽==0 早退在最前，未激活不触碰 ANC）；超时语义=放弃
等待（db3c 已投递 ANC 链自会跑完）——与 A1 超时取消 open 不同，close 语义
已完成不存在回滚。

## 7. 诚实边界

1. **静态补丁无法验证运行时行为**（沿 F1 §7）：C2 的恢复时序、db3c(2,1)
   的提示音能否播出（tone 链在 close 后窗口的表现）、两态表恢复后的循环
   体验——全部留给真机。
2. **症状 3/4 的机理归因是「最优假说」而非实锤**：并发竞争路径静态实锤
   （路径存在），「竞争→提示音丢失/断联」的因果是推断。子任务反汇编补充：
   tone 静默跳过路径（provider 失败→切换照常但无提示音）与 b[ctx+29] 卡死链
   （tone 启动后失败不回调→后续 db3c 全部在途早退）是症状 3/5 的叠加候选；
   ANC 进入链静态无 JL_WLA 写手，扰动源若存在藏在两个跨核 thunk 或经 tone/
   资源并发——F2 的 C2b 提示音本身即判别信号（§10 判据 2/3）。
3. **C2 的边界**：快速「关助听→立即双击开」若 C2c 超时放弃（ANC 进入在途），
   下次 open 的 db3c(1,1) 被在途早退+A1 超时取消（~590ms 后返回无声），再按
   一次即恢复——自愈型边界，验收记录出现频率（§10 判据 4）。C2b 的 db3c 若
   遇 tone 启动后失败（不回调路径），C2c 将等满 600ms 超时放弃——close 变慢
   到 ~1.4s 上限，无挂死（60 次上限兜底）。
4. **A3/压舱边界沿 F1 §7**（首次升频不可避免、高频保持相关判读、续航温升
   未测、诊断档定位）。
5. **hold 常驻判别档未实现**（§3）：若 F2 验收仍断联，需下轮出（open/close
