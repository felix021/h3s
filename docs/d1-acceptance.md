## 1. D1 完成定义（可测验收断言）

D1 = **启动完成并进入稳定调度**（2026-11-14 codex 二次校订改述，路 AI 落档；旧表述
「两核进事件循环」可能误伤合法状态：一核跑应用任务、另一核 idle/等待同样是有代码依据的
真实设计，**不要求两核停在同一种循环**）。断言全部建立在 BI（A1-A5，docs/d1-idle-event-clock.md
§4）之上；前置 = BG-a/b/c + BH 放行到 S19（尾段图 docs/appcore-tail-map.md §2）。
时间口径：**周期断言用驱动 Timer0 的同一全局模型步轴**（含事件时钟快进段），另列实际执行
指令数，不混用两个「步」[codex]；观察窗口按**已建模的时间与周期**定义，指令步数只作
执行预算、不能当实际毫秒 [codex 2026-11-14]。

- **D1-1 真实进入消息循环并阻塞**：真实前缀进入 S19（0x60123e6 循环头），实际调用
  `0x6064c8c(sp,16)`；先如实记录循环首批对 S18 预置事件（0x6000c5a post 的 (18,0)/(20,2)，
  §2.3）的消费结果，随后确认**空队列阻塞**（pend 不返回）→ 两核 park（CPU1 已停泊
  0x12c5ca [trace]；CPU0 经调度器切 idle 任务 0x12c57e→0x12c5ca）→ `event_clock_engaged`。
  **不要求首次 pend 即空队列**（正常路径可先消费 S18 事件）[codex]。**终态不要求两核
  同形**[codex 2026-11-14]：park（两核 idle）是当前证据下的预期形态而非断言形状——断言
  只要求两核各自处于**有代码依据**的运行/等待/idle 状态（如一核持续跑应用任务、另一核
  idle 同样算过）。金丝雀负例：K1
  0x601249c / K2 0x60124ae 在整个验收窗口执行次数为 0（tail-map §4：阈值 h[0x1272d4] 静态
  零，到达即方向错误信号）。
  证据来源：tail-map S18/S19 分段图 [文档]；BP §1.4 park 路径 [文档]；本次循环控制流反汇
  编 [静态]（§2.1）。依赖：BG-a（当前停点 0x60116e6 ADC CON 读侧）、BG-b（W1[0] 边界包）、
  BG-c（S8/S11 任务创建往返）、BH-a 仅当 S13/S15-S17 运行时分支走到充电/电池查询。
- **D1-2 Timer0 连续运转与交错稳定**（并入原「交错稳定性」[codex]）：≥3 次连续到期，每次
  完整周期 = 到期→（资格成立时）交付 IrqDeliveryRequest(core=0,irq=4)→handler 0x12ece8
  真实字节→W1C bit14 清 pending→RTI 回**实际保存的 RETI**→重新 `core_idle_wait_entered`。
  **相邻到期间隔恰 40,000 全局模型步**（BI A2 的多周期推广）；**交付延迟另记**（溢出落在
  IPMASK=6 临界区时经 BF 的 pending 重检机制延后交付，属既有建模语义 [文档]），不要求交付
  间隔也是 40,000 [codex]。逐周期四查：到期/交付/ACK/返回，无漏失无重复。若窗口内发生消
  息分发，须再覆盖一次分发之后的完整周期（分发代码可能动 IPMASK/临界区）。**「无未知停
  点」= 窗口内没有未处理的未知边界、跳过或补值**（比「停点集合无新 kind」强：旧 kind 再
  次阻塞也不通过）[codex]。
  依赖：BE 三件（timer0_irq_delivery_requests+entry/banks/rti，已就位 [文档]）、BI G1/G2
  修正落地、event_clock_projection。
- **D1-3 core tick 的实际效果**：CPU0 core tick 首次溢出按**从实际 park 状态推出的闭式期
  限**到达（BP E2：自 304,317 外推 +143,173 模型步 ≈447,490 指令轴；BG/BH 落地后按实测
  重钉）；交付符合当时的 IRQ 资格与优先级（BF：pending 期间逐步重检）。以该次 handler
  入口/出口为边界核对：真实 ACK（|=0x40 恰一次）、**软件 jiffies [0x125004] mod 2³² 恰
  +1**、时间片调度 call 0x60653AE 真实执行并返回 [文档：路 BF 反汇编钉死]。若触发任务切
  换，按实际恢复上下文验收（不强求返回原任务；BP A5(b) 的「任务恢复」全证在此升级为观
  察项而非硬断言）[codex]。
  依赖：BF 三件接进主场景栈（已就位 [文档]）。
- **D1-4 消息消费与分发闭环**：≥1 个**固件自然产生**的事件走完全链：post 实参→入队表示→
  get-event 返回 13→`[sp]` 实际 id→bit20 检查→（id==0x10000c 时）0x60108fe 特路→按真实查
  找顺序命中 12 字节分发表记录→handler 真实字节执行并返回→回环再次 pend。**不能只以
  「handler PC 出现过」算通过** [codex]。
  - 事件来源候选（模型内，封闭）：S18 预置事件（§2.3，id 变换待运行时观测）；sys_timer
    回调（Timer0 handler 0x12ecd4 查 [0x126f6c+id<<2] 回调表 [文档：路 BE]，表内容是运行
    时数据——首个 IDLE 点时是否非空、回调是否 post 事件，均为 BI/BJ 观测项）；RTOS tick
    时间片调度唤醒的任务（D1-3 之后）post 的事件。
  - **外部输入（P33/WKUP/USB/按键）明确不在 D1 范围**（BP §2 排除表）；d1-gap-map B10 的
    「至少一个输入事件分发」据此改述为「消息循环实际消费并分发至少一个固件自然产生的
    事件」[codex]。
  - **无事件时诚实收口、不静默降级** [codex]：D1-1..3 通过 = 「空闲与定时唤醒子项通过」；
    D1-4 无样本 = 「未覆盖，D1 完整验收未完成」。同时区分两种失败：**回调表为空**（链路
    通但无事件源）与**事件链路不通**（post 成功却在变换/入队/接收处丢失——须定位，不算
    无样本）。
- **D1-5 观察窗口健康度**（新增，codex 2026-11-14）：整个 D1 观察窗口内**无中断风暴、
  无同一事件无限重发、无任务永久饿死**。这是「稳定调度」的否定式总闸：D1-1..4 逐项形状
  达标但窗口内出现三者之一，D1 仍失败。可测判据（按已建模时间轴）：同源 IRQ 交付节奏与
  其声明周期同量级（无无界/指数重发）；除 idle 外的任一就绪任务在窗口内获得过 ≥1 次调度
  机会；事件队列积压有界且消费指针前进（与 D1-2「逐周期四查无漏失无重复」互补：D1-2 管
  Timer0 一家的周期完整性，D1-5 管全窗口的总量健康）。

**codex 2026-11-14 修正吸收对照**（D1-1..4 原文保留，标注吸收点）：①「不要求两核停在
同一种循环」→ §1 定义改述 + D1-1 补「终态不要求两核同形」；②「窗口内无中断风暴/无限
重发/饿死」→ 新增 D1-5；③「窗口按已建模时间定义、指令步数只作执行预算」→ 时间口径句
（2026-11-13 已有「不混用两个步」，本次补执行预算定位）；④ Timer0 多周期完整往返 /
core tick 须有真实效果 / 固件自然事件全链 → D1-2/D1-3/D1-4 既有断言已覆盖（[codex]
标注系 2026-11-13 校订，本次未改动）；⑤「保留未测假设标记」→ 各条「依赖」行与 §5 照旧。

BI 验收（A1-A5）与 D1 的关系：BI=机制首验（Timer0 往返即可），D1=多周期+RTOS tick 效果+
消息分发闭环。全部结论维持投影等级（hardware_mode_certified=false 不升级）。

## 2. 消息循环静态结构（本路新钉死的证据）

### 2.1 循环控制流 [静态]

```
0x60123e6: r0 = sp+0; r1 = 16
0x60123ea: call 0x6064c8c          ; get-event(buf,16)，空队列时 pend（B9 idle 入口）
0x60123f0: if (r0 != 13) goto 0x60123e6   ; 非 13 → 重调（13=取得事件）
0x60123f4: r0 = [sp]                       ; 事件 id 字
0x60123f6: if ((r0 & 0x100000) == 0) goto 循环头   ; 无 bit20 → 丢弃
0x60123fa: if (r0 != 0x10000c) goto 分发
0x60123fe: r0 = r4; call 0x60108fe         ; 0x10000c 特路（返回 0 → 继续分发）
0x601240a: r5 游标走表：id 匹配 → r1 = [r4 记录+8]（handler）
0x601241e: call r1                         ; 间接调用 handler
0x6012420: if (r0 == 0) goto 循环头        ; handler 返回 0 → 继续循环
...两表走完/r10 路径（0x6012424..0x6012444 第二表 0x60a8c68）
```

循环**永不退出**（所有路径回 0x60123e6）；「Loop breaks on event id 13 or 0x10000c」
（tail-map §1）应更正为「13 是 get-event 成功码、0x10000c 是特路分发，二者都不是出口」。

### 2.2 分发表结构修正 [静态]

两表记录为 **12 字节 {u32 filter, u32 event_id, u32 handler}**，非 tail-map 记的 8 字节
{event-id, handler}（旧读法 4 字节错位，81+9 槽实为 **54+6=60 条记录**；表界不变
0x60a89e0..0x60a8c68 / 0x60a8c68..0x60a8cb0）。event_id 取值 0x100002..0x100013
（0x10000c 最常见，20 个 handler）；filter 字段 0xff 为主、0x01 两处（0x60160fc/0x6015ec2）、
0x00 一处（0x601875a）——语义未钉（疑消费/过滤标志），D1-4 命中记录时如实报告即可。
handler 60 条全相异、全在 0x6000d02..0x60261fa（tail-map 的「~30-45 live handler」估计随
结构修正作废）；±4 槽对齐问题
随结构修正一并消除（记录边界由 0xff 周期钉死）。

### 2.3 S18 预置事件与 id 变换 [静态+待观测]

S18（0x60123a6..0x60123bc，循环前）post (18,0) 与 (20,2)：调用链 0x6000c5a（2 字节跳板
`goto 0x601107c`）→ 0x601107c（事件机制域，writer b[0x1265c8]=event machinery 0x606487c
同族 [文档：tail-map S13]）。raw id 18/20 与分发表 id 0x1000xx 的**变换关系未能静态钉死**
（0x601107c 链深入 OS 队列机制）——一处运行时观测项：D1-1 的首批循环迭代即给出答案
（[sp] 读到什么就是什么）。这是 BI/BJ 收口项，不影响断言设计（断言按实际 id 验收）。

## 3. L2 三镜像差分实验设计

### 3.1 差异点全集（b79↔EQ 10 游程 + official↔b79 两族）[静态：本路逐字节复核]

b79↔EQ 全部 10 个差异游程（LE 逐字节扫描复核，与 probe_pi32v2.SITES/R2_ENTRY_BYTES 钉子
一致）：plain 0x0..4/0x20..24（资源表头 CRC，official↔b79 同族）、0x59ce/0x25030/0x2510e/

official↔b79 另有：资源表头 CRC 字节、ANC 键表 0x609e510=plain 0x9e510（app.bin+0x9e410，

### 3.2 钩子机制与目标（模拟器实测）[模拟器+静态]

5 个钩子站点在 EQ 镜像被替换为跳转指令，钉死上游模拟器步进得出目标**全部落在载荷
[0x60e3074, 0x60e31c5) 内**：0x6025364→0x60e3074、0x60059ce→0x60e3092、0x6078846→
0x60e30a0、0x6025030→0x60e30b0、0x602510e→0x60e30c2（与 probe_pi32v2 的
`0x060e3074<=target<0x060e31c5` 钉子互证）。载荷（337B）开头形状 [静态]：
0x60e30b0/0x60e30c2 两桩=**写状态字节 0x1265EA 的 bit1/bit0**（RMW `&~0x7F|2`/`|1`）；
0x60e3092 桩=重放原指令但加 `&0x7F` 掩码（真实行为差：源字节 bit7 被清）；0x60e30a0 桩=
call 载荷内 helper 0x60e30f6 后重放原指令；0x60e30d4=16 字节逐字节比较器。b79 的 LIM
上限 0x060c3338 本身就不允许执行到载荷区——**EQ 镜像的差异执行面=fence 修复放行的
0x060c3338..0x060e31c5**。

### 3.3 静态可达性结论（D1 窗口零触发的静态面）[静态]

### 3.4 L2-a：D1 前缀三镜像差分（BJ 过 D1 后立即执行）

复用 analyze_image_trace 的既有机制（逐步签名=核/前后 PC/flags/16 GPR 规范形/该步全部
guest RAM 写；reconvergence/parity；BK 的条件场景 import 先例），场景=D1 验收场景（BJ 落地
后按其 flag 集转录，单测按 AST 钉一致性），freshness 钉子按新前沿重钉。预算：park 点
（~305k..312k 估计 [文档：BP §1.4]，BG/BH 后重钉）+ ≥3 个 Timer0 周期（120k 模型步）+
core tick 首交付（≈447k 指令轴）——三镜像各 ~500k 模型步量级。

**预测（待核验假设，非豁免 [codex]）**：

1. **official↔b79**：控制流零分歧从 304,036 继续贯穿整个 D1 窗口；首分歧仍 155,390、
   分歧段仍 30 个、报告差异仍 5 处（事件循环代码不读表头 CRC 派生数据——无已知读者）。
2. **b79↔EQ**：+458 步差与 169,439 reconvergence 机制保持；新增签名分歧段预计=**派生族**
   （core tick CNT 恒差 +1832=458×4 在调度器/tick 时间片调度的 CNT 读数处显形 →
   task 簿记 RAM 写差；Timer0 cnt 无差——两镜像 Timer0 同相对点启动、余步相同 [trace：
   路 BK 已钉]）。**逐段追踪差值来源与消费者**：一旦差值影响期限判断、IRQ 资格、调度决
   策或事件顺序，即升级为行为差异（预期不发生，但按证据说话）。
3. **停点 parity**：三镜像在同一 D1 窗口边界停（或同刻续跑），报告差异全部归因到已钉死
   形状（步数派生计数/CRC 错位/fence 寄存器值）。

**证据强度口径 [codex]**：零控制流分歧+签名段全派生=「**本次执行窗口内**镜像差异未被消
费」的动态证据，**不是**「D1 不可达」的一般证明；与 §3.3 的静态闭包分别陈述，两证据互
补（静态=结构上怎么都到不了，动态=这趟确实没消费）。**零控制流分歧不自动证明零差异读
取**：需同时核对差异区域的取指/数据读（逐步签名已含 GPR+RAM 写，取指由执行流保证——
未执行的差异字节不产生签名差；数据读差异会经 GPR 显形——两者都在现有机制覆盖内，报告
里明确引用即可）。
**行为状态比对** [codex]：除 PC 轨迹外，比对事件入队/出队计数、分发表命中记录、IRQ 交付
顺序与次数、任务切换次数、关键 RAM（[0x125004] jiffies、消息队列指针）与停点报告——
其中多数已在逐步签名（RAM 写）与 final report diff 内；分发表命中/事件计数若缺报告键，
作为 L2-a 实施时的报告侧增补项（纯报告、默认关不影响 legacy）。
若 D1-4 无样本（事件链路通但无事件源），L2-a 仍可执行，但**只报告「已通过的 D1 子项
（D1-1..3）三镜像等价」**，不能替完整 D1 补验收 [codex]。

**D2-b1..b4 四类断言**（防「IRQ 进了就算成功」；路 AE §4 草案并入此框架：AE-b1 打开链
=场景前置（固件先配置并启用，进 b2 前提）、AE-b2 DMA 交付→b2、AE-b4 采样穿透→b1、
AE-b3 pipeline 消费→b3；b4 连续性为新增维度）：

| 断言 | 什么算过 | 什么不算过（codex 反例，原样保留） |
|---|---|---|
| **b1 数据与布局** | 已确认的交织/分平面布局正确；通道、样本序号和有效长度在消费者入口可追踪 | 只注入全零——无法辨认串路、错位或旧数据 |
| **b2 DMA 与 IRQ** | 固件先配置并启用采集（set_buffer 0x606dee4 五写+ADC_CON bit5/bit4 使能门）；模型按该配置填**当前**缓冲、产生完成条件（bit7 pending）；经真实 IRQ68 路径（分发器 0x602f406→0x6072628）服务并清除原因（\|=0x40） | 直接调用 handler，或无视使能状态强送 IRQ |
| **b3 消费结果** | 活跃消费者读取正确范围，更新真实读指针/处理计数（ADC_SRP 推进、output-handler 链逐个回调），并产生下游提交或明确的消费完成结果 | 只到函数入口；用 stub 直接返回成功 |
| **b4 连续性与生命周期** | 连续运行跨过**至少两次完整环回**（ADC_HWP 绕 [ADC_ADR,+ADC_LEN) 两圈）；停止、重开或一次重配后无越界、旧帧误用、重复消费 | 单帧通过就声称持续流正常 |

**数据设计**：低幅值、通道间可区分的样本序列，且**随块号变化**（同通道跨块取不同值——
否则检不出「旧帧重复消费」）。**DSP 前校验精确样本**（源节点入口 buf 处读回交织序），
**DSP 后按算法性质验收**——经过滤波、增益、混音后不能要求原标记保持不变。

**DMA 预填方案**（路 AE 推荐案 (a)）落地约定：模型在**每次完成事件前**把数据填进固件
配置的目标缓冲（[ADC_ADR..+ADC_LEN) 的当前窗口），**不一次性预填全部内存**——后者容易
掩盖指针与生产进度错误。DMA 总线行为、缓存一致性未建模：凡依赖「DMA 完成时序」的通过
一律标注**「DMA 完成行为投影下通过」**（与既有 conditional pass / derived-not-measured
同族措辞，证据等级承接 §8）。

**三消费者核对**：mic_effect 源节点（0xD06D）/通话 aec（0x6031D5A）/ANC（共享
audio_adc_hdl）的帧计数**不能简单要求相等**——按各自订阅关系（output-handler 注册与
否）、分块与降采样比例核对；丢帧只能由固件已有策略解释，不能默认合理。

### 6.3 D2-c 升格：所有用例的共同断言（原「OS 状态观察面」，codex 第 4 点）

D2-c 不再是并列第三项，而是 **D2-a/D2-b 每个用例都要过的共同断言**。不宜只要求「状态
发生变化」；每个用例至少断言五条：

1. **分支一致**：预期状态与处理分支一致；不适用事件保持状态或按代码拒绝。
2. **队列规则**：事件队列遵守已知入队、消费、合并或丢弃规则；处理后积压有界。
3. **流生命周期**：流节点的创建、启动、停止、释放匹配生命周期；允许代码明确保留的缓存。
4. **未启用消费者不被调**：未启用的消费者不被调用；停止之后不再消费旧缓冲。
5. **模式切换期间输入**：至少一个代表性「输入发生在模式切换期间」用例按既定顺序完成，
   无死锁、悬空回调或跨模式旧事件误用。

不必穷举双核交错；优先覆盖两类高收益边界：**IRQ 到达缓冲切换前后**、**停止时尚有待处理
帧**。每次输入注入后的状态变化仍须给固件代码依据（derived-not-measured 边界照旧，
不臆造）。

## 7. D3 行为一致性验收：模型 ↔ 真机（新增，codex 第 6 点）

D3 单独回答「模型与真机是否一致」，与 D2（模型内闭环正确）是两个问题，**D2 过线不自动
带来 D3**。依赖顺序：

```
外设/指令局部契约检查（既有 probe 族，持续）→ D1 → D2 最小闭环 → D2 代表模式与边界
→ D3 行为一致性验收
```

- D2-b 的布局与分发**局部测试可提前**（probe_pi32v2 compiled cases 先例）；但正式整机
  验收必须从**真实启动或可追溯的启动快照**进入，不能靠手工构造最终 OS 状态。
- 早期若已有真机证据能验证 IRQ、通道布局或手势时序，**立即**用于缩小模型假设，不必等
  D2 全部完成——已有证据（如 ROM 读取、usb-recovery 读回）先对先销。**新增真机操作
  一律单独授权**（仓库规则：offline 分析/文档不授权设备动作，AGENTS「Device actions」
  节口径）。

**D3 比较面**（双方都可观察的行为；限已有或后续获授权的观测手段）：

| 比较面 | 内容 | 限制 |
|---|---|---|
| 事件流 | 相同输入下事件数量、顺序、最终模式一致 | 需可观察的事件日志面（真机侧观测手段先落实） |
| 寄存器配置 | 关键寄存器配置序列、流启停顺序一致 | 限已有或获授权的观测手段 |
| 时窗 | 按键识别时窗、响应时间落在**事先定义**的误差范围内 | 误差范围须先声明，不能事后拟合 |
| 音频输出 | 仅在输入、采集方法、容差三者明确时比较 | **「有声音」与「音质/ANC 效果正确」分开验收**；后者无校准手段时不进 D3（§6.4 游戏低延迟效果同口径） |

**差分回放的定位**：三镜像差分（L2-a/L2-b，§3）是**同模型内**的持续回归——官方、已
验证修改版、修复候选在预期修改点外保持一致，能发现回归；但**三者在同一模型上相同并不
能证明模型正确**。模型正确性的最终裁判是 D3 的真机对照；两者互补不互替。

D3 在本页只立框架：比较面的观测手段清单、容差声明格式是 D2 代表场景跑通后的后续路线，
不在本轮实施。

## 8. 验收记录格式（新增，codex 第 7 点；D1/D2/D3 通用）

每条验收记录**同时写「结果」和「证据等级」**，固定九栏：

`固件身份｜起始状态｜输入与时间表｜观察边界｜断言｜超时预算｜模型假设｜结果｜未覆盖项`

- **固件身份**：镜像 sha/来源（official/b79/EQ 候选），复用 §3.1 的身份钉死。
- **起始状态**：从真实启动进入还是可追溯快照（§7 要求），停点步数/PC。
- **输入与时间表**：注入内容（fixture 名/版本）与模型时间轴上的时刻；不用指令步数冒充
  毫秒（§1 时间口径）。
- **观察边界**：窗口起止、观测的 PC/寄存器/队列面。
- **断言**：引用哪条定义（D1-n / D2-an/bn / §6.3-n）。
- **超时预算**：模型步/事件数预算；超时=FAIL，不是重跑的理由。
- **模型假设**：本条依赖的投影/fixture 清单（含「DMA 完成行为投影」类标注，§6.2）。
- **结果**：`PASS / FAIL / BLOCKED / NOT_RUN` 四值。BLOCKED 语义见 §6.4（=D2 未完成，
  不是弱化 PASS）；D1-4 无样本=NOT_RUN 的诚实收口照 §1。
- **未覆盖项**：明确列出（模拟前端、DMA 总线仲裁、声学效果……），不许留空。

**证据等级**（独立于结果，另列一栏）：

- **条件性通过**（显式条件下通过）：断言在声明的投影/fixture 之下成立——既有
  conditional pass / derived-not-measured 措辞的验收版承接。
- **真机对照支持**：有 D3 观测数据背书（引用具体观测会话/证据文件）。
- codex 写法样例（原样保留）：
  > PASS，条件性：四路数据经 DMA 完成投影、IRQ68 和真实分发代码到达 ANC 输入；已跨两次
  > 环回。未覆盖模拟前端、DMA 总线仲裁、ANC 声学效果。

测试框架（probe 场景/report）须区分**外设仿真执行**与**真机执行**两类结果来源
（Zephyr emulator/twister 的分层实践可参考，但不能替代本项目的 BR28 行为证据）。

### 8.1 工具用法（路 AX/sim-accrecord 落地，2026-11-14）

九栏格式的机器可读落地=`tools/acceptance_record.py`（纯新增，不依赖 probe/模型代码）：

- **记录文件**：每用例一个 JSON，默认写 `analysis/local-checks/acceptance/<用例id>.json`
  （目录 git 忽略；`--dir` 可指定）。字段=九栏（`firmware_identity`…`uncovered_items`）
  +证据等级（`evidence_level`：`conditional`/`device_supported`，另列于结果之外）
  +条件列表（`evidence_conditions`）+真机引用（`evidence_refs`）+BLOCKED 依赖说明
  （`blocked_missing`）+记录时间戳（`recorded_at`，`%Y-%m-%dT%H:%M:%S`）。
