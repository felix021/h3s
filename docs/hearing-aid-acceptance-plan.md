## 0. 总则

### 0.1 授权模型（硬前置，先于一切真机动作）

真机动作分三档，每档都要用户明示授权，聊天文本确认即够（「看看/继续研究/计划不错」不算）：

1. **只读/基线档**：b79 基线复测、手机只读检查、USB 进 ROM + 双读全片备份（loader 只进
   RAM 不写 Flash，但它是设备交互，单独授权，不说成「纯只读」）。
2. **刷写档**：USB 把 HAL5 写入 bank B。授权必须绑定实际扇区计划——先备份、出计划、
   再确认（两段式，话术见阶段 1 §1b）。
3. **参数/测试档**：BLE 写 key30/31、重启、按键、音频测试、装新版 APK 到手机
   （手机当前装的 0.4/code6 早于助听 tab，阶段 2 前必须装 0.6.x 构建；装机授权随刷写档
   话术一并明示）。

授权话术要素（缺一即不算明示）：候选完整 SHA + 简称前 8 位（用户复述 `9ad0f088`
防拿错包；完整摘要由工具核验，不要求用户抄 64 位）、写入范围（bank B，保留 A/序号/设备
参数/VM/校准）、未测风险（r2 先例：可能无法连接/关机、异常出声、进不了 USB 恢复）、
A 自动回退未验证、恢复路径与耗时估计（不承诺必能恢复）、可随时叫停、回滚预授权
（触发即走已审查 profile，见 §2.2）。授权范围改变、候选或 profile 改变须重审；同范围
已授权动作不重复询问；用户撤销优先一切计数目标。

### 0.2 声明边界总原则

- **保存回执 ≠ 消费 ≠ 出声**（三个层级）：`30 01 00` 只证明 set_config 报告成功；坏魔数
  也照样存得进；曲线是否应用要看开辅听后的音频证据。
- **r0==1 / 回执成功只覆盖分发层**；十段 EQ 非事务（中途失败留部分曲线、fade 0.1f 平滑）。
- M 是调音工具**数字域 dB 刻度**（与 110.3 同标尺），非 dB SPL；attack=100 稳态上限成立
  ≠ 瞬时峰值不越限；±40dB 增益门、freq≤21599 是产品口径/观测域。
- **key30 运行时值 > L2 烘焙值 M=95**（docs/hearing-aid-l5-full.md §3）：合法写入的 M1
  直接覆盖 95，**95 不是硬上限**（App 助听页各频段默认上限 110，直接点「保存」会把 95
  抬到 110）；key 缺失/格式/范围拒时才回落 L2 兜底。
- 单人（用户本人）主观听感可以完成配对比较，但不能据此声明「十段均生效」「MPO 精确
  限幅」「安全声压」「听力改善」。

### 0.3 记录口径

四态沿用 tools/acceptance_record.py：未执行=NOT_RUN；所需工具/观测缺失=BLOCKED（附
blocked_missing）；预设断言被反例推翻=FAIL；断言在规定观察面成立=PASS。用户中止前已
违反的断言仍记 FAIL，中止后未执行的必选项 NOT_RUN 或 BLOCKED（说明缺续测授权）。不
用总 PASS 掩盖未验项；真机记录只有附实际证据引用才可标 `device_supported`。

### 0.4 时间与超时预算（预先固定的验收窗口，不是已测硬件规格）

所有时刻用主机/手机单调时钟记相对时间，另留 UTC 会话时间。超时不偷偷延长、不删掉失败
重跑；复测另编号并保留首次结果。

| 项目 | 预算/计数 | 超时或失败怎么记 |
|---|---|---|
| 开机到可查询的应用服务 | 60s | 健康 FAIL，停止功能测试 |
| BLE connect→READY | 扫描 10s、初始化每次 30s、最多 2 次退避 1s；外部会话上限 75s | 超时 FAIL；最多一次**有记录的**诊断复连，不覆盖首轮失败 |
| 单片 GATT 写回调 | 5s（App 现值） | 断链/本命令 FAIL，不自动补写 |
| 完整命令发送→匹配 RCSP 回执 | 5s（分片时间另计） | 正例 FAIL；已知缺 key 负例只判「本窗口无响应」 |
| 双击→可观察开/关变化 | 第二次按下起 5s；两次手势间隔 ≥5s 且前动作完成 | 无变化先停本项；状态不明禁止继续盲按 |
| 正常关机 | 基线确认的关机手势 + 10s 完成窗 | 无法正常关机=健康 FAIL（r2 对照点） |
| 开流后稳定等待 | 固定 2s 后取样；5s 仍异常即停 | 2s 是比较协议，不是内部提交完成证明 |
| 播放/空闲观察 | 播放 60s、空闲 120s；收尾有限运行 10min | 掉线/复位/异常发声任一 FAIL；不外推长期稳定性 |
| USB 备份/刷写/回滚 | 离线工具收口时逐操作定时 | 排期预留 30–60min 仅作日程估计，不承诺救回 |

### 0.5 会话冻结清单（每次真机会话开工前记档）

仓库 commit、候选/恢复包/已装 APK 摘要、profile 与 plan 摘要、匿名设备标识、手机 OS/
WebView 版本、参数原始 hex、样本 SHA、操作员、输入/输出路由、摆位、音量档、起止时间、
原始证据引用。整片备份、设备地址、日志原件存私有目录（analysis/，0600），不进公开 Git；

## 阶段 1：授权门、USB 刷写完整性、刷后健康

### 1a 新 USB profile 前置验收（H5-PRE-01，离线）

保持旧工具的 r2→b79 保护不变（不放宽、不加「忽略源摘要/任意目标」总开关），新增**具名、
digest 固定**的双向 profile：

| 断言 | 可执行检查 |
|---|---|
| 来源与目标精确绑定 | 输入 2MiB 双读相等；A/B 头 CRC、应用明/密文 CRC、长度与各自摘要匹配；A 序号 2/B 序号 3；候选 UFW 及其提取应用双重 digest 绑定；实际启动 bank 缺独立观测时注明「依据选择逻辑预期 B」 |
| 仅修改 bank B | B=`[0xee000,0x1da000)`，头 32B、应用自 0xee020；写入允许集收窄为**精确变化扇区**（由 before/target 全部差分位置推导，独立校验器复算一致），不授权整个 bank；**不得预填 r2 的六扇区** |
| 不覆盖设备参数 | B 头只更新 `+0..5` 头/明/密文 CRC 与 `+8..11` 长度；保留 `+6..7` 序号 3 与 `+12..31` 设备字段；A、bootloader 逐字节不变 |
| 保留同扇区其余字节 | 以本次双读原片为目标底图，只替换审计过的 B 应用与必要头字段；新增区来源/旧尾清除逐字节写进计划 |
| VM 与资源保留 | `[0,0xee000)` 与 `[0x1da000,0x200000)` 整段不变（含 VM `[0x1da000,0x1de000)`、配对/BTIF/TON/ANCIF）；UFW 的 942080B flash.bin 不是 2MiB 整片，不得整片覆写 |
| 扇区提交顺序 | boot-info 所在 `0xee000` 最后提交，且该扇区内应用字节同样完整校验 |
| 写前新鲜状态 | 执行前重读两遍相等；相对计划仅 VM 区允许变化、目标保留最新 VM 并重绑摘要；其它变化一律拒绝。回滚以**回滚当时**的新双读为底图，不要求整片回到首次备份 |
| 每步验证 | 擦后整扇区全 FF；块写 CRC/协议状态正确；每扇区读回相等；最终整片 2MiB 逐字节等于本次 target。任何错立即停止后续写入 |
| 离线判别力 | 错包/单 bit 损坏/错长度/相位/序号/非法头/A、VM、校准差分/旧计划复用/双读不一致全部在**首个擦除前**拒绝 |
| 中途中断处置 | 完整回滚 profile 不接受混合/坏 CRC bank；对每个擦除/块写/扇区提交中断点做假设备故障注入，依据原备份+不可覆盖 journal+现场新双读形成限定恢复方案；未知混合态拒绝 |

「头最后写」不是原子升级（旧头在过程中仍可能指向部分已改的应用）。保留 bank A 有价值，
但 **A 自动 fallback、强制选 A、完全不枚举 USB 的恢复均未验证**——不修改序号、不破坏
B 头去试 fallback；若剩余失联风险不可接受，就不刷。

### 1b 授权门（H5-AUT-01）

两段式、不同范围，避免拿到现场计划前空泛批准。第一段（基线+备份）：

> 我授权本次对这台 H3S 做 b79 基线复测、指定手机只读检查，以及 USB 进入 ROM、运行固定
> loader 并双读全片备份；不授权擦写、OTP 或其它 RAM 程序。备份保持私有。

备份后出实际刷入/恢复/扇区表/时间估算，再呈现填满的第二段：

> 我已查看 ACCEPT-HA 计划、刷入计划〔摘要/扇区表〕及回退计划〔摘要/扇区表〕，授权本次
> 将 HAL5 M=95 候选〔完整 SHA；简称 9ad0f088〕写入 bank B，保留 A、序号及设备参数、VM
> 和校准。授权所列 BLE 参数写入、重启、按键、分阶段音频测试及向手机安装指定 APK。知悉
> 候选未测，可能无法连接/关机、异常出声或无法进入 USB 恢复；A 自动回退未证；M 不是 SPL，
> 低 M 也不保证瞬时输出。恢复排期估计〔填实〕，不承诺必能恢复。我可随时叫停新测试。若
> 触发已列条件，我同时授权按已审查 profile 恢复 b79〔完整 SHA；简称 b79cb3a6〕；超出
> profile 或出现未覆盖混合态时停止并另报方案。确认 9ad0f088。

用户不预授权恢复就明确记下：故障时先停测试、出具体恢复方案再请求。可选 ANC 并存试验
与坏魔数写入必须在本次授权输入清单内，不从「刷机」推定。Flash 传输中叫停=停止新事务并
保留当前 journal（事前解释中途掉电风险），不把「可中止」承诺成强拔 USB 无风险。

### 1c 刷写执行与刷后健康（H5-USB-01 / H5-HLT-01）

离耳、稳定供电、主机不休眠、无其它 USB/BLE 控制者。新私有会话目录→双备份→审查计划→
写前新双读→逐扇区擦写验证→立即整片比对。异常不删 journal 重跑；按恢复文档识别 USB/
loader 阶段，不在残留 loader 上重复上传。读回通过后拔 USB、**手动正常关/开机一次**
（r2 恢复教训：这步是明确收尾步骤）；无法正常重启本身就是 FAIL。随后 60s 内 BLE READY+
版本/电量查询、A2DP 播放 60s、空闲 120s、正常关机；ANC 键与 App 按 **HAL5 预期**（§1d）
检查，不强求 b79 两态。**暂不打开 HA**（阶段 3 的事）。

**阶段 1 出口**：字节不符停止一切功能测试；刷后 BLE 失联/无法正常关机/复位循环→转已
授权恢复。仅 App 初始化失败且其它健康证据完整时，可做一次有界只读诊断，不把诊断复连
成功抹成首轮 PASS。通过只声明「限定镜像读回一致且基本应用健康」，不声明 HA 可用。

### 1d HAL5 vs b79 预期行为差异表（刷后验收对照，防把差异当故障）

| 行为面 | b79（当前设备） | HAL5（刷后预期） |
|---|---|---|
| ANC 键 | 两态循环 ON↔TRANS（b79 补丁） | **官方三态循环 OFF/ON/TRANS**（未带 --anc-cycle-two-state） |
| 提示音音量 | 音量表 -10dB（b79 构建） | **官方原值，比当前响约 10dB**（--attenuation-db 0；TON 资源文件两边相同） |
| 双击多功能键 | 音频模式循环（key 22） | **辅听开关 toggle**（阶段 3 验证项） |
| 版本查询 | V_0.1.1.8/280 | 相同——版本号不区分镜像 |
| QCY App 兼容 | 正常 | 预期不变（改动不触 QCY 命令面；cmdid 0x30 占用残余风险见 l4 §6.7） |

## 阶段 2：BLE 参数保存、读回与持久化

**全程 HA 关闭、手机测试音停止。** 先读已有 key 原始值存档（历史 VM 不能假定无 key；
key30 可能有路 AB 时代测试字节）。无独立 VM 读取证据时，静默只能记「5s 未收到响应」，
不能反推 key 必不存在；不擦 VM 制造缺 key 场景。前后各发一次已知健康只读查询，只证明
链路在这两个时点可用。

### 2a 字节断言（H5-BLE-01）

hex 口径：key30=1e / key31=1f，cmdid=30；读也走 FF 写形态帧，不能用 `FE 01 30` 原 getter 替代。

| 操作 | cmd 后载荷（data_len + data） | 响应 payload（外层状态/SN 也要对） |
|---|---|---|
| 写 key30 M=95 | `09 1e 48 41 01 00 00 00 be 42` | 精确 `30 01 00`（3B） |
| 读 key30 | `01 1e` | 精确 `30 08`+原 8B（10B） |
| 写 key31 | `59 1f` + 88B | 精确 `30 01 00`（3B） |
| 读 key31 | `01 1f` | 精确 `30 58`+原 88B（90B） |

key31 值：头 `48 41 02 00 0a 00 00 00` + 10×{u16 freq LE, u16 pad=0, float32 gain LE}。
首轮用官方频点 25/53/112/238/505/1070/2268/4807/10190/21599 + 全 0 增益，冻结 88B 及
SHA；App 预设可能是另一组频点，必须记录实际编码，不能只写「平坦」。频率边界合法不代表
扬声器可输出或算法采样率覆盖。

每 key 3 轮「已审查有效值写→回执→读回」，逐字节相等且 SHA 一致；至少一轮与前值不同
（初轮 M95、另一轮 M90；EQ 可一段 -3dB、末轮恢复全 0）。一次只有一个应用请求在途；
记录 seq/SN、连接代次、原始 TX/RX、实际 MTU、片数、时间。key31 整帧 100B：MTU≥103 才
单片；MTU23 则 5 片，逐片等回调且片间隔 ≥10ms；notify 重组同规。不把请求 MTU 当协商
结果，真机只声明实测 MTU。

`30 01 01` = set_config 失败：本次 FAIL、停后续参数试验。写超时 ≠ 没落盘：暂停队列、
重建可辨认连接代次后读回消歧，不盲目补写；仅一次复读是诊断，首次失败不改判。GATT 回调
成功 / bridge `{ok:true}` / 页面提示都不算 VM 已存的证据。

### 2b 负例与重启（H5-BLE-02/03/04）

- **本地负例**：未 armed、8B 长度错、EQ 段数 9/11、非有限/越界值——错误返回且 TX 计数
  为 0，逐项写明拒在哪一层。不经任意写接口把坏形状发上真机；固件侧 shape 拒绝留离线验证。
- **静默负例**：只有先有「get 返回长度不符/缺 key」的独立证据，才把 5s 无响应计为预期
  静默；否则该负例 BLOCKED（前提未观测）。不为凑负例删 key。
- **持久化**：两 key 精确写入确认后，正常关/开机 3 轮，每轮读回完全一致；不打开 HA。
  全片 SHA 不能跨运行比较（VM 合法演化）。

**阶段 2 出口**：两 key 往返/持久化必选项没过，不进参数听感；纯工具缺口记 BLOCKED 而非
固件 FAIL。通过只声明「保存/读取/持久成立」，不声明曲线已应用。

## 阶段 3：双击控制、声学路径与状态隔离

### 3a 首次开关（H5-KEY-01 / H5-AUD-01）——先离耳

手机音源停；两 key 读回为已审查值（M95/全 0）。**离耳**双击一次开，5s 内观察；再双击关
并确认附加输出停止。首次状态辨认不清即停，禁止盲按累计次数。开 HA 前的 db3c(1,1) 请求
可能播 anc_off 提示音——提示音只证明走到提示行为，不证明 ANC 硬件退出或 HA 出声；能查
ANC 状态就前后记录。**没有 HA 开关遥测**（RAM 槽 0x125574 不可读），开关状态只能靠外部
声音观测佐证。

**声学路径钉死**（防假阳性）：确认手机实际扬声器出声；HA 开/关各播同一低电平短语音 ×3
对；ANC 固定 OFF、蓝牙媒体暂停、无 HFP/麦克风竞争。开/关的耳机附加输出差异必须来自
「手机扬声器→耳机麦克风→HA 链→DAC」；A2DP 直达耳机、手机直达耳朵、普通通透都会造假
阳性。离耳录音需固定夹具并测 HA 关闭的直达泄漏；无可区分输出记 BLOCKED，不把「听见
手机」算 HA 成功。

### 3b 重复与重启（H5-KEY-02/03）

**10 个完整开→关周期 = 20 次有效双击**：每次只发生一次预期变化，无多翻/漏翻/意外音频
模式循环；人工手势失误单列不改写成固件成功；每周期收回至可确认关闭，动作间 ≥5s。正常
重启 3 轮：均默认 HA 关（boot 清零预期）、key 仍持久、首双击可开再双击可关。资源泄漏与
任务调度不在 20 次覆盖内。

**双击无反应处置**：健康/正常关机完整时，停 HA 与听感分支，仍可做已授权只读 BLE 检查；
HA 内部状态无法确认则连「继续开关」都不做。伴随失联/关不掉/声音异常→立即停全部功能
测试并转恢复。

### 3c ANC 并存（H5-ANC-01，可选、核心测试后离耳单列）

HA 开期间外部再开 ANC 没有「先关 HA」实现——**不把互斥定为当前候选 PASS 要求**，只记录
状态/出声变化、关 HA 与关 ANC 是否仍可操作。若产品要求严格互斥，该需求当前不满足，不
靠听感补证。并存测试异常立即结束；QCY App 不与测试 App 并发改设置。**建议首轮验收跳过
（NOT_RUN），不拖成核心失败**。

**阶段 3 出口**：开、关、默认关、声学路径均可辨识且无健康异常，才进佩戴 A/B。通过只
声明本窗口外部控制与声音现象，不宣称句柄无泄漏/ANC 强互斥/双耳增益已校准。

## 阶段 4：MPO/EQ 配对比较、软回退与测量边界

### 4a 固定比较条件

手机/耳机/操作员位置做标记（如手机距耳机 0.5m，方位/高度/佩戴松紧不变）；固定手机媒体
音量档、App 信号幅值、耳机音量、ANC OFF、房间。不因某轮「听不见」临时加音量。先短
语音，再按需加中频短纯音；125Hz/8k/16k 能力留可选（手机低频失真/高频无感不归咎固件，
不靠加大 16k 音量追可闻）。样本=固定 SHA 原文件，同配对用同片段；TTS5/音乐3/自然4 先各
选一条作核心，余作扩展，不做全笛卡尔积。记录片段起止/时长/播放次数。

样本 `-20 LUFS` 只是文件综合响度目标：固定版本 FFmpeg 两遍处理、记录实际 I/LRA/TP 与
输出 SHA，不逐试次重归一；纯音另记固定 PCM 幅度/淡入淡出/RMS/峰值。**文件 LUFS 与媒体
音量档都不等于耳机输出 SPL**。

### 4b 主观 A/B（H5-EQ-01 / H5-MPO-01）

每比较预生成 8 对（4×AB+4×BA 随机打散）；每条件 5–10s，中间静音并**关 HA→写全包→读回
→再开→等 2s** 后同片段重放。任何一轮超时/状态不清停本项（不在未知部分曲线上继续听）。
每 4 对休息 ≥1min；疲劳/不适/用户要求即结束。每对只记「前者更强/后者更强/听不出/无法
判断」+信心 0–3+备注，结束后揭序统计，原始选择不改。单人亲手看着参数操作是**开放比较**
（随机序不能消除期待影响），只有预生成且播放时隐藏的编码/自动控制才接近单盲——也不冒称
双盲。8 对是探索记录，不给统计显著性或一般人群结论。

| 用例 | 对照与控制 | 可声明/不能声明 |
|---|---|---|
| EQ 单段 | 全 0 vs 官方频点第 6 段 1070Hz **-6dB**（先用衰减，+6/+12 离耳筛查后另入清单）；固定 M95 与输入 | 可报告此人此片段可重复差异；一段可闻不证明其余九段，听不出也不证明未应用；MPO 在 EQ 下游可压掉增益差异 |
| MPO | EQ 全 0，M95 vs M85（数字域示例），同源同音量；未触发不升声源找限幅，可在审查范围内再降 M | 可报告参数间响度/失真主观变化；不能称 M=85dB SPL 或精确限幅；低 M 不能排除开流默认窗口 |
| 生效时机 | 固定一参数：HA 开着写另一值并读回→关/开，比较写前/未重开/重开后 | 无差异只支持「本条件未检出即时差异」；不能证明每块参数均未更新，也不能把 UI 提交时间当音频生效时间 |

**「听不出差异」是有效观测，不强行选赢家。** 卡 PASS 定义=「按协议完成 8 对并完整记录」，
卡名/断言须写明是比较流程完成；「确证曲线生效」是独立必选项，无测量能力就 BLOCKED，不
随流程 PASS。副作用/崩溃/无法关闭是行为 FAIL，不受主观不确定性豁免。

### 4c 客观声学补验（H5-MET-01，无器材即 BLOCKED）

要声明「十段生效/MPO 曲线」需固定声源、耦合/测量麦、无自动增益测量链，记噪声底/直达
泄漏/校准/重复摆位误差；同参数重复 3 次建立重复性，**先冻结检测门 max(3dB, 3×基线重复
标准差)**再比较，噪声大修夹具、不事后降门槛。无校准只做相对比较，不报绝对 SPL。十段逐
段单独改一段、测目标与邻频、覆盖左右输出（只验 1070Hz 不得写十段全过）；MPO 用同一输入
≥3 档电平阶梯比稳态与瞬态，控制 EQ/NoiseGate/手机压缩的混淆。测试范围外的音质、抗啸
叫、听力补偿/临床获益不在本路声明内。

### 4d 参数软回退（H5-DEF-01，先停音源、离耳）

保存两 key 原值；分别只改魔数第一字节 `48→00`（保留 8B/88B 长度与其余字节），受限工具
显示确切 hex。期望：回执仍 `30 01 00`、读回精确坏魔数；随后完整关→开，key30 按设计跳过
覆盖→重装载 L2 M=95 兜底，key31→Eq1Eff 文件默认曲线；两 key 互不替代（回退一个不清
另一个）。注意：**从低 M 软回退到 95 会增大输出**，不能佩戴时当「静音按钮」。坏魔数删不
掉 key、重启后仍在；EQ 中途失败可能留部分曲线，必须关后重建并以默认对照复验；回执/读回
只验「失效值已保存」，默认曲线实际装载仍需声学/内部观测证据。

## 阶段 5：恢复、收尾与最终状态

**软回退不替代固件回滚**（撤不掉 HAL5 代码）。**USB 回滚（H5-RBK-01）**走新 HAL5→b79
profile：以回滚当时新双读为底图保留最新 VM（不套 r2 六扇区、不要求整片等于最早备份——
试验已写 key 且运行会改 VM）；扇区集重新推导；整片读回等于本次 b79 目标；两 bank 应用
均 b79、A2/B3、资源与设备字段保留；HA key 残留如实归档（不以「恢复出厂/清 VM」名义清
设备数据）。写后拔 USB、**手动正常重启一次**，再做 b79 健康清单：连接/查询、播放、正常
开关机、ANC 键六次两态、双击六次音频模式循环回归、QCY App 三态控制。Flash 读回通过但
健康未过=恢复未完成。无法进入已验证 USB 通道/混合态不被接收时，保留现场与 journal、
停止自动处理、另报具体方案。

**收尾（H5-END-01）**：登记最终镜像、两 key 原始值/是否失效、HA 关闭证据、ANC 模式、
两 App 断开、armed 关闭、音源停止、末次健康状态与未完成项。首轮建议预授权「无论结果
均回 b79」作为终点；用户选择保留 HAL5 须显式确认实验状态，且回滚实测项保持 NOT_RUN
不填 PASS。有限运行观察 10min 后结束，不用「整机长期稳定/助听已验证」作总标题。
