## 0. 一句话结论

**崩溃与噪声是两组独立根因，且都不是「open/close 资源不配对」**：

- **蓝牙断联首选机理 C1（时钟面）**：open 链的 clock_alloc("mic_effect",24MHz) 触发
  DVFS 升频（**即时/延后路径可较快升挡**，另有 ~4s 周期 timer 重算，运行期随 util 与
  Σ 在 24↔48/72MHz 档间振荡）；每次切换在临界区里对 **JL_WLA（BT 射频模拟窗）
  0xFD1920/0xFD1924 做置位-PLL 重锁-撤销序列**，且**切换通知回调表里没有任何 BT
  消费者**；同时 **DAC 启动族 0x06071bca 对 0xFD1924 的 RMW 无锁**，与切换器同寄存器
  存在互踩窗口。BT 对时钟切换零感知 → 链路掉线；切换时机不定（冷启动首个 open 也
  命中）；esco 通话 alloc 128MHz 把 DVFS 顶稳在高档 → 通话不掉线（同观察面还有 C5
  算力不足，见 §3.2）。**桩层无法删除固件的 clock_alloc，但可以用「自名高挡时钟保持」
  抑制运行期振荡**（§4-A3，定位为诊断档）。
- **左耳噪声首选机理 N1（声道协商）**：桩里 `0x06074e64(stream,10)` 实为
  **set_scene(stream, PC_SPK=10)**（路 L1 把它标成 set_notify 是误标），把 ADC 的场景字
  节改写成 10 → ADC SR=全局；更广义地，0x9c2d 图是**无 Channel Expander 的 mono 设计**
  （官方 SDK 同名参考图的立体声变体靠 0xDA15 expander 节点做 mono→stereo，QCY 裁剪版
  没有），若协商把 SET_CHANNEL(2) 传到 ADC，ADC 产出双槽帧而 **en_map=0x1 只有 ADA ch0
  接了 mic——另一槽是无模拟输入的悬空通道，高 PGA 增益下输出刺耳垃圾**，单槽有效数据
  恰好解释「右耳有效+AGC 爬升、左耳固定刺耳」。修复=删掉 set_scene(10)（官方 DHA 从
  不做这个调用）+ 可选的显式 SET_CHANNEL(1) 钉死单声道（§4-B）。
- **open/close 资源配对审计结论（任务①）**：我们的 close 链（stop(fade=0)+release+
  notify(11)）与 open 在框架层**基本配对**——流/节点/ADC 通道/大缓冲/时钟节点全部正确
  回收；已知不配对仅三处且都不是崩溃主因：DacEff 112B hdl 每周期泄漏一次（release 在
  teardown 语境是 no-op）、官方 DAC_NOISEGATE_ON/OFF 配对我们没做（锚点未钉）、官方
  VolEff 音量设置我们没做（VolEff 以 blob 默认值跑）。**跨流共享节点 UAF 机制存在但被
  图拓扑排除**：五图节点 (uuid,variant) 集合与 mic_effect 零交集（§2.4）。

## 1. 框架 open/close 全链结构（任务①基础，[静态]）

「原生 open/close 例程」说明：路 I 已钉死 QCY 激活层（hearing_aid_player_open/close）
整段被链接器裁掉——**固件里没有原生 mic_effect 开关例程**，真机跑的就是我们的桩+载荷。
审计对象 = 载荷序列 × jlstream 框架 API 真实行为 × ADC plug/DacEff 驱动链。

### 1.1 jlstream 任务与同步 RPC（本路新钉）

- stop(0x060741ee)/release(0x06074204) 都是薄壳：stop 写 `h[stream+46]=fade` 后 post
  **cmd4**；release 在 `b[stream+17]==3` 时 zalloc(16B) 同步块 post **cmd9**。post 走
  0x06074192：`os_sem_init` → `os_taskq_post("jlstream",…)` → **`os_sem_pend` 同步阻塞
  等 jlstream 任务回执**。即 stop/release 是跨任务同步 RPC，在按键任务上下文同步等待。
- jlstream 任务主循环 0x06086980：tbb @0x060869ce 分派 **cmd 4..12**。**cmd4 且 fade==0
  时 stop 全同步**：0x06086acc → `b[stream+44]=4` → 0x6075b10(stream,4,0) →
  `b[stream+17]=8` + **同步广播 0x40008**（节点级 close：ADC 走 0x606f8b6 引用计数递减
  → 归零 0x606f3c4 digital_close+按共享标志 free 大缓冲）→ 释放同步量。fade>0 才是
  20ms 定时器异步路径（我们 fade=0，无此问题）。
- **cmd9**：摘待关链表 → 保存并清 `[stream+40]` → 引用计数 `b[stream+9]--`（**无论是否
  归零都执行** 0x6075cc8 整树释放）→ 归零才 0x6075be4（free 辅助链+清 16 位槽位图+摘
  全局流链 0x1264D8+free(stream) 92B）→ 0x6075cc8(root,0)=0x6075c1c **沿边链递归
  free 全部节点+边+调各节点类 op2_release** → `os_sem_post` 放行按键任务。
- **start(0x06074ffe) 在调用者上下文**（按键任务）直接跑：拿 pipeline 锁 → 0x20004
  派发 → 0x20002 重试环。**open 的节点构建/外设使能同步跑在按键任务里**。
- 流对象 92B（0x060744b4）：b[+8] 槽号、b[+9] 引用计数（创建=1；0x6075ce0 pin-all 会
  给全部流 +1，dispatch 尾/协商路径 0x6075d54 成对 unpin——**无泄漏**）、b[+17] 状态
  （3=运行/8=停）、[+40] root pipeline、[+52..67] 内嵌信号量。

### 1.2 两个既有载荷标签的勘误（子任务 C，影响后续所有分析）

- **`ADD_THREAD` 标签错**：0x06074ec6 实为 **jlstream_node_ioctl(stream, 目标id, cmd,
  arg)**（worker 0x06074e7e 按 pipeline id 匹配后 ioctl 派发；0x1100=根/SOURCE 通配）。
  铁证：pc_mic 对它的第二调用是 (0x48, 0x20003, **96000**)——0x20003=SET_FMT、96000 显然
  是采样率，「线程 flags/extra」读法不成立 [静态+SDK]。**即我们的 open 桩其实已经在做
  官方 DHA 的 `node_ioctl(SOURCE, SET_PRIV_FMT, 256)`（0x2000D/0x100），且参数正确**；
  真正的 jlstream_add_thread（SDK 传 "mic_effect1"）从未被调用过——但 open 在真机能出
  声，说明对该图非必需（pipeline 跑在默认 jlstream 任务上）。
- **`SET_NOTIFY` 标签错**：0x06074e64 实为 **两参 jlstream_set_scene(stream, scene)**
  （写 b[stream+28]+派发 0x20006=NODE_IOC_SET_SCENE）。我们的 `set_notify(stream,10)` =
  **把场景从上一步刚设的 16(HEARING_AID) 改写成 10(PC_SPK)**。pc_mic 用 (stream,10) 是
  因为 pc_mic 场景就是 10；官方 mic_effect.c 的 DHA open **从不做这个调用**。

## 2. open/close 资源配对审计总表（任务①交付）

| # | open 动作 | close 逆动作 | 配对 | 残留后果 |
|---|---|---|---|---|

| 2 | pipeline_parse：48B 节点×N+边 malloc；0x60746e6 跨活流复用（无计数） | 0x6075c1c 整树 free+op2_release | ✓（本流视角） | 跨流共享节点会被 free——**但五图节点集零交集，实际不可达**（§2.4） |
| 3 | ADC 开链 0x6032c0c：hdl+79[ch] 引用计数++、增益/SR、大缓冲 zalloc、挂 handler、启动 | stop(0) 同步广播 0x40008 → 计数--→归零 digital_close 0x606f3c4（关数字 ADC+按共享标志 free 大缓冲）+摘 handler | ✓ | 干净 |
| 4 | DacEff 0x60765b0：112B hdl、0x6073106 设备注册 | 0x40008→状态复位+条件清槽；**op2_release 在 teardown 语境是 no-op** | **部分** | **112B hdl 每开关周期泄漏一次**（10 次循环 1.1KB，非崩溃级） |

| 6 | 0x6074e64(stream,10)=set_scene(PC_SPK) | 无 | **多余动作** | ADC SR 三态走「全局」支+VolEff 场景注册错（§3） |
| 7 | open 前 db3c(1,1) 的 ANC 异步退出重配 | 无逆动作（ANC 侧自理） | **否** | 见 §3 N3 |
| 8 | clock_alloc("mic_effect",24MHz) | notify(11)→clock_free 同名摘链 | ✓（记账面） | **记账配对但触发 DVFS 时钟切换**（§2.2，C1 核心） |

**结论：open→close→open 的第二次 open 异常不是「close 漏拆资源」**——静态上 close 把
open 建的东西全部回收（除 112B hdl 泄漏与 noisegate 缺配对，均非崩溃级）。崩溃机理转向
「open/close 动作自身的副作用」（时钟切换、外设窗竞争、ANC 异步交叠），见 §2.2-2.3。

### 2.2 时钟面：clock_alloc 的完整因果链（子任务 A，[静态]）

```
open: get_pipeline_uuid 分支 0x06005982
  └─ clock_alloc("mic_effect", 24MHz) 0x06000978   ← 纯软件记账，本身零硬件写
       └─ 0x060008ca（重算调度器：alloc 新节点/free 后都会调）
            ├─ 任务上下文：直跑本体（lock → clock_set(当前值，即时门内 no-op) → 清计数
            │  → (重新)arm 4000 单位 timer，回调=0x06000a2e）
            └─ 中断/受限上下文：post 延后事件（参数携带档位选择回调 0x06000A0A——
               按请求查 0x0609D5C0 档位表），**延后路径会较快升频**（codex 勘误采纳：
               「首次切换必在 ~4s 后」不成立——请求变化可即时/准即时升挡）
                 └─ timer 每 ~4s 重算：target = min( max(util 目标, Σ链表请求), 160MHz )
                    （Σ 含 base 24M 常驻 + mic_effect 24M + 其它活动请求）
                    ≠ 已应用缓存 [QCY+712] 时 → 0x060004be 真正切硬件
```

0x060004be 切换序列（关键步）：切前回调表 [0x60A8998,0x60A89D8)×8（外设分频重算/SFC
静默/XIP 保护等，**无任何 BT 消费者**；第二机制 3 个监听器槽 0x126CFC 的全部访问也在
时钟框架自身，**BT 侧零注册**）→ 进临界 → 0xFD001C 切过渡时钟源 → **0xFD1920 |=
0x8000000、0xFD1924 |= 0x400（JL_WLA 射频模拟窗！PLL 重锁窗口）** → 开新源 → 等待重锁
→ PLL 分频写 0xFD001C → 撤销 WLA 位 → 事后回调。**BT 控制器库自己也编程 JL_WLA**
（0x60541a6/be/c0：[+84] 位域、[+64] PLL 位域←[QCY+684] 静态值）——两写入者共享窗口、
互不知会。

**DAC 启动族的竞争写**：0x06071bca（含 0x6071e74，open 时 DacEff 使能路径）里有
`[0xFD1924] = ([0xFD1924]&0xFFF9FFFF)|0x20000; |=0x80000; [0xFD0020]&=~0x300000`——
**无锁 RMW 与切换器同寄存器（音频用 bits[17..19]，切换器用 bit10）**，位互踩窗口真实
存在 [静态]。

各 pipeline 的时钟请求（event_notify 分支全表）：mic_effect 24M；a2dp 24M（ldac 再+12M）；
**esco 128M**；ring 48M（以 esco 名义）；linein 120M；pc_spk/pc_mic 96M；tone/a2dp_dec/
ai_voice **无请求**；常驻 base 24M（boot 0x060009e8）。

**解释力**：待机+BT 连接时 Σ=24M=当前值，无切换；开 mic_effect 后 Σ=48M → 下次 timer
（≤4s）触发 **24→48M 切换**（一次 WLA 重锁序列）；HA 运行中 util 随音频负载波动，
DVFS 每 ~4s 重评 → 可能反复升降挡；close 后 clock_free → Σ 回落 → 又一次切换。
**esco 通话把 Σ 顶到 ≥152M（>160M 封顶前的稳定带）→ 无切换 → 通话不掉线**。
[QCY+684]（BT RF PLL 编程输入）全 app 无运行时写入者——「音频 open 改 BT RF PLL 输入」
假设被否定。

### 2.3 已排除/降级的崩溃候选（记录在案）

- **跨流共享节点 UAF**（框架机制真实：0x60746e6 无引用计数跨活流复用+teardown 无条件
  free）：但**五图 (uuid,variant) 节点集与 mic_effect 零交集**（tone/a2dp/esco/pc 全查，
  §2.4 数据）——本场景不可达。降级为框架隐患（若未来同图家族并存需重审）。
- **「set_scene(10)→cmd10→0x6075d8e 跨流收养+清 [stream+40]」**：0x6075d8e 确实会重写
  [stream+40]（含写 0），cmd10 处理器（0x06086ab2）也存在；但全 app 扫描**没有任何静态
  cmd10 投递者**（post helper 5 站=cmd4/9/11×2；裸 os_taskq_post 到 'jlstream' 的全部
  9 站 cmd∈{0,5}）——该路径静态不可达，降级为未解机制（运行期动态构造 cmd 的可能无法
  排除，标注开放）。
- **流引用计数/槽位图耗尽**：pin-all/unpin 严格成对（临界区保护），干净。
- **stop/release 竞态**：fade=0 的 stop 全同步广播 0x40008，release 才拆树——顺序保证，
  无竞态。
- **堆耗尽**：每周期净泄漏仅 112B；echo/reverb 大缓冲在 close 正确释放。

## 3. 左耳噪声机理（任务③）与崩溃机理排序（任务②）

### 3.1 噪声机理排序

| # | 机理 | 证据 | 与症状吻合度 |
|---|---|---|---|
| **N1** | **声道协商把 ADC 推成双槽帧而 en_map=0x1 只有 ch0 有 mic**：0x9c2d 图是无 Channel Expander(0xDA15) 的 mono 设计（官方 SDK 参考图 `~/tmp/hearaid-cj/sdk/flow/麦克风音效.x6flow` 的立体声变体靠 expander 节点，QCY 裁剪版没有）；协商若把 SET_CHANNEL(2)（cmd 0x20007）传到 ADC，ADC GET_FMT 变 ch=37 立体声帧（b[priv+28]==2 分支 [静态]），ch1 槽=**未接模拟输入的悬空 ADA 通道**（4 通道里只有 ch0 被开），高增益下=刺耳垃圾 | [镜像] en_map=0x1；[静态] 37 分支存在；[SDK] 官方图变体 | **最好**：单槽有效（右耳环境声+AGC 爬升）+单槽固定垃圾（左耳刺耳） |

| N5 | DAC 端 ch=2 消费 mono 流（0x6072984 strided 拷贝） | [静态] 双路径存在（0x607287e 有 mono 专用分支） | 低：错位时两耳都坏，与「右好」不完全吻合 |

N1/N5 同源（协商声道值），差别在错位发生在 ADC 帧生成（最贴合）还是 DAC 帧消费。
**槽位↔左右耳映射未钉**（ch0→L 还是 R 未证），不硬说「垃圾必在左」，机理成立即可。

### 3.2 崩溃（蓝牙断联）机理排序

| # | 机理 | 证据强度 | 判别预测 |
|---|---|---|---|
| **C1** | DVFS 时钟切换扰动 BT RF 域：open/close 的 clock_alloc/free → 即时/延后路径或 ≤4s timer 的 Σ 变化 → 0x060004be 切换（WLA 0xFD1920/24 置位-重锁-撤销，BT 零通知） | 链路 [静态] 全钉；「切换→掉线」因果 [推断]（最强候选，与 C5 同观察面） | 断联时刻=双击后即时~8s（升频路径+timer+监督超时）；通话中开辅听不掉线；**A3 保持后不掉线只判「高频保持相关」（C1/C5 不分）** |
| **C2** | DAC 启动族无锁 RMW 0xFD1924/清 0xFD0020 与切换器/BT 并发互踩（open 当场的立即效应） | 写本身 [静态]；互踩后果 [推断] | 与 C1 同修复面（避免切换）+ 缩短 open 与 ANC 退出的并发窗 |
| **C3** | ANC 退出异步重配与 open 的 ADC/DAC 配置交叠（硬件层竞争，非纯噪声） | 时序 [静态]、后果 [推断] | 提前 ≥200ms 关 ANC 再 open，异常减轻 |
| C4 | cmd10/0x6075d8e 跨流收养清 [stream+40]（运行期动态触发？） | 机制 [静态] 存在、触发面未找到 | 开放项；真机日志/仿真前沿推进后复查 |
| **C5** | **算力/实时性不足**（codex 补充）：辅听 DSP 跑在默认 jlstream 任务，24-48M 挡下执行余量/调度及时性不足 → 超时/饥饿类故障；高档（通话/加 hold）即缓解——与 C1 同修复面难分 | [推断]（与 C1 观察面重叠） | 与 C1 共用 §5③/⑦ 判别；归因需跨周期保持实验 |

**冷启动首个 open 即崩的解读**：boot 后 sys=24M（0x6068528 按配置 set 24M）+ ANC 若
已在 OFF（db3c 同模早退无提示音，恰合「没有关降噪提示音」）→ open → 即时/延后升频
路径或 ≤4s timer 的首次 24→48M 切换 → 掉线。「重连后双击=提示音+噪声」与「ANC 在 ON
（配置恢复）→db3c 走完整 OFF」自洽；也不排除软复位路径不放开机音——判别实验①收口。

## 4. 修复方案设计（任务④，给下一路实施）

按 ROI 排序；全部为桩层（追加段内）改动，不动官方代码区（窗口 8B 除外，已占用）。
**字节预算：追加段可用区 3948B，L4/full 已用 874B，余 3074B**——下列各项总预算

### 4-A 崩溃面

**A1（必做，最小改动）open 前 ANC 退出等待（超时取消本次 open）**
db3c(1,1) 返回后**轮询 ANC 过渡标志**：`b[[QCY+500]+29]==0`（过渡清零）且
`b[[QCY+500]+33]==1`（已到 OFF）再继续 open；小步延时用 **0x6064efc(n)**（ANC 退出链
自己在用的任务上下文延时：0x6064efc(1)/(2)/(100) @0x606ebe0 链；任务上下文走
0x6064e80 睡眠，中断上下文走跨核路径——我们桩在按键任务，安全）。上限 ~600ms（ANC
退出 3ms-100ms+，留 6 倍裕量），**超时则取消本次 open**（codex 裁决采纳：超时=前置
条件未成立，放行只会把竞态带进 open；直接返回不开，槽保持 0，用户再按一次即可重试）。
- 证据：db3c 写 b[ctx+29]=1/b[ctx+33] @0x06072/76；ANC 退出链 0x606ebe0 异步、重配
  MIC_CTL1/ADA/增益。
- 预算：~56B。风险：b[+29] 清零与硬件重配完成的先后未钉——等待是缓解非根治；若
  anc_task 与按键任务有依赖反而死等，600ms 上限兜底（取消 open 而非挂死）。
**A2（必做）open 幂等加固**：open 失败路径已有 release+clock 回收；追加「open 返回 -22
时也清槽」现状已满足（槽只在成功路径写）。无需改动（记录确认）。
**A3（诊断档+可用缓解）DVFS 时钟保持（「时钟压舱」，codex 裁决修订版）**
open 的 ANC 等待通过后、**构建音频流之前**追加 `clock_alloc(<自有名串>, 128000000)`
（直接调 0x06000978，名串放追加段 rodata，如 "lfix_hold"）：Σ=base24+mic24+hold128=176M
→ DVFS 目标恒为 160M 封顶值 → **抑制运行期间的升降挡振荡**；close 在 stop/release 完成
后 `clock_free("lfix_hold")`（0x0600572c，按名摘链）。**所有权纪律（codex）**：申请
失败不记账直接继续；open 后续任一步失败（parse/start 错误路径）也要释放 hold；重复
open（槽非零早退）不重复申请。
- 证据：§2.2 全链；esco 128M 同款效果（通话不掉线的现成先例）。
- 预算：~80B+名串 10B。**边界（codex 裁决采纳）**：（a）**首次升频切换不可避免**
  （24→160M 一次仍走 WLA 序列），且 close 释放后下轮 open 再升——**每轮 open 仍有
  一次切换**；要完全压掉中间切换需「保持跨多轮 open/close」的诊断模式（仅测试用，
  需显式退出释放路径）。（b）**A3 成功≠C1 坐实**：160M 同时改善 DSP 算力余量/任务
  调度/缓冲及时性——A3 后不掉线只能判「高频保持相关」（时钟切换扰动 vs 算力不足
  不分），归因需配 §5 实验②/③/跨周期保持。（c）**长期代价**：HA 连续工作数小时的
  续航/温升未测，通话先例只能证明「该档可用」不能外推——A3 定位为**短期诊断档**，
  不作为最终产品方案；最终方案若 C1 坐实应为「避免 mic_effect 触发无谓升降挡」的
  固件级策略（超出桩层，另行立路）。

### 4-B 噪声面

**B1（必做，最小改动）删除 set_scene(10)**
从 open 载荷删掉 `0x6074e64(stream,10)` 调用（3-4 条指令，~14B）。场景保持第 4 步
set_scene(stream,16,0) 的 HEARING_AID。ADC GET_FMT 三态从「10→全局」变为「16→44100」
[静态]；官方 DHA 从不做此调用（SDK 源）。
- 预算：−14B（缩）。风险：若全局 SR=48000（a2dp 场景）而 DAC 跑 48000，改后 ADC=44100
  与 DAC 不一致（图内无 resample）→ 可能引入速率失配。**若真机验证发现音调异常，
  B1 备选形态**：不删而是改值为 1（scene=1→SR=16000，esco 语音带宽）——DHA 立体声
  宽带与 16k 的取舍由听感定。
**B2（改为「设初值」并需运行值核实——codex 裁决修正后）显式 SET_CHANNEL(1)**
原设计「start 前设一次即钉死 mono」**不成立**（codex 修正，已核实）：ADC 开链（cmd
0x40001 的兜底块 0x6032b6c-0x6032b94）会**按 en_map 重算通道数字节** b[priv+28]——
先写初值再逐使能通道 `+1`，en_map=0x1 时自然得 1（mono）。即：**默认开链本身就是
mono；N1 的成立条件收窄为「协商环（start 后的 0x20008 循环）把 SET_CHANNEL(2) 传到
ADC 且发生在重算之后」**。因此 B2 的正确形态是**start 返回后再设**（对协商结果做最后
覆盖）：`0x6074ec6(stream, 0x1100, 0x20007, 1)`；**arg 必须用 1（通道数量语义，
消费者直接存字节），不用 17/18/20（那是 audio_fmt.channel_mode 的模式枚举，编码不同：
AUDIO_CH_NUM(ch)=ch>>4）**。
- 预算：~24B。风险：（a）若协商根本没推 2（默认即 mono），B2 完全冗余——实施前先以
  仿真/日志核实协商后 b[priv+28] 运行值，别为冗余而改；（b）若 DAC 端真按立体声消费，
  mono 帧会走 DAC 的 mono 专用拷贝路径（0x607287e 分支存在）——双耳同信号，正是单 mic
  辅听的预期行为，但需真机听感复核双耳都有声。
**B3（建议）open 后设置 VolEff 音量（补官方 START 回调行为）**
start 返回 0 后直调 set_node_param（官方 mic_effect.c:258-277 同款）：固件候选锚点
**0x06074ece/0x6074efc**（按 11 字符名 "VolEff" 遍历管线节点表匹配 [静态·中置信，
实施前以一次反汇编复核入参序]），参数=volume_cfg（bypass=VOLUME_NODE_CMD_SET_VOL=0x10,
cur_vol=<默认音量>，如 60/100）。可选：读取 key（沿 key30/key31 通道）做运行时可调。
- 预算：~90B+rodata 16B。风险：锚点中置信需复核；volume_cfg 打包布局以 volume_node.h
  为准（packed）。

### 4-C 修复顺序建议（codex 裁决后修订）

**裁决结论：直接做「修订后的案 B」作为下一轮候选**（崩溃与噪声同轮处理，避免多轮
刷机验证），但按修订后的契约实施（A1 超时取消 open、A3 所有权纪律与诊断定位、B2
设初值+运行值核实、B1 附 SR 一致性核查）。

1. **候选 F1 = B1+B2(start 后设)+A1+ A3(可开关)**，其中 A3 尽量做成**运行时可关**：
   若能复用既有参数通道（沿 key30/key31 的 cmdid 0x30 家族，或 config key）让同一镜像
   在运行时选择 hold 开/关，则一次刷机即可做 A/B 对照（codex 建议）；若参数通道改造
   复杂，则出两个仅差 A3 的构建产物（更划算）。
2. **B1 附带核查**：scene=16 下 ADC=44100 与 DAC 实际 SR 的一致性（若 a2dp 全局 48k 且
   DAC 跑 48k，需评估速率失配；不把 scene=1/16k 当随手备选——只在上表核查后决定）。
3. B3（VolEff 音量）在 F1 验证后按需加。
4. 每候选沿 L5 审计纪律：追加段字节身份断言+分桶审计+四层 CRC+verify_ufw_integrity。
5. **真机验收按三个时间窗分开记录**（codex）：open 当场 / 持续运行跨越多轮 timer 重算
   / close 后等待再 open；记录断联次数与延迟、是否复位（双击行为判槽存活）、分别覆盖
   「ANC 已 OFF」与「需退出 ANC」两种前置态。**接受标准=整个 open→运行→close→再 open
   全程稳定**（仅持续开启不掉线不算完成）。

### 4-D 明确不做

- 不在桩层碰 JL_WLA/时钟寄存器（无法安全重入切换序列，且 0x060004be 已是固件现成路径）。
- 不给 0x9c2d 图加 Channel Expander 节点（改 stream.bin 图=拓扑级改动，超出桩层预算
  且无运行先例；B2 显式 SET_CHANNEL 是等效轻量替代）。
- 不做 noisegate 配对（锚点未钉，沿路 L 既有边界；若 B1/B2 后仍有底噪再开路）。

## 6. codex 参谋两案裁决（gpt-6-astra，2026-11-19 02:27）

4. **时钟时序模型错**：0x060008ca 除 arm timer 外还有**即时/延后升频路径**（受限上下文

   改写 §2.2/§5②。
5. **「A3 后不掉线=C1 坐实」撤回**：160M 同时改善算力/调度/缓冲及时性——只能判「高频

6. **降级若干过度断言**：「stop 同步」只证 RPC/回调顺序，DMA/IRQ/排队回调的异步引用
   未全排除（双核尤其）；「无 BT 回调」≠「无保护」（切换器有临界区+跨核请求，位互踩
   需证明确切交错窗口）；软复位未排除（开机音是间接证据）；新增候选 **C5 算力/实时性
   不足**（默认任务承载辅听 DSP，低挡下饥饿/超时同样掉线——与 C1 同修复面）。
7. **A/B 对照工程建议**：优先复用既有参数通道让 hold 可运行时开关（一次刷机做对照）；
   否则出两个仅差 A3 的产物。验收按三时间窗（open 当场/持续运行跨多轮 timer/close
   后再 open），接受标准=**全生命周期稳定**。
