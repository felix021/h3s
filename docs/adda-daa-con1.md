# DAA_CON1（0xfe0a04）：首个硬件反馈依赖的处理（路 CV/sim-adda）

**路号说明**：任务卡称「路 BF」，与仓内既有路 BF/sim-tickdeliv（core tick 交付，
2026-11-13）重号，照路 CT/CU 先例字母顺延记 **CV**（worktree/branch 名 sim-adda）。

停点背景：条件前沿 3,170,362 @ 0x606b426 读 0xfe0a04 = JL_ADDA->DAA_CON1
（br28.h `JL_ADDA=hs_base+map_adr(0x0a,0)`=0xfe0a00，+0x04 __RW，DAC 侧模拟
增益字；+0x20 起是路 AE 钉的 ADA_CON 族，布局互证）。这是**音频 init 尾段
首个非掩码平凡 RMW 读**——读值实质参与写回，且本世界该字零写：读的是
「DAC 模拟块寄存器内容」这个硬件域状态，投影世界无从推导（**首个真实硬件
反馈依赖**，路 AS 验收达成时的钉子）。

措辞红线：该状态一律表述为**「首次读取时的未知状态」**——ROM、他核、模拟域
复位都仍可能影响这个字；不说「零写历史暗示复位值为 0」。

## 1. 静态核对（反汇编钉死，repo codec pin 3608ed1）

### 1.1 RMW 函数 0x606b40e 全链

```
0606b40e: [--sp] = {rets, r4}            ; 序言(恰存 r4)
0606b410: if (r1 >= 3) { r1 = 3 }        ; 增益档位钳 3(表下标 0..3)
0606b416: r2 = 0x060A8608                ; flash 4 档增益码表(见 §1.4)
0606b41c: r3 = b[r1+r2] (u)              ; r3 = 表[档位] (u8)
0606b420: r1 = 0xFE0A04                  ; DAA_CON1
0606b426: r2 = [r1+0]                    ; <<< 停点:首读
0606b428: if ((r0 & 0x1) != 0) {         ; 通道 0 选择位
0606b42c:   r4 = r2 >> 3
0606b42e:   r2 = r3
0606b430:   r2 <= insert(r4, p:3, l:29)  ; bits3..31 保留旧值,bits0..2 ← 表码
          }
0606b434: if ((r0 & 0x2) != 0) {         ; 通道 1 选择位
0606b438:   r2 <= insert(r3, p:4, l:3)   ; bits4..6 ← 表码
          }
0606b43c: [r1+0] = r2                    ; <<< 写回:在两个条件块之外
0606b43e: {pc, r4} = [sp++]              ; 返回(函数不改 r0/r1)
```

要点：

- **insert 语义**：`(old>>3)` 以 29 位宽插回 bits3..31 ⇒ **bits3..31 逐位保留**
  （不是移位）；bits0..2 换表码；bit1 块再把 bits4..6 换成同表码。合成：
  `new = (old & ~0x7 | code) 再 (… & ~0x70 | code<<4)`（按选择位）。
- **写回位置在两个条件块之外**：r0 两位都没选时写回 = 旧值原样回写（总线写
  仍发生——AGENTS「unchanged-value RMW 仍发总线写」不变量在此显形）；本前缀
  r0=0xFF 两块都走。
- **保留位不被写覆盖**：bits 3、7..31 由初值原样带进写回值——初值依赖被写
  **持久化**进寄存器状态，只有「无消费者读这些位」才能让观察路径与初值无关
  （§3 敏感性对照实测正是这一情形）。

### 1.2 veneer 0x606db6c 是真调用，不是跳转

```
0606db6c: [--sp] = rets          ; 保存 veneer 调用者的返回地址
0606db6e: call 0x606b40e         ; 尾距 -10084(编码核算:0x606db72-0x2764)
0606db72: pc = [sp++]            ; 弹回原始调用者
```

返回链：0x606b40e 的 rts 回 **0x606db72**（运行态实测停点处 rets=0x606db72
互证），0x606db72 再以 `pc=[sp++]` 转回原始调用者——**原始调用者的返回地址
躺在 fixer 帧下方的栈上**（fixer 序言 +8B），静态核对时不能把 veneer 后一条
（0x606db72）当成「返回原始调用者」。

### 1.3 调用点（本前缀唯一到达：0x6071b70）

全 app 直接引用扫描（call/goto 目标 = 指令尾相对偏移，逐条核算）：

| 调用点 | 形式 | 实参 | 是否在本前缀 |
|---|---|---|---|
| **0x6071b70** | call veneer 0x606db6c | r0=0xFF、r1=0（双通道全选、档位 0） | **是（停点即其首读）** |
| 0x606dc00 | call veneer 0x606db6c | r0=单通道位（walker 纠偏分支） | 否（音量同步 walker 0x606db74，音频任务域） |
| 0x606b45c | 直调 0x606b40e | r0=3、r1=通道配置字 | 否 |
| 0x6071d92 | 直调 0x606b40e | — | 否 |

运行态实测（停点处寄存器）：r0=0xFF、r1=0xFE0A04（原 r1=档位 0 已被 0x606b420
覆盖）、r3=0x0=表[0]、rets=0x606db72——与 0x6071b70 调用点实参三方互证。
调用点语境（DAC init 驱动，S1..S5 同函数域）：

```
06071b6c: r0 = 255
06071b6e: r1 = 0
06071b70: call 0x606db6c         ; fixer: DAA_CON1 双通道增益 ← 表[0]=0
06071b74: r1 = 0
06071b76: call 0x606db36         ; setter: DAC_VL0 数字音量(§4 下一停点)
```

### 1.4 增益码表实测

0x060A8608 起四字节 = **{0x00, 0x04, 0x06, 0x07}**（chan/档位 0..3），紧邻
CRC16 表（0x060a860c）。**勘误**：路 AS 叙事与 docs/wlaud-init-map.md 记的
「0x060A8548」是转写笔误——指令编码（0x606b416 li r2=101352968=0x060A8608）
与路 BO 证据包一致；0x60a8548 处字节是 {0x2c,0x01,…}，非增益码表。

## 2. 两开关分立（codex 定调第 1 点）

| 开关 | 类型 | 语义 |
|---|---|---|
| `jl_adda_daa_con1_initial_fixture` | 值开关（显式 word，registry value_attr=JL_ADDA_DAA_CON1_INITIAL_PROBE） | 写前读一律返回该字（它就是假设的初始状态，一次性供给）；**无隐式零默认**；fixture 在报告里记录名称/来源/适用场景（label=sensitivity-probe-not-plausible-state） |
| `jl_adda_daa_con1_config_readback` | 布尔开关 | 已核定配置位维护当前值：真实写入后更新、后续读用当前状态（最后写值；__RW 先例=uart CON1 路 AA/lp_timer CON 路 AL；**容器无「合成初始 0」分支**——与 AK 域一/二/AS 域三容器的分野） |

组合行为（模型单测钉死，`JLAddaDaaCon1Registers`）：

- 默认全关：0xfe0a04 无容器，读/写均按 unmapped 停（3,170,362 原形状，legacy
  逐字节不变）。
- **只开读回、无初值、未写入**：读按**原边界**停（unmapped_memory 读
  0xfe0a04，kind/字段逐项一致——codex「仍停原边界」契约）。
- 只开初值：写前读=fixture 字；RMW 写回落记录；**写后读停原边界**（不立
  「普通存储式读回」假设，路 BB P3_AWKUP 首读 fixture 同款边界哲学）。
- 两者全开：写前读=fixture；写后读=最后写值。
- 白名单恰一字 0xfe0a04——**不一次放行整个 ADDA 读族**（codex 第 2 点）：
  DAA_CON0 0xfe0a00/DAA_CON2 0xfe0a0c/ADA_CON 族 0xfe0a20../DAC_VL0 0xfe051c
  全部保持 unmapped，后续读逐地址分类（§4）。

## 3. 敏感性对照（codex 定调第 4 点）

方法：从同一 3,170,362 停点分叉，仅初值 fixture 不同（0x0=保留位全零侧 /
0xfffffff8=保留位全一侧；**两者都是探针，sensitivity-probe-not-plausible-
state，不是合理状态**），读回开关两侧同为开。比较维度与结果：

| 观察维度 | fixture=0x0 | fixture=0xfffffff8 | 结论 |
|---|---|---|---|
| 首次写回值（0x606b43c） | **0x00000000**（实测落记录） | **0xffffff88**（实测落记录） | 写回值携带初值保留位（bits3,7..31），**依赖不因写而消除** |
| 后续 DAA_CON1 读 | 无（fixture 读 1、写 1、写后读 0） | 无（同构计数） | 无后续读消费保留位 |
| RMW 后分支去向 | 无值敏感分支（fixer/caller 均不测读值） | 同 | 路径不依赖初值 |
| 调用目标 | 0x606db36（setter，DAC_VL0） | 同 | 同 |
| 下一停点 | **0x606db4c 读 0xfe051c（unmapped_memory，size 4）** | **同** | 同 |
| 步数 | **3,170,379**（+17） | **3,170,379**（+17） | **多初值同停点=观察路径不敏感** |

证据分级（codex 表）：初值改变→写回值改变=**路径携带初值**（bits3,7..31
保留位）；写回差异不进任何分支/消费=**观察路径对初值不敏感**（本前缀）；
「仿真顺利返回不能证明初值正确」——fixture 值仅让链继续，不构成复位值声称。
保留位全一探针（0xfffffff8）额外证明 bits4..6 清位路径（0xffffff88 的
bits4..6=0）真实执行。

前沿 fixture 取 0x0（保留位全零侧探针）：两探针观察等价下取值任意，取零侧
与后续 DAC_VL0 世界的合成 0 先例方向一致。

## 4. 下一停点分类（codex 定调第 2/4 点）

放行（fixture=0x0+读回开）后首个新 MMIO 边界（实测）：**3,170,379 @
0x606db4c 读 0xfe051c = JL_AUDIO->DAC_VL0**（数字音量，双通道半字对；路 BO
§3 消费者全图）——setter 0x606db36 的 RMW 内部读（并行对第二半 `r3=[r2+0]`，
r2=0xfe051c；读值经 umin 钳制+半字 insert 组装进写回）。停点处实测：r0=0xFF、
r1=0（音量值）、r4=0x3a98（上限 [0x1265C0+1883*4]=[0x1272AC]）、
rets=0x6071b7a。**分类=配置**（数字音量配置字，br28.h __RW）：归下一路
「同法处理」（显式初值 fixture/读回投影的证据先行三选一）。本路不放行、
如实停。计数变化仅：exact_full_word_store 18369→18370（0x606b43c 写回）、
任务栈帧运输 13475→13477（fixer/setter 各一对 {rets,r4} push/pop）、
per-core {0:3,159,474→3,159,491, 1:11,216}；mmio RMW 2046/cnum 7399/
icfg bit9 4544/共享锁 1556 及 Timer0/CRC/rep 族全部不变（+17 步内无 RMW
指令、无到期）。

分类依据（BO 钉死，此处引用）：DAC_VL0 的消费者=getter 0x606daf0/setter
0x606db36/同步 walker 0x606db74（读回-比对-纠偏闭环）/静音 0x606dd16（读回
判零门控）——全部配置面消费，无状态位/测量值语义；对照 DAA_CON2 bit1
（0x606b352 读 `&2` 比较）=状态位读回消费，CHIP_ID=版本/身份——不同类。

## 5. 红线与不做的事

- 不发明初值：探针值显式标 sensitivity-probe-not-plausible-state；
  「首次读取时的未知状态」措辞；仿真通过≠初值正确。
- 不放行整个 ADDA 读族；DAC_VL0 起逐地址分类。
- 运行效果（DAC 模拟通路/偏置/实际增益/音量）不建模——只记录配置 RMW
  执行，不声称任何音频输出验证。
- 新开关默认关，legacy 报告逐字节不变（check_local 全量绿钉死）。
