## 0. 一句话结论

BT 面是**五任务+两硬件窗口**的结构：host 栈（btstack 0x605934E）与控制器驱动
（btctrler 0x603A4EE）都是 app.bin 里的普通 OS 任务，经 os_taskq_post 互通；控制器库
（0x6042-0x605c，含密码库 0x6048-0x604d）通过**两个无头文件命名的硬件窗口**（modem
寄存器窗 0xF00000/0xF08000/0xF0FC00 族 + RF 模拟 JL_WLA 0xfd1900）和**五个 IRQ
（41/76/78/79/82）**驱动片上 modem，ROM 里零 BT 代码、CPU1 与 BT 无关。仿真侧的墙有两道：
任务首跑即撞的**窗口读快照**（控制器库 init 会 memcpy 读 0xF00000/0xF08000/0xF0FC00/0xFD1900
共 1636B）和永远等不到的**IRQ 78/79 事件源**——「无模型制造 IRQ79 → btctrler/btstack
永无 0x400000x 源 → 可连接状态永不可达」，与 USB 的「无 SETUP→IRQ29 永无源」同构。
推荐照 AV 路**方案 (b) 钉住**：D2/R3 只需 app 事件注入（0x100003/0x100004/0x10000C 纯
RAM post + 0x6049626/0x6036d82 直调伪造控制器应答），modem 窗口最小模型 (a) 留 D3/专项。
**另有一处对既有记录的修正**：AY/S19MAP 的「0x100004→0x60160fc→0x60162de 创建链」
中间断裂（§6.1），创建块的真实触发面是配置表 @0x609d9c4 的 walker。

**分层边界结论**：
- **app.bin**：host 栈（btstack+profiles）、控制器驱动全栈（btctrler 任务+0x6042-0x605c

## 3. 「BT 启动到可连接」的精确边界（四问之三）

**仿真里走到哪会停**（按撞墙顺序；类比 USB 的三墙）：

1. **到达墙（D1 域，与 BT 无关）**：S19→park 不触任何 BT 代码 [文档 AY，本路维持]。
2. **注入墙（事件源=app 队列）**：BT 任何代码跑起来的前提是 app_core 队列收到
   **0x100003**（→0x6015ec2→0x60157ce：缓冲池+rcsp 任务）与创建块 walker（§6.1）被触达；
   唯一 0x100004 生产站 0x601670c 本身在 handler 域 [文档 AY]。模型必须注入这些事件
   （纯 RAM post——现有模型即可做，BW/CA 注入先例同族）。
3. **任务首跑墙（窗口读快照）**：btstack 首跑 0x60552b0 依次触达：0xfd001c RMW（已放行
   族）→ 0xfe2200|=1（已有模型）→ **0xfe2100 RMW（读回未建模，首停点候选）**→
   0x12e29c ROM delay（ROM 可执行）→ 0xF0FC10 配置写（可按记录放行）→ **0x6054186
   JL_WLA 读写（0xfd1900 未建模）**；btctrler 侧 init 更狠：**memcpy 读 0xF00000(400B)+
   0xF0FC00(816B)+0xF08000(260B)+0xFD1900(160B) 共 1636B 未映射读**——「未映射读即停」。
4. **协议墙（永无源，BLOCKED 的实体）**：即使 3 全放行，**IRQ 78/79/82/76/41 无模型触发**
   （需要真实射频/基带事件）、0xF08BE8 pending 永远为 0 → ISR 永不进 → 控制器库状态机
   （0x605264e 28 态 tbh）永不推进 → 无 HCI 事件可 post → **btctrler/btstack 除 init 时
   自 post 的 0x40000C 外永无消息 → 「可连接/已连接」状态永不可达**。这正是 D2 无线用例
   预期 BLOCKED 的确切内容。

## 4. 建模方案候选（四问之四）

| | (a) modem 最小模型 | **(b) 钉住（事件注入+读回投影）** | (c) 具名 fixture（状态字节预置） |
|---|---|---|---|
| 建模什么 | 0xF08BE8 pending/ack 位推进+IRQ78/79 交付+窗口 FIFO 数据泵+影子初值 | app 事件注入（0x100003/0x100004 族/0x10000C post）+ 0x6049626/0x6036d82 直调伪造控制器应答 + 窗口/寄存器「读回=影子初值」投影（1636B 快照读按擦除态/出厂 fixture 放行） | 预置 b[0x1265C0+864] 等已连接标志+连接表节点 |
| 固件哪段真跑 | 全链：ISR→引擎→HCI→profile | 任务循环+回调面+RCSP 命令链+S19 分发 | 同 (b) 的消费段 |
| 风险 | 面大（5 IRQ+窗口语义全未钉）；无实测可对 | 影子初值集合需 fixture 化；协议路径零验证 | 同左，且不解决「到达」 |

**推荐 (b) 为主**，(c) 作为其状态附件，(a) 列 D3/专项。分视角：

- **D2 无线用例**：断言对象是应用侧行为（事件→路由/状态/命令回包），不是空口协议正确性。
  注入面全纯 RAM：0x10000C 事件（BW 已在 0x60252c6 入口注入过双击，同一机制）+
  BT 状态事件（0x100004 族）。**D2-B 框架任务（CI）与 D2-a 环（AO）的既有注入机制
  直接复用，BT 专项新增=0x6049626/0x6036d82 两个直调口+连接态 fixture 字节**。
- **D3 真机一致性**：需要对拍真机的 BT 状态字节/事件序列——用 (b) 先把「已连接世界」
  跑起来，把 §3 表 #1-#5 的注入序列对齐真机抓包（若有），(a) 只在需要空口级一致性时立项。
- **R3 app 联调**：真机侧 AndroidBleTransport（路 AU 已落地）连的是**真机 BLE**，不是仿真。
  仿真侧的接驳点=**0x6000cba（RCSP 命令桥）或更下游 0x60252c6**：把 transport 层收到的
  RCSP 帧直接注入仿真分发链，即可在无 BT 硬件模型下跑通「app 命令→固件状态迁移→事件
  回包」全闭环。**R3 不需要 (a)**。
