2026-11-13。本页是 BJ（D1 验收）前置预研的续篇，回答 D1-4「消息消费全链」断言的
两个关键未知：①S18 预置事件 (18,0)/(20,2) 走完消费链后触发什么；②Timer0 回调表
[0x126f6c] 何时被填、D1 窗口内 Timer0 周期对消息循环的贡献是什么。**只读**：未改
tools/ 任何代码；反汇编用钉死 codec（pi32v2-isa @3608ed1，主仓 reference-cache，
RAM-code 从 flash 源 0x060c3e18 窗按 RAM 基址重解码）；动态证据来自一次内存态观测
（import probe_irq_entry.irq_case 按主场景参数在内存里重跑 p11_heap_experimental_config
及 timer0_irq4_delivery_probe，只追加额外 RAM 快照、不落盘任何报告文件、analysis/
基线不动——纯调用侧参数注入，tools/ 文件零改动）。

证据强度：**[静态]** = 指令锚定反汇编（本路）；**[模拟器]** = 钉死上游模拟器步进；
**[采样]** = 上述内存态重跑的 RAM 快照实测（步数为指令步口径）；**[文档]** = 既有
docs/HANDOFF 钉死条目；**[推断]** = 由上述证据链推出。结论基于 main `52b5622`。

## 0. 摘要（两未知各一句话）

1. **S18 事件没有 id 变换**：post API 硬编码事件 id=0x10000C，raw 18/20 只是载荷
   首字（子码）；(18,0) 由分发表 handler 0x6023962 认领（链尾是两个门控字节挡住的
   短闭合），(20,2) 走特路的 sys_timer 手动触发路径（查 0x126F3C 链表 id=2）。
2. **Timer0 回调表在 ~110.5k 指令步就被填好**（值=0x603622C，tick_timer_init 的
   注册段 0x6066d86 写入，经 0x1265C0+2476 偏移寻址所以全镜像无字面量），D1 窗口内
   每个 Timer0 周期都执行 tick 回调（计数+累计+sys_timer 轮询）——**不是纯空转**，
   但 D1 窗口内已注册的两个 sys_timer 定时器都不到期、不产生新事件。

## 1. S18 两事件的全链推演

### 1.1 post 链（谁把事件放进队列）[静态]

S18 段（app_core 尾段，循环前）：

```
0x60123a6: r0 = 18; r1 = 0;  call 0x6000cba    ; post(子码18, 参数0)
0x60123ae: r0 = 20; r1 = 2;  call 0x6000cba    ; post(子码20, 参数2)
0x60123b6: r0 = 632; r1 = 1; b[r8+632] = 1     ; S18 尾部标志位
```

call 目标按 end-relative 精确计算是 **0x6000cba**（0x60123ae-71412；tail-map 记的
0x6000cba 正确，**d1-acceptance §2.3 记的「0x6000c5a（2 字节跳板 goto 0x601107c）」
是地址笔误**——0x6000c5a 的 goto 实际指向 0x600107c，与本链无关）。

0x6000cba 是事件 post API [静态]：

```
0x6000cba: [--sp]=rets; sp-=8; d[sp]=r1_r0     ; {18,0} 载荷压栈
0x6000cc2: r0 = 0x60a1d11                       ; 队列名/标识（flash 字符串区）
0x6000cc8: r1 = 0x10000C                        ; ★事件 id 硬编码，无任何 raw→0x1000xx 变换
0x6000cce: r3 = sp+0                            ; 载荷指针
0x6000cd0: r2 = 2                               ; 载荷字数
0x6000cd2: call 0x6064978 → 0x606487c           ; 入队机制（tail-map 钉过的 event machinery）
```

0x606487c 入队表示 [静态]：环队列 slot 头字 = `(字数+1) | (id << 8)` =
`3 | 0x10000C<<8` = **0x10000C03**，后跟载荷 {18,0}（12 字节记录）。队列对象经
0x60647fa(0x60a1d11) 按名字查找，环游标/容量在对象 +8/+12/+14 [静态]。

### 1.2 get-event 返回与 [sp] 的 id [静态+互证]

S19 循环 `0x60123ea: call 0x6064c8c(sp,16)`；0x6064c8c → 0x6064b98（取记录）→
0x60649b0（解包）：

```
0x60649b8: r0 = [slot]          ; 头字 0x10000C03
0x60649ce: r0 = r0 >> 8         ; → 0x10000C
0x60649d0: [r9++=4] = r0        ; ★buf[0] = id（0x10000C）
0x60649f4: [r9+r1<<2] = 载荷[i] ; buf[1]=18、buf[2]=0
```

即 **[sp] 读到的就是 0x10000C**（不是 0x10000C03）：bit20 检查过（0x10000C &
0x100000 ≠ 0）、id==r12（0x10000C）→ 特路命中。BR 留的「id 变换待一处运行时观测」
就此静态闭合：**变换不存在，post 直接用 0x10000C**。

### 1.3 特路 0x60108fe 按子码分派 [静态]

特路以**载荷首字（子码）**分派，不是按 id（id 已被特路拦截）：

```
0x6010924: r0 = [r9+0]                 ; 子码
  == 21 → 0x601093a（0x126F44 第二链表分支）
  != 20 → goto 0x6010a38（公共出口，返回后继续分发表 walk）
  == 20 → 0x6010932: r0 = r6.b0        ; r6=[载荷+4]=2
           call 0x60108c6              ; 0x126F3C 链表按 id=2 查节点
           → 命中则调节点回调（0x601096a call r1 链）
```

- **(18,0)**：子码 18 → 直接走公共出口 → **特路返回 0，继续分发表**。
- **(20,2)**：子码 20 → 查 0x126F3C 链表 id=2。@689,402 采样该链表非空（首节点
  id=1、回调 0x609d9e0；第二节点 id 未采样）[采样]——**id=2 节点是否存在是 (20,2)
  消费的一个运行时观测项**：若不存在，r5=0 后 0x6010946 `b[r5+0]` 读地址 0 会在
  模拟器撞 unmapped_memory 诚实停（独立边界，非链路不通——固件实机上链表语义保证
  查询合法）。

### 1.4 分发表 walk 顺序修正 [静态]

S19 的 0x601240a 段 walk 的是**表 2（0x60A8C68..0x60A8CB0）**（初始游标
r0=r11=表 2 基址，边界 r13=表 2 结束）；walk 完经 0x6012424..0x6012456 段（含
[r8+611*4] 过滤对象调用，见下）再走**表 1（0x60A89E0..0x60A8C68）**（r10 基址、
r7 边界）。**d1-acceptance §2.1 的「0x601240a 游标走表（表 1）」与「第二表」的
顺序记载反了**。表 2 无 filter 检查；表 1 段当过滤对象 [0x1265C0+611*4]=[0x126F4C]
非 0 时要求 `对象字节 != 记录.filter` 才调 handler（0x6012442..0x6012446；
@689,402 采样 [0x126F4C]=0 → 过滤未激活，全部表 1 记录无条件参与匹配）[采样]。

handler 调用约定：`r0 = 载荷指针（sp+4）`（0x601241a mov.rr.p 并行对：A 半
`r0=r4` 与 B 半 `r1=[r0+8]` 取 handler 字——B 半按硬件语义读旧 r0=表记录指针），
`call r1`；返回 0 → 继续 walk 同一事件的下一条匹配记录；非 0 → 本事件分发结束
（0x6012422 回循环头取下一事件）。**一条事件可命中多个 handler**（20 条
0x10000C 记录挨个检查）。

### 1.5 子码认领表与 (18,0)/(20,2) 的 handler [静态]

20 个 0x10000C handler 的入口子码检查（本路批量反汇编）：

| 认领子码 | handler |
|---|---|
| 18 | **0x6023962**（表 1[39]） |
| 20 | 无（特路 sys_timer 路径是 20 的唯一消费者） |
| 21/22×3/29-31/32-36/108-115 等其余子码 | 0x600434a(22)、0x600de6e(22)、0x601411a(29-31)、0x6015480(33)、0x6017608(34)、0x6017c18(3-10)、0x6017e0c、0x6017f0c(113/114)、0x601875a(无检查)、0x60190d8(32/35/36)、0x601b232/0x6023426/0x60252c6(位掩码族)、0x602325e(108)、0x6023962(109/110/112/18)、0x6023a0a(109/112)、0x6024db8(22)、0x6026052(115)、0x6016b84/0x6016b88(恒返 0 桩) |

- **(18,0) 的消费**：表 2 walk（0x600434a/0x60252c6 都不认领 18，返回 0）→
  表 1 walk → **0x6023962 认领 18**：
  ```
  0x6023972: if (r1 != 18) skip
  0x6023976: r0 = 0x8FBE(36798)        ; 资源/事件码
  0x60239b2: r0 = 0x9DD2(40402); r1=0
  0x60239ba: call 0x60237d8(40402, 0)
  ```
  0x60237d8 是短链：并行对读 **b[0x125B54]**（功能门控）——非 0 直接返回；
  =0 时 call 0x601a592(1, 40402, …)，后者再查门控 **b[0x127184]** [静态]。
  两个门控 @689,402 采样 b[0x125B54]=0 [采样]、b[0x127184] 未采样——**若两级
  门控都关（未启用对应功能），(18,0) 的 handler 链短闭合**（0x6023962 执行、
  经 0x60237d8/0x601a592 的门控检查、返回 0、回 pend）；若门控开，深层是
  0x601a5xx 域（BT/提示类，未逐层命名——那是 D1-4 之外的下一个边界，如实记录）。
- **(20,2) 的消费**：特路 sys_timer 路径（§1.3）+ 全部分发 handler 均不认领
  20 → walk 完回 pend。

### 1.6 S18 handler 链上的下一层事件/回调注册 [静态]

0x6023962→0x60237d8→0x601a592 链上**没有 post 新事件、没有定时器/回调注册**
（三个函数体都是门控+参数搬运+尾调用）。S18 两事件的消费链在 handler 返回 0 后
回循环头，不产生下一层事件。

## 2. Timer0 回调表 [0x126F6C] 的填充时序

### 2.1 写点（唯一的）[静态+采样互证]

**写点在 tick_timer_init（0x6066c78 函数整体）的注册段**，此前全镜像字面量扫描
（app flash/RAM code/RAM DATA/ROM）对 0x126F6C 只有 RAM code 读点 0x12ecd6——
因为写点经「设备结构基址+偏移」寻址，不产生字面量：

```
0x6066c78: tick_timer_init（OS tick 初始化，一个整体函数）:
  0x6066c82..c8e: 初始化 sys_timer 快/慢轮双链表头 0x126DF0/0x126DF8（自指）
  0x6066c92: malloc(16) tick 对象 {+0:1000us, +4:回调0x603622C, +8:-1, +12h:1}
             挂 [0x1265C0+776]=[0x1268C8]
  0x6066cc0..cd8: 扫 TIMER0..5（对象表 [0x126F54+id*4]==0 且 SFR CON&3==0）选空闲
  ── 选中（id=r7=0）后 fall-through 进注册段：
  0x6066ce4: malloc(72) timer 对象 → [0x126F54+id*4]（对象表写点，0x6066cec）
  0x6066d08..d16: 对象 {+4:周期(取 tick 对象+0), +8:回调(取 tick 对象+4=0x603622C),
                  +16h:优先级, +68:SFR 地址}
  0x6066d34..d72: 配 SFR（CON=0x4000 PND清/CNT=0/PRD 按源与分频计算）
  0x6066d76..d82: tid = (SFR-0xFD0400)>>>4 /16 = 0
  0x6066d86: r0 = r11 + 2476           ; ★0x1265C0+0x9AC = 0x126F6C（回调表基址）
  0x6066d8a: [r0+tid<<2] = r9          ; ★[0x126F6C] = 0x603622C —— 写点
  0x6066d94: r2 = [0x60A2508+tid*4]    ; QCY Timer ISR 表 → 0x12ece8
  0x6066d98: r0 = tid + 4 = 4          ; IRQ index = tid+4（Timer0→IRQ4，与路 BE 互证）
  0x6066da6: call request_irq(4, prio=1, 0x12ece8, cpu0)
```

这一段就是 SDK `_timer_hw_set_irq_cb`（gptimer_hw_v2.c bitcode：`gptimer_cb_table[tid]
= irq_cb; request_irq(timerx_index_table[tid], priority, timer_hw_cb_table[tid], 0)`）
的 QCY 内联形态——QCY 没有链接 SDK 的 gptimer.c 封装层，驱动逻辑直接写进
0x6066c78。

### 2.2 写入时刻 [采样]

预算二分（p11_heap 场景、指令步口径）：[0x126F6C] 在 **110,000 步=0、
111,000 步=0x603622C**——写入发生在 **110.0k..111.0k 之间**，即 OS 初始化段
（AGENTS 记录的 tick_timer_init 时代，~110.8k）。此后直到 689,402 停点恒为
0x603622C，槽 1..5（TIMER1..5）恒 0 [采样]。

**对路 BE 记录的一处修正**：BE 条目称 delivery probe 交付时「空回调派发」。当前
main（52b5622）实测重跑同一 probe 场景：交付时 [0x126F6C] 已是 0x603622C（110.5k
已填），handler 0x12ece8 → 0x12ecd4 → **call 0x603622C 真实执行**——停点快照
[0x1268CC]=1、[0x1268D0]=0xa（tick 计数恰 +1、累计 ms 恰 +period10）[采样]。
BE 的交付/W1C/RTI 机制记录全部正确，「空回调派发」四个字与实测不符（推测当时
按静态假设表空描述，未核 r1 值；BE 时代的 analysis 报告不在 git 历史中无法复核，
以当前实测为准）。

### 2.3 回调 0x603622C 与 sys_timer 层 [静态+采样]

```
0x603622c: tick 回调（每次 Timer0 到期执行）:
  r0 = 0x1268C4 tick 块
  [r0+8]  += 1        ; [0x1268CC] tick 计数
  [r0+12] += [r0+0]   ; [0x1268D0] 累计 ms（period=10，wrapper 0x6000898 配）
  call 0x6066de0      ; sys_timer 轮询
0x6066de0: 遍历快轮 0x126DF0 / 慢轮 0x126DF8 两张链表:
  节点 {id@-4(无), next@0, prev@4, 回调@8, 到期时刻@20, 参数/标志@24, flags@28}
  到期（[+20] ≤ 当前 tick 计数）→ 摘链（周期标志 bit25 时重挂）→ call [+8](arg=[+24]&0xFFFFFF)
```

@689,402 快轮链表内容 [采样]：两个节点，均为 BSS 静态结构（非堆）——

| 节点 | 回调 [+8] | 到期 [+20] | 参数 [+24] | flags [+28] |
|---|---|---|---|---|
| 0x1261E4 | **0x606750c（LRC trim 例程）** | 115 | 10 | 0x00010001 |
| 0x126208 | **0x6069538** | 115 | 10 | 0x00010002 |

（慢轮 0x126DF8 空。）

**对 HANDOFF 路 AF/AG 记录的口径修正**：「第一个/第二个任务创建（入口
0x606750c / 0x6069538）」的 call 0x6066c26 实为 **sys_timer_add 的 4 字节 thunk**
（0x6066c26 `call 0x6066ba6`，即 sys_timer_add(回调, 115tick, arg=10)）——这两次
是**软件定时器注册，不是 OS 任务创建**（真任务创建是 pmu_task 那次 0x6067242，
AF 的多任务往返记录不受影响；「优先级 10」实为定时器参数）。注册后 wrapper
0x6000898(10) 启动 Timer0（10ms STD12M）的记录不变。

### 2.4 D1 窗口内 Timer0 周期的贡献 [推断，基于上述静态+采样]

D1 窗口（park 后 ≥3 个 Timer0 周期 ≈ 120k 模型步 ≈ 12 个 tick）内，每个周期：
W1C ack → tick 回调（[0x1268CC]+1、[0x1268D0]+10、轮询 2 节点）→ RTI 回 park。
两个定时器到期时刻都是 tick=115（≈1.15s，D1 窗口外）——**D1 窗口内 sys_timer
轮询零命中、零新回调、零新事件**。Timer0 周期对消息循环的贡献=**把 tick 计数
推进 12 步 + 唤醒 park 的核再 park**，没有事件产生。若 D1 验收窗口拉长到 tick=115
（~460k 模型步 park 后），trim/0x6069538 定时器到期、其回调动作成为下一个观测面
（本路未展开）。

## 3. 对 D1-4 的验收建议

1. **S18 预置事件够不够当消费样本**：够。**(18,0) 单事件即满足 D1-4 全链**——
   post 实参（0x60123a6）→入队表示（0x606487c 环 slot 0x10000C03）→get-event
   返回 13（0x6064c8c）→[sp]=0x10000C→bit20→特路（0x60108fe 子码 18 直通）→
   12 字节表命中（表 1[39]，walk 顺序表 2 先、filter 未激活）→handler 0x6023962
   真实执行→call 0x60237d8（门控 b[0x125B54]=0→再查 0x601a592 门控 b[0x127184]）→
   返回 0→回 pend。**唯一残余不确定**：两级门控若开着，深层 0x601a5xx 域未逐层
   验证——但该域无 post/无回调注册（§1.6），链路闭合性不受影响；若模拟在其内部
   撞新边界，那个 unknown 属 **BT/提示域（D2+）**，按「D1-4 断言面=0x6023962 执行
   +返回+回 pend 已达成、深层域边界如实记录」收口。
2. **(20,2)** 是第二样本（特路 sys_timer 路径），但其消费依赖 0x126F3C 链表 id=2
   节点的存在性（§1.3）——id=2 缺失时撞 b[0] 读停点。建议 BJ 把它列为观测项而非
   D1-4 必经样本（(18,0) 已够断言面）。
3. **「回调表空 vs 链路不通」的区分**（d1-acceptance §1 D1-4）现在可静态回答：
   [0x126F6C] 恒非空（110.5k 起=0x603622C），Timer0 handler 的回调派发不是空跳；
   D1 窗口内没有事件源依赖该回调（sys_timer 到期都在 tick=115）。
4. **D1-4 与 D1-2 的交互**：S18 事件消费发生在首批循环迭代（D1-1 允许），之后
   空队列 pend；Timer0 周期在消费之后仍需覆盖 ≥3 个完整周期（d1-acceptance 的
   「分发后再覆盖一完整周期」要求不变）。

## 5. 方法与不确定处

- 动态采样=内存态重跑（p11_heap_experimental_config 全参数 + timer0_irq4_delivery_probe
  参数），只注入额外快照窗（0x126F3C/0x126F64/0x1268C0/0x1261E4/0x126208/0x125B54/
  0x12524C 等），停点与主场景一致（689,402 @0x6011704 / 304,857 @0x60116e6 的
  fd31 停点），报告零落盘、analysis/ 基线零改动。
- [0x126F3C] 链表第二节点（0x125270）的 id 字节未采样——(20,2) 特路查询结果
  是 BJ 运行时观测项；0x126F3C/0x126F44 两链表的注册者（0x609d9e0/0x609d9fc
  回调所属域）未逐层命名。
- b[0x127184] 门控值未采样；(18,0) 深层 0x601a5xx 域未反汇编完（若门控全关则
  不进入）。
- 常量 0x8FBE/0x9DD2（0x6023962 用）语义未命名（资源/事件码类）。
- 本页所有指令锚点基于 b79 测试镜像（与 official 的差异区不在本链上）；结论基于
  main 52b5622，BX/BY 合并后按新 main 复核锚点。
