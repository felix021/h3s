后续已补入[外设信息与受限模型](hardware-contracts.md)：可选场景中真实PLL完成返回、连续启动推进到GPIO初态。本文原9组严格／隔离回归仍保持，默认不启用新外设模型。

2026-11-10，使用[实机双读得到的128 KiB ROM窗口](rom-read.md)，按精确摘要接入启动探针的只读取指和数据映射。本轮完全在本机离线完成，没有连接设备、写Flash或产生新固件。

结果：**冷PLL路径执行到了真实ROM，停在首次PLL控制写；隔离的`mask_init`在明确REP假设下完成返回。** 整机启动、外设时序和中断交付仍未实现。工具：[probe_rom.py](../tools/probe_rom.py)，脱敏结果：[rom-execution.json](../evidence/rom-execution.json)。

## 九组用例

| 用例 | 模型步数 | 结果 |
| --- | ---: | --- |

| 隔离调用`_pll_init` | 3 | 同一PLL0.CON4写入边界 |
| 隔离`mask_init`，严格REP | 15 | 在ROM `memset`的`0x4242`停止，尚未清理上下文 |
| 同上，允许非零倒计数 | 33 | 清零60B，停在`0x424c`的零计数尾循环 |
| 同上，额外假设零计数跳过 | 40 | 返回，60B区域符合预期；指针、边界标记、栈和R4～R15均核对通过 |
| ROM `memset`，对齐目标／61B／填充0xa5 | 29 | 返回，摘要正确；只使用非零循环假设 |
| ROM `memset`，对齐目标／63B／填充0xa5 | 31 | 返回，摘要正确；只使用非零循环假设 |
| ROM `memset`，目标地址0 | 9 | 在`0x4244`首次写入时拒绝，ROM保持只读 |
| 应用入口，PLL就绪及既有启动假设 | 17248 | 仍停在应用`0x060664c4`的`0xf2c11c`控制写，尚未调用ROM |

“步数”是探针的模型step，不是CPU周期或实机计数；并行指令、REP控制器和诊断适配都有明确边界。隔离函数的返回目的地是模拟器哨兵`0x01c70000`，到达即停止，不把它当真实代码。所有合成参数和寄存器值都不是设备现场快照。

## `mask_init`的实际契约

导出`0x1fde8`跳到`0x4590`，函数体到`0x45bc`之前，共44B／12条解码指令。唯一直接调用是`0x45a4 → 0x4226`，即真实ROM `memset`实现。根据指令和隔离执行，逻辑可写成以下分析伪代码：

```c
void mask_init(void *arg0, void *arg1) {
    memset((void *)0x19fd68, 0, 60);
    *(uint32_t *)0x19fd7c = (uint32_t)arg1;
    *(uint32_t *)0x19fd80 = (uint32_t)arg0;
}
```

本函数没有直接访问MMIO，也没有在这段代码中建立完整中断／RTOS环境。不能因名字叫`mask_init`就把它解释为“整个ROM硬件初始化”。QCY调用点的参数是`NULL, log_putbyte`，后者地址`0x06000b10`；这里仅保存指针，并不调用它。

测试把上下文初始内容保留为未知，只在前后各4B放置合成标记。非零倒计数场景确实通过ROM指令写满60B，全零SHA256为`5dcc1b5872dd9ff1c234501f1fefda01f664164e1583c3e1bb3dbea47588ab31`。允许零计数跳过后，保存回调和NULL，最终60B SHA256为`ea9e019585ef384ad5ac3cf20c850a89421f368ff8ac290cee544ab7d2ae6ceb`。独立主机预期只负责核对结果，没有代替ROM函数执行。

`memset`先按字清理，再执行字节尾循环。60B意味着15个word、0个尾字节，因此这里再次遇到BR28尚未实测的零计数REP语义。代码结构支持“零时跳过”的解释，**这仍是代码推断，不是硬件测量**。严格用例保留停止；显式假设用例单列。

另选61B和63B，使word次数及尾字节次数均非零，避免依赖零计数跳过。实际ROM输出逐区域摘要等于主机填充，返回指针正确，栈与检查的寄存器恢复，左右标记未变，64B缓冲区里未请求的尾部仍未知。非零大计数仍沿用既有倒计数研究模型，不能当成BR28硬件语义已经认证；这些对齐案例也不代表验证了所有`memset`路径，未对齐／条件块／异常仍有缺口。

## `_pll_init`揭示的硬件依赖

导出`0x1fe14 → 0xc2ce`，函数体结束于`0xc368`之前，共154B／44条解码指令。冷路径中执行了ROM导出跳转、保存返回地址和加载PLL基址，下一条真实指令是：

```text
0xc2d6: PLL0.CON4 (0xfd4610) = 0
```

模型在应用写入前停止。参考SDK的`br28.h`将`0xfd4600`定义为`JL_PLL0`，依次包含CON0～CON4；该文件精确摘要已记录于[data/dependencies.json](../data/dependencies.json)。这比此前“ROM入口无法取指”更具体，但尚未执行后续时钟配置。

以下来自有界静态解码，**不是后续指令已经动态执行的结果**：

- 访问PLL0.CON0～CON4，读取ROM全局`boot_arg_list + 4`（`0x19fc2c`）。前面的QCY冷路径向这里写入24MHz，ROM据此计算`(value / 2000000 - 2) | 0x800`并写CON1；该输入下结果为`0x80a`。最后向`boot_arg_list + 8`写48000000。
- CON2写`0x5e`，CON3先写`0x11f`再置`0x200`；CON0先写`0x40892d90`，随后设置bits0、1。这些常量不能替代寄存器副作用模型。
- 两次调用`0xa2fa`辅助函数，传入10与160。该函数使用`JL_TIMER0`（`0xfd0400`），设置CON／CNT／PRD，轮询CON的bit15。它需要定时器进展；给MMIO套一个普通字典不会自然产生完成事件。
- 配置`0xfd0018/1c/20`，参考布局对应`JL_CLOCK.CLK_CON0/1/2`；两次调用`0xc2b8`的CPU倒计数辅助函数，并含两条`csync`。时钟选择、同步和实际时间都未建模。

因此下一阶段不仅要允许寄存器存取，还要明确PLL／时钟和Timer0完成条件。当前没有用“永远就绪”的读值或延时空函数绕过这些依赖。

## 模型改动与保持的边界

`probe_boot.explore(..., rom=...)`现在接受可选私有ROM，必须匹配`131072B`及SHA256 `7cae0a02e3ab3755c1e392f03c89222dd701065ec9bd3ec8ac109a7b3f40f793`。只映射该地址窗口，禁止写入；未知RAM保持未知，外部寄存器依旧拒绝。原来的探针默认不提供ROM，历史报告和停止位置保持可复现。

另核对窗口末尾的4B导出`0x1fffc → 0x10fb8`：只执行跳转一步，不执行后续函数。上游解码器默认取6B，本地在ROM末尾改为仅解码已取得的剩余字节，既能执行完整的4B指令，也不跨窗口读取或补零。结果列在JSON的`rom_tail_fetch_check`。

新诊断适配仅在明确映射精确ROM并选择对应选项时生效：

- `memset`两个固定REP位置：可选非零倒计数、另外可选零计数跳过。不是给所有REP或ROM开通用模拟。
- `0x4244/424e`的word／byte后增存储、`0x45b0/45b8`的指针存储按真实宽度写入，避免上游模型为合并旧word而读取未初始化内容；条件块中不会直接套用该适配。
- `0xc2d6`按真实完整word存储报告PLL写入，随后由未知MMIO门槛拒绝；不把上游存储模型的旧值读取误称为架构load。
- 隔离用例显式提供全部GPR、SP和返回哨兵。未模拟复位入口、SSP银行、IRQ、双核、真实交接初值或硬件时间。

正常PLL路径仍在`0xf2c11c`停止，是因为该控制写发生在调用`mask_init`之前。隔离执行成功没有给连续路径豁免。现有严格零REP／ICFG／IPMASK停止也都保留，本轮不能用来批准刷机。

## 本机复现

需要Python3.11、固定社区模拟器及官方UFW，另外由操作者显式提供私有ROM。工具不会获取ROM、连接设备或要求把ROM放入仓库。

```bash
python3 tools/probe_rom.py \
  --rom /private/path/rom-000000-020000.pass1.bin \
  --report analysis/rom-execution/results.json

# 包括原主机检查、四组旧探针和本轮九组真实ROM用例：
python3 tools/check_local.py \
  --rom /private/path/rom-000000-020000.pass1.bin
```

没有私有ROM的公开复现仍用`python3 tools/check_local.py`；不会自动下载ROM或把它伪造为零。公开JSON只含摘要、合成状态和少量解码文本，不含原始ROM二进制、私有文件路径或完整RAM／代码写入镜像。检查在本机执行，没有运行GitHub CI。
