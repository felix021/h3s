### 1.1 get-event 内部（buf 写面钉死——本路新钉）

0x6064c8c(buf, N) 的返回 13 路径：循环取当前任务 taskq 记录（0x6064b98）→
**0x60649b0 解包**（BZ/S18 先例互证，本路逐指令复核）：

```
r0 = [queue+8 游标处 slot 头字]
n = 头字低 8 位 - 1                        ; 载荷字数
buf[0] = 头字 >> 8                          ; = id（0x6064d72 族恒 0x100000）
buf[1..n] = 载荷字 i（拷贝上限 N-1=7 字）
```

**buf 写字数 = 消息载荷字数 n，与 buf 容量无关**。n=1 时 buf[1] 写、**buf[2]
（=0x18ca64=[r10+8]）从不写**。0x300000 族回调消息（如 0x60752c4 post 的 3 字）
不返 13——在 0x6064c0e 内联消费后续取（SIMPRE P3 先例），不进 buf 检查。

停点形状收敛（codex 复核修正）：0x60869b6 已过（buf[1] 字节已知）而 0x60869ba
停（buf[2] 缺）→ 载荷 **n=1**（普通 {0} post）。两点诚实收窄：①「buf[1] 已知」
只证明字节已知，不证明刚被本次解包写入（首轮循环≠该物理栈无历史写）——
**n=0（零载荷消息）结构上也可能**（0x6064a00 有符号 0<0 不成立、0x606487c
入队路径无 n>0 检查，codex 逐指令复核）；② get-event 返 13 无绕过解包的路径
（13 唯一装点 0x6064d4a，必经 0x6064b98→0x60649b0）。**最短补证**（开启臂
watch 项）：记录本次 dequeue 的 slot 头字/游标/解包写集/0x60869b6 后 r0——
若为普通 {0} post，预期头字=0x10000002、id=0x100000、n=1、buf[1]=0。

r6 装载后的活区间 = **[0x60869ba, 0x6086b0c)**（cmd0 丢弃路径）。两级复核
（本路区间指令 + codex 被调链补核）：

同步路径指令逐条（codex 复核含原始字节）：

| PC | 字节 | 指令 | 含 r6？ |
|---|---|---|---|
| 0x60869b6 | d0 ec a4 00 | r0 = [r10+4]（独立 ld.w.l） | 否 |
| 0x60869ba | d0 ec a8 60 | r6 = [r10+8]（独立 ld.w.l，**flags 不变**） | 装载点 |
| 0x60869be | 31 e1 fc 0f | r1 = r0-4 | 否（r0=cmd） |

  **之后**才执行，cmd0 路径不经过；tbb 索引是 r1（来自已初始化 cmd）。ld.w.l

- **无并行指令对**：实际经过的 69b6/69ba/69be/69c2/6b06/6b0c 均无 `.p` 后缀，
  0x60869ba 不是前一条并行指令的后半（codex 逐字节复核；`#` 并行对只在
  cmd10/cmd8 分支体 0x6086ace/0x6086af0 的 mov.rr.p，cmd0 不执行）。
- **被调链补核（codex）**：0x6075ce0 全函数（0x6075ce0..0x6075d0e）只用
  r0/r1/r2/SP/RETS，两次调用 0x12b55c/0x12b5b0；0x12b55c..0x12b5ae 只用
  r0..r3；0x12b5b0..0x12b608 只用 r0..r4（保存恢复 r4）。同步链不读写 r6、
  无继续调用。注意措辞：该区间**helper 自身有内存访问与分支**（不是「零内存
  访问/零分支」），只是全部不依赖 r6。
- **0x6075ce0 语义修正（codex）**：该短函数=「遍历保护/引用计数增加」
  （全局 b[0x12649c]++、链表各对象 b[obj+9]++；对应 0x6075d54 减计数/零值

- cmd∈[4,12] 的后续 2 字载荷消息（{5,obj} 等）：r6=已初始化堆指针 obj，
  0x60869c6/c8 与 tbb 分支正常消费——**与本停点（cmd0）无交叉**。
- 结论：**在已知 cmd0、同步路径上，[r10+8] 读值不参与谓词/地址/算术/控制
  目标，最终被 r12 覆盖**。IRQ/任务切换若在活区间介入，寄存器保存恢复仅
  传播 unknown（codex 验证臂 7 的覆盖项，静态不预承诺）。

### 3.1 等价性措辞（codex 限域，替代「控制流与 silicon 等价」的过强表述）

> 在该固件字节、同一已知 cmd0、有效任务栈映射及当前已声明的架构假设下，
> 真实装载所得任意 32 位值都不影响上述同步路径的分支、地址和已知状态结果，
> 且在 0x6086b0c 被覆盖。保留未知值的模型对这个局部片段保留了所有可能值的
> 共同控制流；该结论来自反汇编，未通过本设备测量。

「残留值」不必然随机（可能是复位值或先前写入——模型未写≠设备从未写）；
不可由此片段推出 silicon 已到达同状态。可比项=PC/已知寄存器/外部可见写入/
unknown 来源与运输关系；禁止把「全部寄存器逐值相等」当未限定的等价结论。

## 4. 下一停点预判（按 (a) 放行；codex 排序为本路采纳口径）

**侦察优先级排序，非实测停点/概率估计**——没有链表字段/队列次序/就绪态/
timer 状态的运行数据，无法承诺「+1-5 万步」落在精确 PC。

1. **jlstream walker 的对象 RAM / 间接节点操作边界**（最邻近真实新消费面）：

2. **回 pend 后的兄弟任务边界 / 无新边界进入事件钟**：walker 收尾

3. **已有节点的数据回调 → decoder / 尚未覆盖的音频运行域**：状态 3 真实入口
