## 0. 一句话结论（六问六答）

1. **事件源链**：0x60207a2 = app_core 事件 0x100009 的 handler（注册记录
   {module=0xff, event=0x100009, handler=0x60207a2} @0x60a8b9c，泵第二 walk 区
   [0x60A89E0,0x60A8C68) 内第 37 条——BTMAP §7 旧称「表1[37]」，§8.1 勘误后两 walk 的
   命名以区间为准），形态=对 8 字节参数缓冲首字节的三张 tbh 子分发（0..30/82..93/
   129..160，另有 176 特判）。**0x6021002 在子事件 83 的 case 体 0x6020f52..0x60210fa+
   共享出口 0x60212ba 内**——83 在 **82..93 表**（@0x6020896，83→0x6020F52），**不在
   129..160 表**（对 D2AJ INJ-03「tbh 跳表 129..160」记录的勘误：该表述沿自本路任务书，
   面板原文应读作「tbh 三表子分发」）。0x100009 全 app 唯一 poster=0x601b944(sub,param)
   →post('app_core')；其唯一调用者=0x601be6e（{144,code} 消息分发器）的转发尾；0x601be6e
   唯一被调路径=回调数组 {0x601be6e,0x60222b2} @0x60a89d8..0x60a89e0，由 walker
   0x603573e 遍历，walker 挂 RAM vtable 槽 [0x124C80+280]、**静态零调用者**（闭源传输库
   函数指针调用）。传输物理面=**3 个硬件 UART**（JL_UART0/1/2=0xfd2000/2100/2200，IRQ
   12/13/14，handler 0x60355e0/f2/04，RX DMA 环 0x125BFC/544B，0x55/0xAA 帧）——**通话态
   事件不在 BT 栈任务里，在 UART 事件总线上**（§1）。
2. **协议墙**：**通话态未被 BT 协议墙结构性锁死**。BTMAP 的墙（IRQ78/79 无源→HCI 永无源）
   锁死的是 BT 空口/profile；而 aec 创建链的消费端整条在 UART 事件总线（IRQ12/13/14）+
   app_core 队列上，与 btstack/btctrler 任务零静态耦合。{144,code} 帧的**最初生产者静态
   不可见**（闭源传输/BT 域；本机 HFP 栈生成 vs 外部对端发来，静态无法区分 [推断]）——但
   注入只需要帧字节进 0x603573e/0x601be6e，不需要 HCI/ACL/SCO 建立（§2）。
3. **注入层级**：三级评估+codex 参谋（§3）。**推荐=方案 (b)「传输 API 层直调 0x603573e
   （vtable 槽等价直调）+ 真实 app_core 泵消费」**，合成输入=3 字节帧 {144,83,chmap}（与
   按键 RES 档位/音频样本字节同深度）；(a) UART 物理层（RX DMA 预填+IRQ12 真交付+闭源
   0x55/0xAA 解析器全真跑）列为正式验收升级路径/D3 专项；(c-ii) 直调 0x60207a2 只做定位
   辅助。codex 结论=正式验收选 (a)、诊断用 (b)——本路采纳其诊断先行+全部风险清单，
   对「(a) 为 b3 验收必要条件」给反驳（b3 断言对象是应用侧 aec 簿记消费闭环，非物理
   UART 输入验证；照 BTMAP (b) 先例收窄，§3.4）。
4. **最小通话场景**：**单个事件帧即足**——{b0=144, b1=83, b2=chmap}（chmap≠0），无需
   82/85 等前置通话事件、**无需 SCO 无线链路**（整链不触 BT/modem 面）。链序（§1.2/§1.4
   勘误后）：分发器 case 83 写 b[QCY+8087]=chmap+h[QCY+2616]=50→**只 post**（无 relay）→
   泵→handler case 83：读回 chmap→**共享出口 0x60212ba 链式调 0x60200b6(chmap)**（esco
   数据面开链，chmap 兼作 flags）→**返回 0 则对象存活、非零则 0x601ca3e 拆除对象**
   （D2AI 勘误 5 已钉开链成功返 0；b1 直调 0x60200b6(0x5) 已证 park 世界返 0）。即**簿记
   门与数据面门是链式不是并列**。唯一硬门=chmap≠0（r5==0 → 跳过创建但仍调
   0x60200b6(0)）。负例=chmap=0（事件照达、创建被真门拦、[QCY+624] 保持 0）。chmap 首选
   **0x05**（兼作 esco flags=b1 已证取值；节点数 2），备选 0x0B（对齐 blob en_map；节点
   数 3）；位映射语义 [未钉]。注意 bit0x20 **清零**才触发 0x601d8a6(1,1)（UART CON 位
   写，已有容器）——0x05/0x0B 都会走该支路，计入 PC 覆盖而非避开（§4）。
5. **依赖面**：0x60207a2 跑在 **app_core 任务上下文**（泵 0x60123C0 第二 walk）——park 世界
   泵已活（D1 验收域），**S19 消息循环不是新前置**（WDFEED 在途项不阻塞本注入：注入发生
   在 post-park 的 world_prep/直调层）。真正的前置是**队列消费机制**：0x601b944 的 post
   入队后，泵要跑到 handler 需 (i) M1-c 全环真调度 resume（EQPIPE 记录的正路，GPCNUM 已
   放行、世界待重钉）或 (ii) post_stop 再直调 0x60207a2(参数缓冲)（跳过队列语义，定位用
   弱化）。另有两处运行风险：0x601b85c UART 发送支路在 **handler 侧 0x6020fbe、出队之后
   创建之前**（TX 等待环读侧未全钉，卡死症状=「chmap 已写、事件已消费、handler 停在
   0x6020fbe、对象未建」）；与 0x601be6e 返回值=1→第二回调 0x60222b2 被自然跳过（§1.4，
   非缺陷）。
6. **codex 参谋**：已跑（三选一+风险+验收框架，§3.3）；采纳=诊断先行/walker 入口优先/
   chmap=0 对照/因果链断言框架/九条补充风险；反驳=(a) 作为 b3 解锁必要条件（ROI 论证）。

## 1. 事件源链（预研问题 1）

### 1.1 0x60207a2 是什么（OS 事件分发形态）[静态·本路]

注册与形态：**app_core 事件泵（0x60123C0）第二静态 walk [0x60A89E0,0x60A8C68) 的记录
{module=0xff, event=0x100009, handler=0x60207a2} @0x60a8b9c**（12B 记录三元组，module=0xff
=任意模块；BX 路已知此表，本路补该记录的事件号与 handler 对应）。泵消费顺序
（BTMAP §8.1）：pend 16 字 → 0x10000C 模块分派 → 表1 walk → 模块钩子 → 第二 walk。
0x60207a2 收到的 r0=参数缓冲指针（不含事件号字），**b[buf+0]=子事件号**驱动三张 tbh
子分发：

| 子事件范围 | 入口判断 | tbh 表基 | 表长 | 备注 |
|---|---|---|---|---|
| 0..30 | `if (r0 <= 30) goto 104`→0x602082a | **0x602082e** | 31 | 与 129 共享 case 0/129→0x602086C |
| 129..160 | `r2=r0-129; if (r2>31) goto 出界` | **0x60207da** | 32 | 133/136/147..159→默认 0x602125e |
| 82..93 | 出界后 `r1=r0-82; if (r1>11) goto 0x60208c8` | **0x6020896** | 12 | **83→0x6020F52（aec 创建体）** |
| 176 | 0x60208c8 `if (r0 != 176) goto 默认` | — | 1 | 0x60208ce 起，指针型参数 |

tbh 语义=表紧跟指令、目标=表基+2×半字值（`tools/analyze_eq_toggle.py:74` 的既有解码
先例，本路三表全量复算）。入口三个前置调用（0x6008298=按 40B 步进扫描 0x12867A 表数
活跃 link、非零则跳过 0x6001ef6/0x60107a8 两个计时簿记）均为副作用，不构成分发门
[静态·本路]。

### 1.4 再上游：0x601be6e（{144,code} 消息分发器）与 UART 事件总线 [静态·本路]

## 2. BT 面现状与协议墙判断（预研问题 2）

BTMAP 的墙（§3 四墙）复核：到达墙（D1 域，无 BT）维持；注入墙（app 队列事件）——本路
证实 0x100009 即此族；任务首跑墙（modem 窗口 1636B 快照读）与协议墙（IRQ78/79 无源→
0x400000x 源永缺→可连接不可达）**只锁 BT 空口/profile 域**。

**通话态是否被协议墙锁死？——否，理由三条**：

1. **结构证据**：aec 创建链（0x603573e→0x601be6e→0x601b944→泵→0x60207a2→0x6021002）
   的每一环都在 UART 事件总线+app_core 队列+RAM 对象上，零 BT 栈任务参与；触达的硬件
   =JL_UART0/1/2（IRQ12/13/14）+三处 GPIO RMW（0xfd5200/0xfd5208、0xfd5100 经
   0x601b960）——**均不在** modem 窗/IRQ78/79/82/76/41 的 BT 面内。
2. **注入边界同构先例**：按键 RES 分压字节（ADC/GPADC 域）、音频样本字节（DMA 域）之后，
   UART 帧字节是第三个「物理输入字节」级边界；0x55/0xAA 帧格式可从构建器 0x6060254
   反推（未钉，§7），RX 解析器是 app.bin 内真码（闭源但可执行）。
3. **反向确认 [推断]**：若链被锁死，真机 aec 也无法建立；真机通话降噪若生效，则
   [QCY+624] 唯一写点链在真机是活的（真机行为静态不可证，条件式表述）。锁死的只是
   「从 BT 空口自然长出通话态」这条**生成路径**，不是「通话态事件的消费路径」。

**如实收窄**：解锁 b3 ≠ 解锁 BT。SCO 音频链路（真 mic 数据经 esco 编码发出去）仍需要
BT 空口（协议墙内）；b3 需要的只是「通话态事件被应用层消费」——即 aec 前端簿记对象的
建立，它独立于空口。这与 BTMAP §4 的方案 (b)（事件注入+读回投影，D2 断言应用行为非
空口协议正确性）同一裁决线。
