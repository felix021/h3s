# 有线/游戏模式固件面：USB Audio 与效果场景切换钉死（路 AT / sim-wiredgame）

2026-11-14。d1-acceptance §6.4 范围表最后两块未实证域（有线模式、游戏模式）的固件面
调研。**只读静态反汇编**：未改 tools/ 任何代码、未跑 probe、未连真机。证据源=官方原
app.bin（SHA256 `18f3d573…`，线性反汇编基址 0x06000100，call 目标公式
`pc+指令长+带符号位移`，与 key-action-map 同族校准）+ 公开工件 stream.bin/config.dat
镜像字节 + 既有 docs/HANDOFF 条目。全部结论 **derived-not-measured**。

证据强度：**[静态]** = 本路反汇编/镜像字节钉死；**[文档]** = 既有 docs/HANDOFF 钉死；
**[推断]** = 上述链推出；**[未定位]** = 如实标注。

## 0. 一句话结论

- **有线 = USB Audio（USB 声卡），不是 3.5mm AUX**：产品自己的 stream.bin 里有六条
  管线，其中 `pipeline-PCAudio`（描述串就是 "USB Audio"）与 `pipeline-a2dp` 并列；
  app.bin 有完整 usb_stack 任务 + USB 设备驱动 + pcspk/pc_mic 音频节点；3.5mm linein
  在产品代码里**零引用**（只剩 SDK 通用提示音表/音量名表里的孤儿字符串）。有线插入
  **涉及固件输入源切换**（整条第二管线+独立音量节点）。
- **游戏模式 = 音频模式状态机的取值 3**：入口是 App cmdid 46（面板 subItem index 3）
  或按键 cmd 7（循环 1↔3）；配置变化=**效果 ctx 挂起/延迟重建/回调恢复 + EQ 预设
  （"MusicEqBt" idx 1/2/3）+ 场景字节 + 两个标志位**，全程不动编解码参数/SBC-AAC
  选择/缓冲长度/时钟——「低延迟」由 DSP 效果图切换（stream.bin 场景名 `gam_eff`）实现，
  端到端延迟降低本身维持 §6.4「放 D3」既有裁定。

## 1. 有线模式：USB Audio 证据链

### 1.1 stream.bin 管线全表 [静态：镜像字节]

stream.bin（公开工件）0x1e4a..0x1f5f 管线记录（`pipeline-<名>##<描述>`，UTF-8 中文）：

| 管线 | 描述串 | 定位 |
|---|---|---|
| pipeline-tone | 系统模式/单独播提示音 | 0x1e4a |
| pipeline-a2dp | 蓝牙音乐 | 0x1e90 |
| pipeline-CVP | 蓝牙通话 | 0x1ec3 |
| **pipeline-PCAudio** | **USB Audio**（默认分组） | 0x1ef5 |
| pipeline-a2dp_dut | 产测模式 | 0x1f28 |
| pipeline-mic_effect | 辅听 | 0x1f5f |

**没有 linein/AUX 管线**。配套节点实例名（stream.bin 0x3ad..0x6e0 名字表）：`pcspk`
（0x416、0x68c 两处）、`Vol_PcspkMusic`、`pc_mic`（app.bin 节点描述符表 0x60a8e4c，
24B 记录式）、`DAC1/2/3/6`、`MusicEqBt`、`Vol_BtdMusic/Vol_BtmMusic/Vol_BtcCall`、
`MicEff/DacEff` 等。`Vol_LinMusic`（0x494）也在这张 SDK 名字表里，但全 bin 无任何
linein 管线/节点引用它（见 §1.4）。

### 1.2 usb_stack 任务与 USB 设备驱动 [静态]

- **任务**：`usb_stack`（名串 0x60a1d38）任务体 **0x6035840**（os_task_create 实参
  0x6035840 @0x6007028），栈深配置取 b[QCY+1870]，句柄存 [QCY+752]（0x126498）。
  创建门=**b[QCY+1864]（0x1268D8）!= 0**（0x600701e）；bit0 清零时直接
  `b[QCY+3024]=7`（USB 模式字节=7=禁用）且不建任务（0x6006fec..0x600703a）。
- **使能配置的来源**：0x1249C0 起 128B 先整块填 0xFF（0x6034efc，rep 2 16），再由
  0x6011412 一带的名字键控 syscfg 读取族按 flash 表覆盖（调用点 0x6034f12/0x6034f1a，
  表基 0x60a1b08 区）；USB 子配置=其中 0x1249F4 起 **12B**，由 0x600741c 交给
  0x6006fce 复制进 QCY+1864..1875。**上电默认 0xFF=使能，产品是否用 config 覆盖关掉
  属运行时值 [未定位]**（config.dat 里只有 ver_info/reset_io/power_io 等少数 IO 项，
  无 USB 使能项）。
- **驱动面**：JL_USB（br28.h `ls_base+map_adr(0x18,0)` = **0xfd1800**）全 app 共 23 处
  基址引用：0x600471a..0x6007438 十一处（USB 设备驱动主体）、0x60357b4..0x6035878
  （usb_stack 任务）、0x601b318、0x6068a7c、0x60c67f6/0x60c8448+（RAM 库）。
  usb_stack 轮询 **CON0 & 0x820**（0x6035804，线态/插入检测位族）与 **& 1**
  （0x6035878，设备模式位），按 b[QCY+3024]（0x126D60）低 4 位 tbh 分派模式 0..6
  （7=禁用），带重试计数（b[QCY+3040]）与 50 单位退避（0x6035a02 一带）。
- **插入事件源**：0x6000c8a 向 `usb_stack` 投递（os 层名 'usb_stack'，q 基 0x127198，
  事件号 129/130/131：上电初始化 129 @0x6017f62、插拔 130/131 @0x601805a）。调用方
  0x6017f42 挂在电源/充电初始化尾段（0x6017fe0 族一次性投递）。
- **DP 脚复用 UART0（既有事实，路 S/V 域）[文档]**：正常 boot 主路径把 FI_UART0_RX
  写为 0x2f=USBDP_IN（0x6001342 写 0xfd5c90），即 USB D+ 脚平时当调试/AT 串口
  （'AT+getcolour'/'dut mode' 串族在 app.bin）。SDK 惯例是 USB 插入后由 usb_stack
  接管脚位、关调试串口——**接管动作的具体代码 [未定位]**，D2 真要跑必须先把这步钉死。
- **提示音**：tone 表（zh 0x60A379C/en 0x60A387C 两变体，选择字 [QCY+348]，取数器
  0x600c2aa）里 id 19='linein.*'、id 20='pc.*'（en 表 id 75/76 对应）。

### 1.3 有线插入时固件做什么（裁决面）

- **输入源切换成立**：`pipeline-PCAudio` 是与 a2dp 并列的完整第二音频管线（独立
  DAC/merge/音量节点 `Vol_PcspkMusic`、上行 `pc_mic`），usb_stack 枚举成功后按模式
  tbh 分派启停——这就是「实际插拔输入→事件→路由切换」的固件侧实体。BT 侧让位/
  暂停的具体策略代码 [未定位]（属 D2 跑通时的观察项，不影响裁决）。
- **USB audio class 代码**：驱动主体 0x6004..0x6007 十一处 SFR 引用 + 'pc_spk'
  （0x6005c60 处 r0=11 类号的名字注册 0x60057e6）+ pc_mic 节点 ioctl（0x60339c4）
  ——uac 上下行都在。USB 描述符串（Vendor/Product 文本）未在 app.bin 出现
  [未定位]（可能在 RAM 库或按二进制表存，不影响能力判定）。

### 1.4 3.5mm linein 无产品化证据 [静态]

- 'linein' 名串 0x60a1ab4：全 bin（含非对齐扫描）**唯一近邻引用是 0x60217da→
  0x60a1abb**——指向 '123456' 串中段，是指令字节巧合，非指针；产品代码零引用。
- 'linein.*' 提示音只存在于 SDK 通用 tone 表；`linein_off_poweroff`（0x60a2383）
  同样零引用（cfg_tool 协议族孤儿串）；stream.bin 无 linein 管线。
- 对照组：Vol_* 音量名表（Vol_LinMusic/Vol_USBMusic/Vol_PcMic…，0x609d10x 一带）与
  tone 表是 SDK 通用资产，其中 USB 侧的名字（pcspk/Vol_PcspkMusic）在产品管线里
  真被用上，linein 侧没有——**字符串在场≠功能在场**，判定以管线/引用为准。

### 1.5 有线模式范围裁决

**形态**：USB-C 声卡模式（PCAudio）。**涉及固件输入源切换：是**（第二管线+独立音量
域+usb_stack 模式机），按 §6.4 准入规则（新增数据布局+资源生命周期）**满足进 D2 的
准入条件**；但 D2 侧需要 USB 设备控制器（0xfd1800 SFR 族、端点 FIFO）+ 主机枚举
（SETUP/描述符/IN-OUT 事务）+ DP/DM 线态建模，当前模型只有恢复模式的 ROM loader
USB 面，**普通模式 USB 设备栈未建模**——列为 **D2 扩展用例（预期 BLOCKED：模型缺
USB 设备面）**，等价于把「插拔→路由切换→旧流收尾→返回」的断言框架先冻结、实现
排到 USB 外设模型之后。不升必选（本轮未承诺该能力）。

## 2. 游戏模式：配置变化链全图

### 2.1 状态机与入口 [静态]（key-action-map §4.1 的入口面在此补 App 命令注册表）

- **音频模式字节 0x124a04**（config key 22 的 1B 镜像），取值族 {1=音乐, 3=游戏,
  4=电影}——面板 cmdid 46 subItem index {1,3,4} 与固件循环表（0x60a18c0+18 三字节
  {1,3,4}）两端互证（[文档]+[静态]）。
- **App 命令注册表**（0x60a9b78 起 28B/条，{w0, getter+4, setter+8, ·, ·, cb+20,
  cmdid+24}；EQ cmd 0x22 getter 0x602580a/setter 0x602583c 与 ANC cmd 0x17
  getter 0x6025c84/setter 0x6025ca4 两个既有锚点校准栅格一致）：
  - **cmd 46 (0x2E) 模式切换**＝{w0 0x60260f0, getter 0x6026120（读 b[0x124a04]）,
    setter **0x6026134**, cb 0x6026176}。setter：`b[0x124a04]=载荷字节` → 500 单位
    延迟工作项 → **0x60261de**（cb 实参 100819422=0x60261de @0x602615e）：
    `0x60251fc(b[0x124a04], 1)` + 清 [0x125F80] 句柄。w0 0x60260f0=开机同步：
    get_config(22)→缺省置 1→`0x60251fc(模式, 0)`→BLE 回执 46。
  - cmd 16 (0x10)＝另一字节 b[QCY+38]（0x1261C6）的读写组（w0/cb 把它置 2，setter
    0x6026234 写载荷）；0x60261fa 侧另有「模式字节==3 → b[QCY+38]=2」联动。该字节
    在按键 handler 0x60252f4 处当门（==1 时提前返回已处理）。**语义（面板哪个开关）
    [未定位]**，与游戏模式主链无控制流耦合。
- **按键入口**：cmd 7（多功能键双击默认）→ 0x6025404：发布动作名（0x6018bf4，游戏
  进/出的名字是 'InLowLatency'/'OutLowLatency'，见 §2.4）→ get_config(22) → 循环
  {1,3,4}（当前 1 或 4 → 3；当前 3 → 1）→ `0x60251fc(下一模式, 1)`。
- **应用器 0x60251fc(模式, flag)**（key-action-map §4.1 已钉，本路复核一致）：前置门
  `0x601662a()&4 且 b[0x125F7E]==0 → 返回`；模式>4 返回；写 b[0x124a04]；按模式
  分派（下节）；尾部 `set_config(22, 0x124a04, 1)` 持久化。flag=0「立即装预设」/
  flag=1「先放提示音、音完再装」两种时序（§2.3）。

### 2.2 配置变化三件套（「开关→真实配置变化」的实体）[静态]

进入/退出模式 3（游戏）时，应用器依次做三件事（退出对称反做）：

1. **低延迟标志对**：`0x600efd0(1|0, 0)`（游戏开/关）写 **b[QCY+27]（0x1261BB，
   InLowLatency 活动）与 b[QCY+45]（0x1261CB，镜像）**（0x600eff2/0x600eff6）；
   开启侧再经 0x6008298 活动查询门调 0x600ee9a(0)。标志读取者：
   ①活动查询 0x601a81c（b[QCY+27]，被应用器/恢复回调/BLE 命令簇 0x60232xx/0x60237xx
   调用）；②**效果节点装配路径 0x6031c82（读 b[QCY+45]）**，位于大函数 0x60319d6
   （0x124C20 音频框架对象族，jlstream 节点协商/装配域）——低延迟状态影响流节点
   setup 的分支在此，**具体改哪些节点参数 [未定位]**。
2. **场景字节 [0x124A10] + 延迟场景切换**：`0x6024f02(0|1)`（游戏/电影→0，音乐→1；
   双活动门 b[QCY+33]!=0 && 0x6005700()!=0）→ `0x6024e6a(场景)`：场景 0 立即落
   [0x124A10] 并挂 300 单位定时器 → **0x602f576**（清定时器句柄→`0x6013cd4(0,
   "MusicEqBt")`，经 0x60057e6 类号 15 的名字注册表 + 0x6074938 stream.bin 名表查找
   的效果装配族）；场景≠0 挂 500 单位定时器 → **0x602f592 → 0x6024e6a(场景)**
   （与 [0x124A10] 比较的收敛循环，落点由装配侧回写 [未定位]）。
   stream.bin 侧的场景名表（0x1df2 起，len 前缀串）：**`default`、`spatial_on`、
   `gam_eff`、`movie`**（另 arg0/arg1/wide_band/narrow_band 参数名）——模式字节到
   场景名的精确映射 [未定位]（框架内部按 id 查表），但「游戏模式=效果场景表切换」
   的载体钉死。
3. **EQ 预设族 "MusicEqBt"**：`0x6024fe6("MusicEqBt", idx)`，idx 映射 {音乐 1, 游戏
   2, 电影 3}（应用器 flag==0 路径与恢复回调两处一致）——经 0x60750aa stream.bin
   名字表取 EQ 节点配置记录，从 VM config 族读预设曲线，成功后 b[QCY+43]=idx、
   b[QCY+42]=2（0x602502c/30）；应用例程 **0x6025118**（eq-toggle 已钉的 EQ 参数
   应用链）。

### 2.3 挂起-重建-恢复生命周期（与 §6.2「配置切换」的对照面）[静态]

flag!=0 路径不是直接重配，而是走**名字键控的效果 ctx 挂起队列**：

- `0x600dab6(键, 0x602619a)`：`0x600d95e(键)`（128 槽名字注册表查 ctx；键=提示音
  表槽内容——模式 1/3/4 分别取 tonetable[+104]/[+100]/[+220]，即 'music_mode.*'/
  'game_mode.*'/'movie_mode.*' 名串）→ **b[ctx+13]=1 挂起** → [ctx+120]=0、
  [ctx+124]=0x602619a（恢复回调）→ `0x600da64(ctx)` 把 ctx 挂进工作链表
  0x124A64（异步任务稍后重建效果链，完成后以 (0,10) 调回调）。
- **恢复回调 0x602619a(0,10)**（eq-toggle 的 0x0602619a(0,10) 在此展开）：读模式
  字节——4→`0x6024fe6("MusicEqBt",3)`；3→`(,…,2)`；1→活动查询后 `(,…,1)`+
  `0x6025118` 应用。即「提示音放完→按当前模式重装 EQ 预设」。
- 生命周期形状=**挂起标志→延迟重建→回调恢复**，与 ANC 域「停-重配-启」（0x606e9e8/
  0x606ebe0 直切）是**两种不同机制**：这里是播放侧效果图的异步重建+回调，ANC 是采集
  侧硬件块同步重配。b4 类断言（无旧帧误用/停止后不再消费）两者通用。

### 2.4 动作名与提示音 [静态]

- 动作名表（0x60a486a 起）：…'InLowLatency'（0x60a48c4）、'OutLowLatency'
  （0x60a48d6）…与 anc_on/off/trans 并列；watcher 对表 0x609dd88 行={0x601a852,
  0x601a878}：0x601a852 发布 'InLowLatency'（0x6018bf4）后查 b[QCY+27]，
  0x601a878 对 'OutLowLatency'（0x609ced3）。第一份 'InLowLatency' 串 0x60a2011
  被 0x601a858 引用（strcmp 面）。
- 提示音：模式切换提示音即上述 tonetable[+100/+104/+220] 的 'game_mode.*'/
  'music_mode.*'/'movie_mode.*'（zh/en 双语）。

### 2.5 游戏模式范围裁决

**满足准入的「真实配置变化」**：不只是标志位——效果 ctx 挂起/重建/回调恢复（新
资源生命周期类型，播放侧）+ EQ 预设重装 + 场景字节 + set_config(22) 持久化 + BLE
回执 46，链路全部静态钉死、注入面单一（一条 cmd 46 帧或直调 setter 0x6026134），
实现成本低。**建议进 D2**，定位=「播放侧效果管线重配」代表用例，复用 §6.2 配置
切换的断言框架（旧配置停止/新配置生效/无旧帧按新布局解释/停止后不再消费），不按
模式取值 1/3/4 重复跑（同链等价类，一个代表即可）。**不满足/不承诺的**：编解码
参数、SBC/AAC 切换、缓冲长度、时钟——全链（含传递 callee）零命中；「低延迟效果」
本身维持既有「放 D3/专项性能验收」裁定不变。
