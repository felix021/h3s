## 0. 一句话结论

回执方向是**三级队列**结构：cmd handler 把响应写进调用方 resp 缓冲 → 公共出口
**0x600b66e**（恳求回执）/ **0x6009f6a**（无恳求通知）组包 → **0x6009db0** 在 BT 缓冲池
里分配块、拼出 `FE DC BA…EF` wire 帧、挂上 **TX 队列 [pool+16..20]** 并发信号量
（0x606474a(pool+56)）→ **rcsp 任务 0x60097FE** 的排空半环取出节点、按连接匹配双传输面
（0x6009692 事件环 / 0x60075ce→0x6003b02 通道 129）→ 通道 129 帧组装成 TX 块挂
**[0x1265C0+7300]** 链并 post('btstack',255) → btstack 轮询器里的控制器库泵 0x6041612
摘链、经 0x6036e96→0x6003704 以事件 **0x400003** 交控制器引擎。**bridge 的最小读出点=
拦 0x600b66e/0x6009f6a 入口（载荷级，免解析 wire）**；最小注入点=直调
**0x600f85e(SN, body, 0, len)**（RCSP 自定义命令全家族）或既有 BW 先例的 0x10000C 事件
注入（按键/action 域）。状态旁路：EQ 曲线镜像 b[0x1265C0+5356..]、ANC 三字节
b[0x1265EB..ED]/b[0x12666B..D]、音频模式 0x124a04 等可直接 RAM 轮询。

## 1. 问一：回执帧的构造与发送口（handler 完成→帧构造→入队→发送，PC 级）

### 1.1 响应包装与公共出口 [静态·本路]

分发器 0x0600f85e（opcode 0xFF 命令体，表 A [0x060a9b78,0x060a9d1c) 15×28B 注册表，
路 R4 已钉）的回执半段，本路逐 PC 复钉：

```
0x0600f932-0x0600f93e  setter(resp=sp+44, 128, data=r6+2, len=b[r6+1]) → r0=n
0x0600f942             ifs (n < 1) → 跳过响应（静默）
0x0600f946-0x0600f954  resp[0]=b[r7+24](cmdid)、resp[1]=n；r0=n+2（总长）
0x0600f960-0x0600f968  call 0x600b66e(r0=0xFF, r1=0(status), r2=r4(SN), r3=resp, [sp]=SN)
```

**0x600b66e = 全部 opcode 恳求回执的公共出口**（本路 call 边枚举 12+ 调用点：
0x600f6cc/0x600f968/0x600fbc4/0x600fd00/0x600fd22/0x600fe10/0x6010012/0x601005a/
0x601012c/0x6010148/0x601019c…——RCSP 协议引擎各 opcode 的响应全走这里）。体：

- 门：`[0x1265C0+1004]`（BT 缓冲池 ctx 指针）非零且 `b[pool+24]` 非零（链路在位门，
  0x600b678-0x600b690），否则返回 4（rcsp 未起/无连接→回执丢弃）。
- 组 2 字节头 `{status=r1, SN=r2}` 于栈 sp+22（0x600b692-0x600b696），调
  **0x6009db0(pool+12, hdr, 2, resp,…)**（0x600b6ac）。响应 body 因此以
  `status, SN, cmdid, n, data…` 开始——与 protocol.md §2.1 实测格式互验一致。

**0x6009f6a = 无恳求通知出口**（固件主动推送，无 SN 回显）：ABI
`(opcode, payload 指针, len, r3 旗标, [sp] 附加字)`（0x600f79e/0x601a84a/0x6025696 三
调用点形状互证）；SN 取自 `b[pool+28]` 自增计数器（0x6009f94-0x6009f9e），同样汇入
0x6009db0（0x6009fc4）。上层包装 **0x6025652(cmdid, payload, len) →
0x6009f6a(0xFF, payload, len+2, 0, …)**（0x6025680-0x6025696）；AO 路钉过的两个用例
本路复核：模式失配回执
0x06025652(0x2E,字节,1)、ANC 尾部 **0x06012bfe → 0x6025652(0x17, &b[0x12666B], 3)**
（0x6012c14，载荷=RAM 0x12666B..0x12666D 三字节）。

### 1.2 帧构造与入队：0x6009db0 [静态·本路]

池分配（自由链按块规格对齐切分）后在块内拼 wire 帧（r4=块基）：

- 帧区起于**块基+40**（r0=r4+36，`b[r0+4..6]=FE DC BA`，0x6009ed8-0x6009eea；+36 处另有
  1 字节 0 类型/保留位）；
- flags 字节在帧+3=块+43（0x6009f04）：无头纯通知分支 `flags |= 0x4000`
  （0x6009eec-0x6009efc）；
- 帧+4=opcode、帧+5..6=len_BE16（0x6009f06-0x6009f0e），hdr{status,SN} 与 resp 载荷两段
  memcpy 到**帧+7=块+47** 起（0x6009f12 / 0x6009f28，ROM 0x1fd74），尾字节 **EF**
  （0x6009f32-0x6009f38）——**头 7B+尾 1B=固定开销 8B，与 protocol.md §2.1 实测帧格式
  逐字段一致 [静态+文档互验]**；
- 块挂 TX 双链队列：`[r8+8]=块+20`（r8=pool+12 → 队头 [pool+16]、队尾 [pool+20]，
  0x6009f44-0x6009f58）；
- **0x606474a(pool+56) 信号量投递**（0x6009f3c-0x6009f5a 前后夹 0x6064538/0x606474a）。

池 ctx 几何（本路钉）：`[0x1265C0+1004]`=ctx 指针；**+12 队列对象、+16/+20 队头/队尾、
+24 链路在位门、+28 无恳求 SN 计数、+56 信号量、+72 连接句柄(u16)、+74..79 对端 MAC**。

### 1.3 rcsp 任务 0x60097FE：TX 排空半环 [静态·本路]

任务体两半环（btmap §1.1 的消费侧细化）：

- **排空半环**（0x6009900-0x600995e）：`0x6064538(pool+56)` 信号量 pend
  （0x6009908-0x600991a）→ 遍历 `[pool+16]` 队列（r6=[r12+16]，r12=pool ctx）→
  每节点 `0x6009712(r0=h[pool+72] 连接句柄, r1=pool+74 对端 MAC, r2=[节点+8] 数据块
  指针, r3=块内长度域+8)`（0x600992e-0x600994a）→ 摘链 0x600922e、归还池 0x600924e。
- 槽回调半环（0x60097fe-0x60098d4）：[0x1265C0+268] 槽环遍历（命令桥 0x6000cba 的
  注册面，btmap 已钉）；尾部 0x60095f8 为长度核对/锁清理，非发送口（本路辨析）。

### 1.4 双传输面 [静态·本路]

0x6009712 按连接（句柄 h[pool+72] / MAC b[pool+74..79]）匹配两张回调表：

- **slot256 面**：`0x6007f5c([0x1265C0+1024], 句柄)` 匹配 → **0x6009692**：调
  0x6007f54 后经 **0x6008a76(opcode, sub, ptr, params)** 写事件环
  （环存储 [0x1265C0+1587×4]/[+1588×4] 头尾，事件字 `{sub<<16|opcode}`），调用形状
  (28,2)/(26,5)/(10,4)（0x60096c8/0x6009702/0x6009702 前后）。
- **slot257 面**：`0x60080ea([0x1265C0+1028], MAC)` 匹配 → **0x60075ce(ctx, 帧, len)**：
  门 `b[0x1265C0+2140]`、pend [0x1265C0+2144]，thunk 0x60075c6 →
  **0x6003b02(MAC@ctx+20, 通道=129(0x81), len, 帧)**（0x6007600-0x6007616；通道号
  由调用者直传，本路在 0x6017af8/0x6023272/0x6013fee 抽样复核 r1=106/39/57 等）。

0x6003b02 是通用「按链路+通道发数据」复用器（switch r1∈{1..7,47,124,256,266,267,270,
默认}）。通道 129 走默认分支（0x6003c50 起）：重试等待（≤100 次×0x6064efc 睡眠）→
门 `b[0x1265C0+7204] != 12` → 分配 len+20 块（0x12e160/0x1fd80）→ 块布局
`{+4..9 MAC、+10 类型、+12 通道(129)、+14 len(u16)、+16 起=帧字节}` →
**0x6003aee 挂 [0x1265C0+7300] TX 块链尾**（0x6003cd2-0x6003cdc）→
**0x6003a34 post('btstack', 255)**（0x6003a36 名串 0x060A1BC8='btstack' 脚本复核）。

### 1.5 btstack 消费与控制器交接 [静态·本路]

- btstack 任务 0x605934E 的 get_event 分派对非 0x4000001..E 事件（含 255）走
  **0x6059304 轮询器 walker**（0x6059eb2-0x6059eba，轮询器链表 @0x124DE0，节点
  {+16 回调,+21 使能,+22 优先级}）。
- 控制器库域泵（含 0x6041612 的函数）：`r10=[0x1265C0+7300]` 头块（0x6041612-0x6041616）
  → 临界区摘链 0x6008a1c（0x6041620-0x604162e）→ 块 MAC 与 0x060A1F28 处
  {全零/全 FF} 掩码比对后查连接句柄（0x6003540/0x6003578）→ 按通道分发：非 261 →
  **0x6036e96**（0x60416a6）→ 0x6003606 取连接结构 → **0x6003704(0, 5, 2051/2052, 块)**
  = post 事件 **0x400003**（0x6003714，2051/2052=0x803/0x804——btmap 钉的 btstack
  案内二级分派码族）→ 控制器引擎/btctrler 域内消费（0x6036d82 同族 [文档 BTMAP]）。
- 空口/控制器内部（modem 窗 0xF08000 FIFO、IRQ78/79）不在本路范围——M1 不需要
  （读出点在 §2 上游）。[未钉：控制器引擎对 0x803/0x804 的逐案处理]

### 1.6 RX 对称面（补 btmap 未钉项）[静态·本路]

正向 glue 本路顺带钉死（btmap §6.3-4 的「LE→rcsp 精确 glue 未钉」补案）：

```
LE ATT 写入 → 0x6060ef8（ATT 句柄匹配 @表 0x060A9344 族）→ 0x601045a(句柄,…)
→ 0x6010534（0x6060f16 第二入口，len/handle 域）→ RCSP 协议引擎 0x600fd0a
（含 0x600ffd0：call 0x600f85e(SN=body 前序号, body, …, len)）
→ 表 A 分发 → setter（EQ 0x22=0x0602583c、ANC 0x17=0x06025ca4、0x1d=0x06025e82…）
```

0x600f85e 入口 ABI：`r0=SN、r1=body 指针（body[0]=cmdid 或 0xFE 读查询）、r3=len`；
body[0]==0xFE 且 body[1]==1 走 getter（`FE 01 cmdid` 只读查询）。

### 1.7 双命令面澄清（对任务书锚点的修正）[静态·本路]

表 2（0x60a8c68，6×12B）有**两个** 0x10000C handler：[0]={0xff,0x10000c,**0x600434a**}
（消费 param 字==22 的事件：`b[param+4]==1 → 0x6001b9a`）、[5]={0xff,0x10000c,
0x60252c6}（AO 全图的按键/action 域，0x10a00 族载荷门）。**EQ 0x22/ANC 0x17 等 RCSP
自定义命令不经 0x60252c6**——它们在 BT 任务上下文经 §1.6 引擎直调 0x600f85e（表 A）。
0x6000cba 桥（post('app_core',0x10000C,{r0,r1})，0x6000cc2 名串 0x060A1D11='app_core'
脚本复核）服务于把 rcsp 侧事件转成 app_core action/命令事件的那族槽回调
[推断：哪类 RCSP 帧走桥未逐帧钉，不影响回执路径结论]。

## 2. 问二：仿真侧最小注入点与最小读出点

### 2.1 正向注入（app 帧→仿真固件）

| 方案 | 入口 | 口径 | 适用 |
|---|---|---|---|
| **I1 直调 0x600f85e**（推荐） | `0x600f85e(SN, body, 0, len)`；body[0]=cmdid、body[1..]=data（写）或 body=`FE 01 cmdid`（读） | 纯 RAM 直调（任意已运行任务上下文；异步 setter 经 0x60256aa trampoline 投递命名任务，与真机同路径） | **RCSP 自定义命令全家族：EQ 0x22/ANC 0x17/提示音 0x1d/keystore 0x30…** |
| I2 直调 0x600fd0a | 协议引擎上游（opcode 级，非 0xFF 标准_opcode_ 也能喂） | 同上，多覆盖标准 opcode | 需要非 0xFF 命令时 |
| I3 事件注入（BW 先例） | post('app_core', 0x10000C, {载荷字, x})；0x10a00 族→表2[5] 0x60252c6，param==22→表2[0] 0x600434a | 既有 D2-a/BW 注入机制直接复用 | 按键/action 域（music_pp/音量/模式切换） |

I1 与 AO/BW 注入先例同口径：零硬件模型、纯 RAM 调用；比「伪造整个 BLE 栈收到 ATT 写」
少两个环节（跳过 0x6060ef8 句柄匹配与帧重组），而 setter/回执链 100% 真跑。

### 2.2 反向读出（回执/通知→bridge）

| 方案 | 拦截/读取点 | 拿到什么 | 评价 |
|---|---|---|---|
| **R1 拦 0x600b66e 入口**（推荐·恳求回执） | `(r0=0xFF, r1=status, r2=SN, r3=resp载荷指针)`，resp=`{cmdid,n,data…}` | app 可直接消费的响应 body（同 protocol.md 解析前形态） | 免 wire 解析；SN 在手可直配 app 等待者 |
| **R2 拦 0x6009f6a 入口**（推荐·通知） | `(r0=opcode, r1=payload 指针, r2=len, r3 旗标)` 或其包装 0x6025652`(cmdid,payload,len)` | 无恳求通知载荷（ANC 0x17/模式 0x2E…） | 与 R1 合计覆盖全部反向帧 [静态：两出口是仅有的 0x6009db0 消费上游——call 边枚举 0x6009fc4/0x600b6ac 两处] |
| R3 RAM 轮询 TX 队列 | `[0x1265C0+1004]`→pool；队头 `[pool+16]` 沿节点 +0 走；帧 wire 字节=**块基+40**（FE DC BA…EF） | wire 级字节流 | 零 hook 纯读；但队列瞬态（排空即还池），轮询漏帧风险需停 rcsp 任务或快频轮询 [推断·风险] |
| R4 拦 0x6003b02 入口 | `(MAC, 通道, len, 帧)` | 通道级 wire 帧 | 与 R3 同信息、更早一站；双传输面合并点 |

**建议**：M1 用 R1+R2（函数入口拦截，载荷级），R3 作为「不打断执行的旁听」备选。

## 4. 未钉清单（诚实边界）

1. 0x6009db0 帧 flags 位的完整拼式（0x80/0xC0/0x4000 族在 16 位临时里的组合顺序）——
   落到 wire 的单字节与 protocol.md 实测一致 [互验]，但 16 位中间值未逐位展开。
2. 控制器引擎对 0x803/0x804 事件的逐案处理、modem FIFO 写入形状（D3/专项域）。
3. slot256/slot257 两传输面与 BLE/SPP 的对应关系（哪张表对应 LE GATT 通知）——按
   通道 129 走 btstack TX 链的形状 [推断] 为 LE 面；双设备/经典 BT 场景未钉。
4. 0x6000cba 桥消费的 RCSP 帧类别（哪类帧转成 0x10000C 事件）。
5. 0x6003b02 内 0x609f3b8 索引表载入后被 `r1=129` 覆盖的死代码（0x600760c-0x6007610）
   ——解码经 codec+模拟器语义（ld.w.idxs=dest=mem[base+idx<<2]，tools/probe_boot.py
   同款）双重确认，仍标注为未解释的编译器残留 [静态·本路]。
6. 全部为静态推导：队列瞬态时序、信号量唤醒延迟等动态行为无实测。
