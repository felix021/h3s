## 0. 一句话结论

`0x060252c6` 收 **OS 事件 id 0x10000c** 的载荷字（`0x10000|(key<<8)|gesture子类型`，即 AJ 实测的
0x10a00 族），拆出物理键 10..13 与手势子类型，经掩码 `0x09050307` 映射逻辑键 {7,3,5,9}、经 tbb
表把手势子类型折成**手势类别 1..6**，再查 **QCY+3404 的 15×3B 映射表**（config key 48 持久化，
默认表=flash 常量 0x0609e250），命中后由 `0x06025382` tbb 跳表按动作号分发——cmd 1..6 是
「发布动作名+提示音/音量」、7 是**音频模式**（key 22 状态机，不经 ANC dispatch）、11 是 **ANC 模式**
（anc_next→0x060189aa→0x0600dcee/0x0600db3c，R2 辅听接驳窗口正在这条链上）；9 返回已处理无动作、
8/10/0 返回未处理、127 返回已处理无动作。动作分支内**未发现对耳转发调用**；App 侧动作同步走 BLE 自定义命令回执
（cmd 0x17/0x2E），不走 WL/AIRO。

## 1. 0x060252c6 全图（入口→查表→分发）

### 1.1 注册与入口 [静态+文档]

- handler 注册：S19 第二张分发表（0x60a8c68，6×12B 记录）**记录[5] = {filter 0xff, event_id
  0x10000c, handler 0x060252c6}**（0x60a8cac 处 LE32 指针唯一引用；表结构见 d1-acceptance §2.2，
  路 eq-payload-semantics BT 修正「0x60252c6=表2记录[5]」在此逐字节核实）。全 app 无直接 call 调用点
  （19,111 条线性 call 边扫描零命中；0x060252c6 的 LE32 引用仅 0x60a8cac 一处）。
- 入口参数：`r0` = 事件载荷指针，`r6 = [r0]` = 载荷字 `0x10000|(键id<<8)|手势子类型`。
  路仿真证据 [仿真：BW]：从 handler 入口注入 `0x10000|(10<<8)|4`（=0x10a04 双击）即完整走通；
  生产者侧 [文档：AJ] 手势 post 序列实测（0x10a00/0x10a01/0x10a02/0x10a03/0x10a0a/…）。

### 1.2 入口门与手势类别折叠 [静态]

```
0x060252cc  if ((r6 & 0x10000) == 0) → 直接返回      ; bit16 = 键事件族门
0x060252d0  r0 = r6.b0                               ; 手势子类型 0..6（>6 走默认）
0x060252d4  if (r0 > 6) → 0x060252f4（默认路径）
0x060252d8  tbb [r0]，表 @0x060252da = {04 06 0d 0d 08 0a 0c 00}
            目标 = 0x060252da + 2*表字节
0x060252f4  r7 = 0x1265c0（QCY 全局结构基址）；r5 预置 6（默认类别）
```

子类型→手势类别（tbb 目标处给 r5 赋值）：

| 手势子类型（post 低字节） | tbb 目标 | 手势类别 r5 | 语义 |
|---|---|---|---|
| 0 | 0x060252e2 | **1** | 单击（AJ 实测：单击只 post 0） |
| 1 | 0x060252e6 | **5** | **长按确认**（AJ 实测 75 拍阈值 post 0x10a01，见 §3.3） |
| 2 | 0x060252f4 | 6（默认） | 长按持续（每 15 拍重复）——无动作 |
| 3 | 0x060252f4 | 6（默认） | 释放确认——无动作 |
| 4 | 0x060252ea | **2** | 双击（AJ/BW 互证） |
| 5 | 0x060252ee | **3** | 三击（n+2 规律） |
| 6 | 0x060252f2 | **4** | 四击 |
| >6（10..14 长按档） | 0x060252f4 | 6（默认） | 长按档 post 不触发按键动作 |

即**手势类别 1..5 = 映射表的手势槽位**（单击/长按/双击/三击/四击），**类别 6 = 无动作类**
（持续/释放/档位 post 一律吞掉返回已处理——AJ 的「长按释放无多发单击」负例在此得到静态解释：
释放确认 3 与档位 10..14 都折进类别 6）。

### 1.3 模式门 0x80 位与按键映射 [静态]

```
0x06025314  r4 = r5 | 0x80
0x0602531c  call 0x06008170（工作模式查询，见 §4.3）
0x06025320  if (r0 != 5) r5 = r4        ; 非 5 → 手势类别 |= 0x80
0x06025326  r0 = (r6>>8) + (-10)        ; 键 id 字段 -10
0x0602532c  r2 = 255
0x0602532e  if (r0 <= 3) { r2 = 0x09050307 >> (r0<<3) }   ; key10..13 → {7,3,5,9}
```

- 键掩码 `0x09050307`：key10→逻辑键 7（多功能）、key11→3（音量-）、key12→5（音量+）、key13→9；
  键 id 超出 10..13 → r2=255，表永不命中 → 返回未处理 [静态；BW 同形]。
- **0x80 位语义 [静态+推断]**：模式查询返回非 5 时手势类别附加 0x80，附加后与映射表的
  gesture 字节（1..5）不再相等 → 查表必落空 → 返回。即**非基线模式下整个按键映射动作被抑制**
  （面板文案有「音频模式/通话模式」两组绑定，通话侧不经这张表——其处理路径本轮未追，
  [未定位]）；「5=普通/非通话基线」是 [推断]（若 5 为罕见态则常态按键全失效，与实测按键可用
  矛盾；BW 注入场景以 5 为基线通过）。

### 1.4 映射表与查表 [静态]

```
0x0602533e  r0 = r7 + 3406        ; 指向表项+2（action 字节），表基址 = QCY+3404 = 0x12730c
0x06025344  r2 = r2.b0（逻辑键）, r3 = r5.b0（手势类别）
0x0602534a  循环 15 项：b[r0-2]==r2（键）且 b[r0-1]==r3（手势）→ 命中，r5 = b[r0]（动作号）
0x0602535e  未命中 → call 0x06017958 → 返回 r4=0（未处理）
0x06025364  命中 → r5=动作号；call 0x06017958 → r9；call 0x060140fc → r6
0x06025370  r1 = r5-1；r1>10（无符号）→ 0x060253a4（动作 0/越界检查）
0x06025380  r4 = 1（返回值预置「已处理」）
0x06025382  tbb [r1]，表 @0x06025384 = {09 14 1c 24 32 39 40 07 06 07 65}
```

表结构：**15 项 × 3B {key, gesture, action} @ QCY+3404（0x12730c..0x127338，45B）**，首匹配语义。
两个按键上下文 API：

- `0x06017958`：查活动音频链路对象（内部走 0x060178e4 链表查找），返回对象指针或 0 → r9。
  r9==0 时动作 5/6 直接返回已处理（不执行）。
- `0x060140fc(r9)`：把该链路与全局活动链路（[0x1266a0]，ROM 6 字节比较 0x1fd7c）比对，一致返回
  1 → r6。r6==0 时动作 2/3/5/6 返回已处理（无提示音不执行）。
  （两者在 BW 注入场景均为合成桩 [仿真：BW]。）

## 2. 每个动作的执行链锚点 [静态]

### cmd 1/2/3/4：媒体/助手动作 =「动作名发布 + 提示音」

共同形状：`0x06018bf4(名字串, 0)` →（门）→ `0x060075c6(r9=链路对象, 提示音号, 0, 0)`。

- **0x06018bf4（动作名发布器）**：读 `[QCY+416]`（0x126760，31B 环形缓冲对象；b[0]=写游标，
  +1..+31=名字区）。流程：strlen(0x1fd8c) → 取锁 0x06064538 → 溢出则清 31B → ROM memcpy
  (0x1fd74) 把名字追加进环 → 更新游标 → 放锁 0x0606474a。**环的读取者/「music_pp→AVRCP」的
  直接执行点本轮 [未定位]**——按键分支内没有对 0x06019140 族（BT 媒体命令 tbb 分发器，cmd 0..4）
  的直接 call；同名包装器族 0x06019284/0x060192b0…（对象+8/+12 形，发布同名后**直接**调
  0x06019140(128/1,…) / 0x06019272→0x06009c0e）属于另一输入源（App 远程动作命令同词汇复用
  [推断]），不是按键路径的执行者。D2-a 的「动作执行」观察点建议直接用**环写入（[QCY+416] 对象
  游标+名字字节）**——它在分支内、可观察、与动作一一对应。
- **0x060075c6 → 0x06003b02（提示音）**：tone 播放入口（[QCY+924] tone 播放器句柄；r0!=0 时取
  链路对象 +4/+5 两字节做场景名）；提示音号 45/66/69/70=助手/播放暂停/下一曲/上一曲反馈，
  2/3 的提示音被 r6 门（链路一致才响）。
- cmd 4 的 0x06008298：走 0x1281fa 起 2×40B 记录表，数 `b[rec+15]&4`（语音助手能力位）的链路数，
  0 → 不响提示音直接返回已处理。
- **对耳转发**：动作分支内未发现任何对耳转发调用（WL/AIRO 词汇不出现在 0x060252c6→动作链首层）；
  [未定位] 更深层（btstack/rcsp 内部）是否有，本轮不臆测。

### cmd 5/6：音量±（带辅听活动门——R2 交汇点之一）

`0x06017a58`（音量+）/`0x06017b22`（音量-）首层同形：模式查询 0x06008170 → 0x0601252c（活动设备名
取 4B）→ 0x060124d8（名字表校验，0 → 返回）→ **0x0603370c = `[QCY+592]（0x126810）!= 0` 门**
——该槽由 0x06016cc8/0x06016ce4 与 0x060336e6 写放（**pc_mic/mic_effect 播放器对象簇**，
路 L 激活序列锚 0x06016e84/0x06017078/0x06033504/0x060339a4 所在族）：辅听链活动时音量键在本路径
**直接返回（不调媒体音量）**[静态；辅听自身的音量接管路径未追，标未定位]。门后：音量级别取
0x06013b10(1/2) → 上限读 **QCY+4434 u16（config key 86 的 2B 槽）**（0x06012770 取）→
0x0601267a(类型, 级别) 写回 QCY+4434 并 post **0x10000/0x20000 位标志事件族**（0x06012572/
0x060125bc；音量应用消费者本轮未追）→ 提示音 0x060075c6(…,106) / 0x06003d46(261,1,'A') /

### cmd 7：模式切换（音频模式状态机，与 ANC 无关）

见 §4.1。首层：`0x06018bf4('InLowLatency')`（发布名）→ `get_config(22, 0x124a04, 1)`（当前音频

见 §4.2。首层：`b[QCY+444]`（0x12677c）挂起标志门 → 0x0600bbd8（当前 ANC 模式）→ 0x06018b60

### 3.3 手势类别 5=长按槽的触发时机 [静态+文档：AJ]

类别 5 的唯一来源是**子类型 1（按下确认 0x10a01）**；AJ 实测单击序列只 post 0x10a00（无 0x10a01）、
长按序列在 75 拍阈值 post 0x10a01——即**长按动作在「按住超窗确认」时刻触发一次**，其后的持续
（2）/档位（10..14）/释放确认（3）post 全部折入类别 6 不再触发。app-protocol §2.5 的
「5=长按 [假设]」就此升级为 [静态+实测] 互证。

## 4. 模式切换状态机（cmd 7 与 cmd 11 是两台互不相干的状态机）

### 4.1 cmd 7：音频模式（key 22）[静态]

- 当前模式字节：**0x124a04**（get/set_config(22) 的 1B 缓冲；config-key-map「key 22=音频模式
  1B」的 RAM 落点在此钉死）。取值族 {1,3,4}（+失配默认 0x4f 读数）。
- 切换逻辑（0x06025404 分支）：查当前值 → 当前=1 或 4 → `0x060251fc(3, 1)`；当前=3 →
  `0x060251fc(1, 1)`（1↔3 往复，4 也进 3）；失配（读数不属 {1,3,4}）→ 只发 BLE 回执
  `0x06025652(46, 0x124a04, 1)`（cmd **0x2E(46)** = 面板「模式切换」cmdid，自定义命令帧构造器：
  {cmd,len,data} → 0x06009f6a(0xFF, 帧, len+2, 0, 帧) 经 [QCY+1004] RCSP 对象发送）。
- **0x060251fc(模式, flag)**（模式应用器，eq-toggle「调用 0x060251fc」展开）：
  - 前置门：0x0601662a 返回 &4 且 b[0x125f7e]==0 → 直接返回；模式>4 返回。
  - 写 0x124a04 = 模式；按模式分派：
    - 1：0x0601a81c（b[QCY+27]）活动查询 → 需要时 0x0600efd0(0,0) 关 → 0x06024f02(1)
      （scene 切换：0x060225da 活动检查 + 0x06005700 + 0x06024e6a）；flag==0 时走
      `0x06024fe6("MusicEqBt", 1)`（装载预设）+ `0x06025118`（应用 EQ 参数——eq-toggle 已钉的
      链）；flag!=0 时走 ctx 路径 `0x0600c2aa` → `[ctx+104]`。
    - 4：同形（0x06024f02(0)；flag==0 → 0x06024fe6("MusicEqBt",3)；flag!=0 → [ctx+220]）。
    - 3：0x0601a81c!=1 时强停（0x0600efd0(1,0)+0x06024f02(0)）；flag==0 →
      0x06024fe6("MusicEqBt",2)；flag!=0 → [ctx+100]。
    - 2 或其他：直落 set_config(22)。
  - flag!=0 的统一出口：`0x0600dab6([ctx槽值], 0x602619a)`——把**音乐模式恢复回调 0x602619a**
    （eq-toggle 的 0x0602619a(0,10)）挂进 0x0600d95e 返回的 ctx 的 **[ctx+120]/[ctx+124] 槽**
    （b[ctx+13]=1 挂起标志）或无 ctx 时直接 `call 0x602619a(0,10)`。
  - 尾部：`set_config(22, 0x124a04, 1)` 持久化。
- **cmd 7 不触 ANC/mic_effect dispatch**：它的「模式应用」走 0x0600dab6（音频效果 ctx 槽族），
  与 0x0600db3c（ANC dispatch，§4.2）无调用边。

### 4.2 cmd 11：ANC 模式（key 16 + ANC ctx）[静态；链与 anc-cycle.md/路 AL 一致]

- 当前模式存储：**[QCY+500]（0x1267b4）→ ANC ctx（0x0602eeb2 zalloc 572B）；当前内部模式字节
  = b[ctx+33]**（权威读点 0x0600bbd8：`[QCY+500]+33`，返回 1/2/3=OFF/ON/TRANS 内部编号）。
  0x0600db3c 切换时先写目标缓存 b[ctx+5] 与 b[ctx+28+5]、置 b[ctx+28+1]=1 过渡标志；
  最终提交（b[ctx+33] 更新点）在 anc_task（0x602d3a0 族 0x0602d5xx 有 +33 写，但该处 r14 基址
  与 161 立即数语义需运行时确认——**提交点本轮 [未定位]**，诚实标注）。
- 直切路：`0x06018b60`（anc_next：循环表 0x609e510 三字节、first-match、mode_enable 位掩码
  b[ctx+1]，伪代码=anc-cycle.md）→ `0x060189aa(下一模式, flag=(key15值或1)<<1)`：
  - 特例 目标==2 且 flag==2：写 QCY+168..173（wire mode/scene/strength 镜像=1/5/0）→
    `0x0600db3c(2, 1)` **直接进 ANC dispatch**（0x06018a7e 调用点）。
  - 一般：0x0609e27d 的 {wire,internal} 对表（01 02/02 01/03 03，anc-cycle「三对映射字节」）把
    内部模式折 wire 值写 b[QCY+171] → 按目标模式调 **0x0600dcee(wire, scene, strength, 1)**
    （0x06018ac0/ad8/aec 三点；0x0600dcee=App 0x17 同一 direct-set 入口——路 AC「键循环同一
    dispatch 以 flag=1 汇入」在此展开到调用点）→ 尾部 `0x06012bfe`：镜像写回 QCY+171..173 +
    `set_config(16, QCY+171, 3)`（key 16 持久化）+ **BLE 回执 0x06025652(23=0x17, QCY+171, 3)**
    （App 侧「设备已切换」通知）。
- 挂起路（0x0602544e 分支首段）：b[QCY+444]!=0 → 跳过查询直接直切（清 QCY+444）；否则
  0x0600bbd8 查当前模式，**当前==2（ANC ON）** 时不立即切：置 b[QCY+444]=1 → ctx 取
  `[ctx+140]` → 0x06016f34 → **0x6066a8a(0, 0x6023a70, 2000)** 延迟投递（工作项分配入队族；
  延迟单位未钉）→ 返回已处理。0x6023a70=小函数（`r0=0; call 0x6018ec8`），0x6018ec8=ANC
  切换**状态机续行 helper**（b[[QCY+480]+0]=参数、连锁检查后走完成支：0x060260e6、0x060118ea(50)、
  0x060753e8/0x06018e82）——两段式「先挂起、延迟后续行」[静态；精确续行目标模式依运行时状态
  而定，未钉]。
- 事后联动：切换完成读新模式（0x0600bbd8）——**1（OFF）→ `0x060251fc(1, 'anc_off')`**
  （借非零 flag 走 ctx 路径恢复音频模式 1=音乐 EQ 场景；'anc_off' 串只当真值用）；2/3 → 仅
  `0x06018bf4('anc_on'/'anc_trans')` 发布动作名（r8+556/+1174）。
- 0x0600db3c 内部（R2 接驳窗口宿主）：ctx=[QCY+500] 空→出；模式限 1..4；同模式幂等出；
  置过渡/目标缓存；flag!=0 时经 0x0600c2a0 再分 ON/OFF/TRANS 两侧——**路 Y 的 6 窗口
  ON-1 0x0600db9a / OFF-1 0x0600dc74 / ON-2 0x0600dbc4 / OFF-2 0x0600dc9a / TRANS-A 0x0600dc7e /
  TRANS-B 0x0600dca4 全部落在本函数内**（本轮逐窗口复核地址一致）。

### 4.3 模式查询 0x06008170（两台状态机共用的「工作模式」门）[静态+推断]

`0x06008170`：0x6003578 查活动对象 → 有则取 `b[对象+13] & 0x0F` ==5 判定；无对象走 0x1281fa 起
40B 记录表（b[rec+15]&4 活动位）兜底；命中返回 5，否则尾部读 ICFG 低字节返回（该 SFR 读在模式
查询里的语义 [未定位]）。返回 5=基线（§1.3）；音量函数也查它分档。**它不是 ANC/音频模式状态机
本身，而是通话/场景占用指示**[推断]。

### 4.4 与 R2（mic_effect 辅听链）的交汇点结论

- **ANC/通透切换窗口（路 Y 的 L1 close 接驳 6 窗口，宿主 0x0600db3c）的可达动作分支=cmd 11**：
  0x0602544e →（直切或挂起后）0x06018b60 → 0x060189aa → 0x0600dcee（0x06018ac0/ad8/aec）→
  0x0600dd62/0x0600ddac → 0x0600db3c，及特例 0x06018a7e → 0x0600db3c(2,1)。**cmd 7 不可达**
  （其 0x060251fc→0x0600dab6 是另一台 dispatch，调用边分开）。App 0x17 直设同汇入（路 AC）。
- **音量动作（cmd 5/6）与辅听链的交汇**：0x06017a58/0x06017b22 的 0x0603370c 门读
  **[QCY+592]（pc_mic/mic_effect 播放器对象槽）**——辅听活动时音量键在本路径被吞（返回不执行
  媒体音量）。即 R2 载荷激活后，D2-a 的音量动作用例会观察到「动作已处理但媒体音量链不走」，
  这是动作覆盖×辅听接驳的**第二个可测交汇点**（第一个=cmd 11 窗口本身）。
- R2 记忆中的 mic_effect 场景槽 0x125574（路 R2 选址）与本页两个状态（音频模式 0x124a04、
  ANC ctx [QCY+500]+33）互不相干——三者分属三个域，不要混用。
