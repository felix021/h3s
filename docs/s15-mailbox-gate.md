## 0. 一句话结论

b[0x1299f8] 的**唯一写者** = `power_init`（入口 **0x6067876**）内的
**0x60679f8 `st.b.l b[r6+40]=r0`**，值=1，r6=0x1299d0（该函数 0x606787a 单点
`li.u32 r6=1219024`，callee-saved 跨 call 存活），有效地址=0x1299d0+40=0x1299f8。
触发条件=**boot 期冷启动一次性写**：仅当「非 wake（0x60674aa()=[0x12521C] bit1
==0）且 b[0x1299f0]==0（首 init 守卫，同函数 0x6067914 刚置 1）」时走到该行；
wake 或重入两条旁路都跳到 0x60679fc 绕过。写后无任何清 0 者 → 冷启动后恒 1。
这解释了「全 app 无 0x1299f0/0x1299f8 字面量」——地址=结构基址字面量
**0x1299d0** + 立即数偏移 **+40**（以及邻字节 b[0x1299f0]=基址+32），不直接
装载字节地址。

## 1. 写者定位（四问：PC/函数/触发条件/写后持久性）

### 1.1 PC 与指令 [静态·本路，脚本 ~/tmp/s15w/anchors.py]

```
0x6067876  push.rets_rl [--sp]={rets,r12-r4}      ← power_init 入口（app_core 0x60120dc call 0x6067876）
0x606787a  li.u32  r6 = 1219024                    ← 0x1299d0（结构基址，唯一一次给 r6 赋值）
0x60678f8  call.l  -1106 → 0x60674aa               ← 读 [0x12521C] bit1（wake 标志）
0x6067900  beqz    if (r0==0) goto 10              ← 非 wake 才继续（wake 走 0x6067902→0x606790a goto 240→0x60679fc 旁路）
0x606790c  ld.bu.l r0 = b[r6+32]                   ← 读 b[0x1299f0] 首 init 守卫
0x6067910  bnez    if (r0!=0) goto 234             ← 已 init 则旁路到 0x60679fc
0x6067912  li.u8   r0 = 1
0x6067914  st.b.l  b[r6+32] = r0                    ← b[0x1299f0]=1（守卫置位）
   …（P11 堆拷贝 / PWR_CON bit5 请求-响应 / 堆信息读，同一冷启动直线段，无条件）…
0x60679f6  li.u8   r0 = 1
0x60679f8  st.b.l  b[r6+40] = r0                    ← ★b[0x1299f8]=1（本路钉的写者）
0x60679fc  li.u32  r0 = …                           ← 两条旁路与直线段的合流点
```

### 1.2 函数归属 [静态·本路]

函数入口 **0x6067876**=power_init（HANDOFF 前沿行互证：app_core 0x60120dc 调用
power_init；本路脚本复算 call 目标 0x6067876 命中）。全 app 对 0x6067876 的 call
点恰 1 个（0x60120dc）。

### 1.3 触发条件（boot 期一次性 / 条件分支）

写 b[0x1299f8]=1 在 **power_init 的冷启动首 init 路径**上，两个条件都满足才到：

1. **非 wake**：0x60674aa()（`ld.w [0x12521C]; uextra bit1`）返回 0。
   0x6067900 `beqz` 放行。wake 侧（bit1==1）在 0x606790a `goto 240` 直接跳到
   0x60679fc，跳过该写。
2. **首 init 守卫**：b[0x1299f0]==0（BSS 冷启动清零）。0x6067910 `bnez` 放行。
   已 init 侧跳到 0x60679fc 跳过。

两条件在当前擦除/冷启动世界都成立（HANDOFF 前沿行已钉 [0x12521C] bit1=0、BSS
清零）→ 该写必执行、值=1。**一次性**：b[0x1299f0] 在同函数 0x6067914 先置 1，
此后任何重入（wake/二次调用）都绕过整块，b[0x1299f8] 不会再写。

### 1.4 写后持久性（S15 时刻值=1 的依据）

全 app 对 0x1299f8 无清 0 写者：offset-40 字节写全扫+抽象解释只命中 0x60679f8
一个 st.b.l 目标 0x1299f8（其余 st.b.l [rX+40] 候选的基址都落在各自函数的结构
字面量上，非 0x1299d0）。BSS 清零只发生在冷启动初，之后该字节由 1 保持到 S15。
与 BA §0.1（3.17M 停点实测 1）、B2R 门复测（当前前沿实测 1）互证。

## 2. 读门 + S15 邮箱静态链（读门→邮箱读写→ack 投影）

### 2.1 读门 getter [静态·本路]

```
0x606749e  li.u32  r0 = 1219024        ← 0x1299d0
0x60674a4  ld.bu.l r0 = b[r0+40] (u)   ← b[0x1299d0+40] = b[0x1299f8]
0x60674a8  rts
```

0x606749e 全 app 唯一 call 点=0x600a592（喂狗 0x600a590 内）。喂狗逻辑：

```
0x600a590  push.rets
0x600a592  call 0x606749e             ← 读门
0x600a598  beqz if (r0==0) goto 10    ← 门=0 走普通喂狗（keys+CON），跳过邮箱
0x600a59a  li.u8  r0 = 8              ← 消息字节=8
0x600a59c  call 0x12cc7e              ← 门≠0 走 P11 邮箱
```

### 2.2 邮箱 RAM-code 0x12cc7e（flash 母本 0x060c6456）→ 首停 0x12CC94 [静态·本路复算，与 BM §3.1 逐字一致]

```
0x12cc7e  [--sp]={rets,r4}; r4=r0     ; r0=消息字节(8)
0x12cc82  call 0x12b55c               ; pend（OS 临界区助手）
0x12cc88  r1=0xFF
0x12cc8a  r0=0xF27F43                ; P2M+3 回声槽
0x12cc94  b[0xF27F43]=0xFF           ; ★清回声槽 = S15 首停（P2M 区未映射，字节写最先撞）
0x12cc96  b[0xF27F87]=r4             ; M2P+7 写消息字节（M2P 窗已映射✓）
0x12cc98  r1=0xF2A608
0x12cc9e  [0xF2A618]=0x400           ; M2P_INT_SET bit10 kick P11
0x12cca2  csync
0x12cca4  r2=[0xF2A60C]              ; P2M_INT_PND
0x12cca6  if ((r2&0x1000)==0) goto csync  ; 无界轮询 bit12（ack）
0x12ccaa  r2=b[0xF27F43](u)
0x12ccac  if (r2!=r4) goto csync      ; 回声≠消息→回轮询
0x12ccb0  [0xF2A608]=0x1000          ; P2M_INT_CLR 清 ack
0x12ccb4  call 0x12b5b0              ; post
0x12ccb8  返回
```

首停=**0x12CC94 `b[0xF27F43]=0xFF` 写**（BM §3.1 三勘误后的形态：消息字节地址
0xF27F43/0xF27F87、ack 轮询 0xF2A60C、0xF2A618 真名 M2P_INT_SET）。ack 投影
(p2m_mailbox_ack，已由 B2G 提层到 conditional) 的武装语义：kick 0x400→PND
bit12 读回 1+回声=M2P+7 值；CLR 0x1000 清位。

### 2.3 S15 逐轮喂狗调用点 [静态·本路复算]

S15 环 0x6012330..0x6012356：0x6012334 `call 0x600a5b4`（S15 包装）→ 0x600a5b6
`call 0x600a590`（喂狗）→ 读门 → 门=1 → 0x12cc7e(8) 邮箱事务，共 11 轮
（S17 若达再加 151 轮，BM 事务账本 162 计）。

## 6. 未钉死处（如实标注）

1. **唤醒路径的运行时真值**：[0x12521C] bit1 恒 0 依赖「当前擦除/冷启动世界」；
   warm-boot 世界若 bit1=1，门不重写（保持既有 RAM 值）——门在真机 warm-boot 下
   仍为 1 是推断（写后无清 0 者），非实测。
2. **b[0x1299f8] 的结构语义**（对应哪个 SDK 成员/配置项）未命名；只钉到「QCY
   结构 0x1299d0 基址 +40 字节、被 0x606749e 读、喂狗门」。语义命名不属本路裁决面。
3. 本路抽象解释按 call 杀全部 GPR（保守）；写者经 callee-saved r6 跨 call 存活是
   手工复算确认，非解释器自动结论——同族「跨 call 基址存活」若有其他站点，静态
   全扫的覆盖边界同 ASS（如实标注）。
